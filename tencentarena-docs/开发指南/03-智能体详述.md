## 观测处理
环境返回的`observation`信息包含了针对智能体的局部观测信息，可以在`observation_process`函数中对这些局部观测信息进行处理。

我们推荐用户使用预处理器`preprocessor`对环境返回的`observation`信息进行预处理：


```
def observation_process(self, env_obs):
    feature, legal_action, reward = self.preprocessor.feature_process(env_obs, self.last_action)
    obs_data = ObsData(
        feature=list(feature),
        legal_action=legal_action,
    )
    remain_info = {"reward": reward}
    return obs_data, remain_info
```

### 特征处理
当前基线版本提供了 **69 维**的简化特征向量，布局如下：


| 部分 | 维度 | 含义 |
| --- | --- | --- |
| local_view | 49 | 以小悟为中心的 7×7 局部地图（0=障碍, 1=已清扫, 2=污渍），归一化到[0,1] |
| global_state | 12 | 全局状态（步数归一化, 电量比, 清扫进度, 剩余污渍比, 坐标归一化, 4方向污渍距离, 最近污渍距离, 是否在接近污渍） |
| legal_action | 8 | 移动方向合法掩码（8维，0-7方向） |
| 合计 | 69 | — |

### 奖励处理
当前基线版本提供了**最简单的清扫奖励**设计：


| 奖励项 | 含义 | 数值 |
| --- | --- | --- |
| cleaning_reward | 每步清扫的格子数奖励 | +0.1 × 清扫格数 |
| step_penalty | 每步时间惩罚（鼓励效率） | -0.001 |
最终奖励：`reward = cleaning_reward + step_penalty`

时序处理：使用 GAE（Config.GAMMA, Config.LAMDA）计算 advantage 与 reward_sum，作为 PPO 的训练目标。

代码包仅提供了最基础的智能体实现，用户可以仔细阅读[环境详述](/docs/p-competition-robot_vacuum/13.0.1/guidebook/dev-guide/env/)和[数据协议](/docs/p-competition-robot_vacuum/13.0.1/guidebook/dev-guide/protocol/)，根据自己对环境的理解，进行特征工程、奖励开发等工作，不断提升智能体的能力。

## 算法介绍
我们在代码包中提供了**基础 PPO 算法**实现，同时还提供了一个**diy**模板算法文件夹，用户可在该文件夹中自定义算法实现。


| 算法 | 说明 |
| --- | --- |
| PPO | Proximal Policy Optimization，近端策略优化算法，训练稳定性高，收敛速度快 |
| DIY | 用户自定义算法实现模板 |

### 算法详细说明
**模型设计（Actor-Critic）**：

当前基线版本使用**单 MLP 骨干 + 双头**结构：


```
输入 (69D)
  → MLP骨干 (69→128→64)
    → Actor头 (64→8)  → 动作logits
    → Critic头 (64→1) → 状态价值
```
选手可以自行设计更复杂的网络结构

**动作输出**：

- 当前基线版本的动作空间为 **8 维离散动作**（仅移动方向 0-7）。
- 合法动作掩码（legal_action）：使用 mask 把非法选项从概率分布中排除（实现上为对 logits 做大负数惩罚再 softmax）。
- 采样策略：训练时随机采样（multinomial），评估时选最大概率（argmax）。
**训练流程**：

- 交互采样：Agent 与环境交互生成采样（SampleData），包含 obs, action, prob, value, reward 等。
- 后处理：填充 next_value 并用 GAE 计算 advantage 与 reward_sum。
- 更新：在采样数据上执行 PPO 更新（策略损失、价值损失、熵正则）。
- 保存/评估：定期保存模型并在验证地图上评估性能。
**损失函数**：


```
total_loss = vf_coef × value_loss + policy_loss - beta × entropy_loss
```- `value_loss`：Clipped 价值函数损失
- `policy_loss`：PPO Clipped surrogate 目标
- `entropy_loss`：动作熵正则化（鼓励探索）

## 模型评估
用户可以在腾讯开悟平台上创建模型评估任务。


### 地图配置
为考察模型的**泛化能力**，本赛题共提供 15 张地图：


| 地图类型 | 数量 | 说明 |
| --- | --- | --- |
| 开放地图 | 10 张（编号 1～10） | 开放给选手进行训练和评估 |
| 隐藏地图 | 5 张 | 用于最终测评，选手不可见 |
创建评估任务时，可通过平台界面**勾选**需要评估的地图（支持多选 1～10）

**💡 泛化性建议**：

- 训练时建议使用**多张地图**进行训练，避免模型过拟合到单一地图
- 评估时建议在**多张不同地图**上测试模型表现，确保策略具备跨地图适应性
- 最终测评将在隐藏地图上进行，模型需要具备对**未见过地图**的泛化能力

### 环境配置
另外在创建评估任务时，还需对该任务的环境进行配置：


```
[env_conf]
# 官方机器人数量。可配置范围为1～4（整数）
robot_count: 4
# 充电桩数量。可配置范围为1～4（整数）
charger_count: 4
# 最大步数，单局任务预测步数达到最大步数时，任务结束。可配置范围为1～2000
max_step: 1000
# 最大电量，满电状态下的电量。可配置范围100～999
battery_max: 200
```
**任务状态**：


| 状态 | 说明 |
| --- | --- |
| 已完成 | 小悟机器人撞到官方机器人、电量耗尽、或达到任务最大步数时该局任务终止 |
| 异常 | 各种原因导致的异常 |

## 选手开发指引
基线代码包提供了最简单的智能体实现，以下给选手提供部分优化提示，选手们可以自行探索更多优化方向：


### 1. 特征工程

| 方向 | 说明 |
| --- | --- |
| 充电桩特征 | 添加充电桩位置、距离、BFS路径距离等信息 |
| NPC特征 | 添加官方机器人位置、速度、接近方向等信息 |
| 轨迹特征 | 记录历史移动轨迹，辅助避免重复路径 |
| 全局污渍图 | 使用粗粒度网格表示全局污渍分布 |
| 地图记忆 | 记录已探索区域和未清扫区域 |

### 2. 奖励设计

| 方向 | 说明 |
| --- | --- |
| 充电桩导航 | 低电量时鼓励接近充电桩 |
| NPC躲避 | 惩罚与官方机器人过近的行为 |
| 探索奖励 | 鼓励探索新区域，减少重复清扫 |
| 效率奖励 | 奖励连续清扫行为，惩罚空闲 |
| 多头奖励 | 分解清扫/电量/安全等多个目标 |

### 3. 模型结构

| 方向 | 说明 |
| --- | --- |
| CNN分支 | 处理局部地图保留空间结构信息 |
| 注意力机制 | 动态关注充电桩、NPC、污渍等实体 |
| 多头价值 | 分解清扫/充电/安全的价值估计 |
| RND网络 | 添加好奇心驱动促进探索 |
| 独立Critic | 分离策略和价值网络减少梯度干扰 |

### 4. 行为策略

| 方向 | 说明 |
| --- | --- |
| 充电策略 | 根据电量和距离决定何时返回充电 |
| 躲避策略 | 根据NPC位置和速度规划安全路径 |
| 清扫规划 | 优化清扫路径减少重复覆盖 |
