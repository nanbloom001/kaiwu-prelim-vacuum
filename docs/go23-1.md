# go23-1

## 1. 问题定义

基于上一轮验证，当前策略还剩两类典型失败：

1. 充电桩与官方机器人靠得太近时，机器人会在 `charge` 模式下反复躲避、局部打转，但电量其实还够，应该主动换去更安全的桩补电。
2. 遭遇官方机器人贴身压迫时，机器人虽然能避免立即碰撞，但容易在原地或 2~4 格小范围内来回摆动，缺少“先脱困、再恢复目标”的能力。

go23 解决的是「arrival credit 过宽」；go23-1 解决的是「planner 中间态太弱」。

---

## 2. go23-1 的核心判断

这两个问题本质上都不是 reward 不够，而是规则规划器缺一个中间层：

- 现在只有“正常追目标”
- 或“所有安全动作都没了再 fallback”

中间缺的是：

- `charge` 过程中，当前桩高风险且连续无推进时，允许换桩
- NPC 很近但还没完全封死时，允许暂时放弃原目标，先走 escape

因此 go23-1 不主打再堆 shaping，而是补 planner 的两个状态：

1. `charge retarget`
2. `npc escape`

---

## 3. 方案拆分

### 3.1 充电模式从“最近桩”升级成“按桩选优”

原问题：

- `_plan_path_to_charger()` 把所有充电桩格子摊平，一次 A* 找最近格子
- 这会偏向“物理上最近但实际高风险”的桩

go23-1 改法：

- 按 `charger_regions` 逐个评估充电桩
- 对每个桩单独规划路径
- 综合 `distance + risk_penalty + revisit_penalty` 选桩

风险项至少包含：

- 路径是否进入 `PATH_RISK_RADIUS`
- 目标桩本身是否离 NPC 过近
- 当前是否已经出现 charge-loop / 局部回环

这样 `charge` 目标不再是“最近格子”，而是“当前最值得去的桩”。

### 3.2 增加“连续停滞后换桩”

原问题：

- `return_mode` 一旦触发，会持续到接近满电
- 即使当前桩附近长期危险，也不会主动切换

go23-1 改法：

- 保持 `should_charge=True`
- 但若满足以下条件，可切去其他桩：

1. 当前仍在 `charge`
2. 连续若干帧 `charger_distance` 没有下降
3. 且当前路径/目标桩持续高风险
4. 且电量足够支撑去备选桩

对危险桩加入短暂 cooldown，避免立刻又被选回去。

### 3.3 增加主动 escape，而不是等 safe_mask 清零

原问题：

- 现在只有 safe 动作全灭时才走 fallback
- 只要还剩 1~2 个动作，就继续按原目标推进
- 结果是目标牵引和局部避险互相拉扯，容易小范围横跳

go23-1 改法：

- 当 `nearest_npc_distance <= 4`
- 且 `safe_mask` 很少，或最近 8 步已经形成局部回环

则临时进入 `escape`：

- 暂时忽略原目标
- 优先选择更远离 NPC、出口更多、不是回头路的动作

### 3.4 escape 打分从“单步远离”升级成“可持续脱困”

原问题：

- 旧的 `_rank_escape_actions()` 只看下一步离 NPC 远不远
- 不看候选点是否是死角、是否又回到刚才的位置

go23-1 改法：

- 保留 `npc_dist`
- 新增：
  - `safe_exits`
  - `dead_end_penalty`
  - `revisit_penalty`
  - `anti_backtrack_penalty`

目的不是走最远一步，而是走向更容易继续逃开的局部空间。

### 3.5 近 NPC 时，下调目标牵引

原问题：

- `_rank_legal_actions()` 在近 NPC 时仍给较强的 path 对齐和目标推进奖励
- 容易压过逃逸意图

go23-1 改法：

- 当 `nearest_npc_distance <= 3~4`
- 动态降低：
  - `path_action` 奖励
  - `progress` 权重
- 动态提高：
  - `npc_escape_progress`
  - 局部回环惩罚

这不是放弃目标，而是在危险窗口内把“脱困优先级”提到目标前面。

## 4. 代码落点

本次 go23-1 只改：

- `code/agent_ppo/algorithm/algorithm.py`
- `docs/go23-1.md`

主要新增状态：

- `recent_positions`
- `charge_stall_frames`
- `charger_avoid_until`

主要新增能力：

1. 局部回环检测
2. 按桩选优
3. 危险桩短时冷却
4. 近 NPC 主动 escape
5. escape 的出口/死角感知

---

## 5. 预期效果

go23-1 预期让下面指标下降：

- 充电桩附近的重复打转
- `mode=charge` 下的无效躲避步数
- 近 NPC 场景的原地回摆
- “明明没被完全封死却被拖死”的局数

允许短期波动的指标：

- 单局动作更不平滑
- 局部探索路径更分散
- 某些场景下首次到桩时间略变慢

这是可接受的，因为 go23-1 目标不是“更稳地追当前目标”，而是“别在错误目标上稳定打转”。

---

## 6. 验证重点

优先看以下日志现象是否改善：

1. `charge` 模式下，目标桩附近有 NPC 时，是否能在若干帧后切换到其他桩
2. 近 NPC 时，是否从 2~4 格小圈摆动变成更明显的脱困移动
3. `fallback` 触发次数是否下降，而 `escape` 是否承担更多中间态脱困
4. 早死局里，是否减少“最后几十步都在原地附近来回走”的轨迹

---

## 7. 一句话总结

go23-1 的本质是：

- **把 planner 从“只会追目标或彻底兜底”升级成“危险时先脱困、充电时能换桩”的中间态策略。**
