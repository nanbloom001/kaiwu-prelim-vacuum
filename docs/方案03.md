# 方案03：基于充电桩锚点、条带清扫与动态避碰的扫地机器人方案（强化版）

## 1. 文档目标

本文将原方案03从“泛化分治 + 学习优先”收紧为“安全硬约束 + 充电桩锚点规划 + 条带清扫 + 学习微调”的落地方案，直接解决实测中的三个主要问题：

- **无法稳定避开官方机器人**：官方机器人是动态障碍，不能再按静态墙处理。
- **回充规划偏晚**：必须保证任意时刻都存在一条可执行的安全回桩路径，且路上不会没电。
- **清扫轨迹绕圈严重**：要从“就近贪心 + 小范围打转”切到“长直线条带 + 少量换道 + 安全返航”。

本方案默认以当前仓库的训练配置为基线：

- 地图 `128 x 128`
- 局部视野 `21 x 21`
- 动作空间 `8` 方向
- `battery_max = 200`
- `robot_count = 4`
- `charger_count = 4`
- 当前本地 `max_step = 1000`

说明：策略结构不依赖 `max_step = 1000` 还是 `2000`，但电量规划必须严格按 `battery_max = 200` 设计。

---

## 2. 总体设计原则

1. **安全硬约束先于收益**：不撞官方机器人、不在去充电桩路上没电，这两件事高于任何清扫收益。
2. **充电桩是锚点，不是补救点**：开局先找桩、记桩、选桩、算回桩成本，不允许“电量低了再想起来回去”。
3. **清扫按条带执行，不按圆形扩散**：优先做长直线往返，必要时只移动 1 格换道，再继续直线清扫。
4. **先扫当前桩周边，再跨桩转场**：每个充电桩负责一片锚定区域，当前区域没有明显收益后才去下一个桩。
5. **学习模块只做局部微调**：返航、避碰、换桩、条带主逻辑全部由规则和规划控制，学习模块不能覆盖安全规则。

## 4. 关键状态与地图维护

整局维护以下状态：

```python
self.static_obstacle_map   # 静态墙体，确认后长期保存
self.free_map              # 已知可通行区域
self.dirt_map              # 已观测未清扫污渍
self.cleaned_map           # 已清扫区域
self.visit_count_map       # 访问次数，抑制来回绕圈
self.charger_map           # 已发现的充电桩坐标
self.anchor_region_map     # 每个格子归属哪个充电桩服务区
self.robot_tracks          # 官方机器人轨迹（位置、速度、置信度）
self.robot_danger_map      # 动态危险代价图
self.return_cost_cache     # 到各充电桩的最短路代价缓存
self.current_anchor        # 当前服务中的充电桩
self.current_stripe_plan   # 当前条带清扫计划
```

地图更新分两类：

1. **静态层**：墙体、已知可通行区域、充电桩、污渍、清扫结果。
2. **动态层**：官方机器人位置、预测速度、未来 3-5 步危险走廊。

静态层可累计，动态层要做衰减。对官方机器人，旧位置不应永久封死，只应在若干帧内保留风险。

## 5. 关键改进模块

### 5.1 开局即找最近可达充电桩

“最近充电桩”不能按欧氏距离选，而要按**当前已知地图上的最短可达路径代价**选。

#### 5.1.1 开局逻辑

```python
def init_episode(self, obs):
    self.reset_all_maps()
    self.update_memory(obs)
    self.update_chargers(obs)

    if self.charger_map:
        self.current_anchor = self.select_nearest_reachable_charger(self.cur_pos)
        self.bootstrap_return_path = self.plan_path(
            self.cur_pos,
            self.current_anchor,
            avoid_dynamic_robot=True,
        )
    else:
        # 若初始视野没看到充电桩，不做远距离盲走，只做保守探索
        self.mode = "SAFE_EXPLORE_FOR_FIRST_CHARGER"
```

#### 5.1.2 约束说明

- **只要视野内已经有充电桩，就必须立刻记录并建立到桩路径。**
- 如果初始视野没有充电桩，不允许直接深度探索，而是做**小半径保守探索**，直到看到首个充电桩。
- 一旦发现首个可达充电桩，就把它设为当前锚点，后续所有清扫和探索都以“能否返回任一已知充电桩”为前提。

### 5.2 电量护栏：任意时刻都能回到某个充电桩

这里不再用固定低电量阈值，而是改用**动态安全电量**：

```python
def calc_safe_energy(self, pos):
    min_return_cost = min(
        self.path_cost(pos, charger, avoid_dynamic_robot=True)
        for charger in self.charger_map
    )

    detour_margin = 8          # 官方机器人或局部绕障的冗余
    unknown_margin = 6         # 未完全观测区域的不确定性冗余
    dock_buffer = 6            # 到桩后的最小安全缓冲

    return min_return_cost + detour_margin + unknown_margin + dock_buffer
```

#### 5.2.1 电量硬规则

```python
def must_return_now(self, pos, battery):
    safe_energy = self.calc_safe_energy(pos)
    return battery <= safe_energy
```

规则说明：

- 只要 `battery <= safe_energy`，**立即停止清扫，切换返航模式**。
- 每前进一步，都要重新评估“新位置是否仍能安全回桩”。
- 条带计划、直接清扫、换桩转场，都必须经过这个可行性检查。

#### 5.2.2 动作级可行性检查

```python
def action_is_energy_feasible(self, next_pos, battery_after_move):
    safe_energy_after_move = self.calc_safe_energy(next_pos)
    return battery_after_move >= safe_energy_after_move
```

这意味着：**不是只检查“现在该不该回去”，而是检查“下一步走完以后还回不回得来”。**

### 5.3 官方机器人动态避让

官方机器人在视野里会表现为障碍，但本质上是会移动的动态体。如果仍然按静态障碍处理，会有两类问题：

1. 以为通道永久堵死，导致规划过于保守。
2. 没有提前预测交汇，导致正面撞上。

#### 5.3.1 检测思路

- 比较连续两帧 `21x21` 视野中的“障碍”分布。
- 对发生位移的障碍点进行匹配，形成机器人轨迹。
- 用最近 `3-5` 帧估计速度向量和移动方向。

```python
def update_robot_tracks(self, obs, prev_obs):
    moved_blocks = detect_moving_obstacle_cells(obs, prev_obs)
    self.robot_tracks = associate_tracks(self.robot_tracks, moved_blocks)
```

#### 5.3.2 危险走廊建模

不只是给机器人当前位置加一个圆形危险区，而是给它未来几步的路径加风险：

```python
def build_robot_danger_corridor(self):
    self.robot_danger_map.fill(0)
    for track in self.robot_tracks:
        for t in range(0, 5):
            pred = track.pos + t * track.velocity
            radius = 2 if t <= 2 else 1
            self.inflate_danger(pred, radius, decay=0.7 ** t)
```

#### 5.3.3 避让策略

- **路径规划阶段**：A* 将危险走廊作为高代价或不可通行区域。
- **执行阶段**：如果官方机器人朝当前路径迎面靠近，优先横向让开，避免同向抢道。
- **视野边缘阶段**：当机器人出现在 `21x21` 边界且朝本机靠近时，提前让路，不要等它贴脸再改。
- **窄路场景**：若返航通道被官方机器人短暂堵住，优先等待 1-2 步或平移让行，不要硬挤。

这部分的目标不是“永远离机器人很远”，而是**避免进入它未来几步高概率经过的区域**。

### 5.4 以充电桩为锚点的条带清扫

用户提出的“向左走 99 步、向上走 1 步、向右走 99 步回到充电桩”的思路是正确方向，本方案将其泛化为：

- **优先长直线**
- **每次只换 1 格道**
- **每条条带都带返航校验**
- **遇障碍或官方机器人后先绕开，再尽快回到原条带或下一条条带**

#### 5.4.1 条带区域定义

对当前 `current_anchor`，先计算该充电桩服务区域内的条带包围盒：

```python
def build_anchor_cleaning_area(self, charger):
    region = self.anchor_region_map == charger
    reachable = region & self.free_map
    return bounding_box(reachable)
```

#### 5.4.2 条带计划生成

```python
def generate_stripe_plan(self, charger):
    area = self.build_anchor_cleaning_area(charger)
    stripes = []

    # 宽区域优先水平条带，窄高区域优先垂直条带
    horizontal = (area.x_max - area.x_min) >= (area.z_max - area.z_min)

    if horizontal:
        z = charger[1]
        direction = -1  # 先向左，便于从充电桩外扩
        while area.z_min <= z <= area.z_max:
            end_x = area.x_min if direction < 0 else area.x_max
            stripes.append((end_x, z))
            z += 1
            direction *= -1
    else:
        x = charger[0]
        direction = -1
        while area.x_min <= x <= area.x_max:
            end_z = area.z_min if direction < 0 else area.z_max
            stripes.append((x, end_z))
            x += 1
            direction *= -1

    return stripes
```

#### 5.4.3 为什么不是机械固定 99 步

`99` 只是一个形象例子，不是固定常量。真实执行时，单条条带的终点必须满足：

```python
def stripe_endpoint_is_feasible(self, endpoint):
    cost_to_endpoint = self.path_cost(self.cur_pos, endpoint, avoid_dynamic_robot=True)
    cost_back_to_any_charger = min(
        self.path_cost(endpoint, charger, avoid_dynamic_robot=True)
        for charger in self.charger_map
    )
    reserve = 12
    return self.battery >= cost_to_endpoint + cost_back_to_any_charger + reserve
```

因此，真正的“99 步”应理解为：

- 条带尽可能长；
- 但长度上限由**返航代价 + 绕障冗余 + 官方机器人风险**共同决定；
- 不满足可行性时，必须提前截断并返航。

#### 5.4.4 条带执行规则

1. **必须在满电或接近满电时出条带**，否则先回桩补电。
2. **每到一个新条带终点前做一次电量可行性校验**。
3. **遇到障碍或机器人导致条带断裂时**：
   - 先局部绕障；
   - 若 3-5 步内无法回到原条带，则直接跳到最近的后续条带入口；
   - 若剩余电量不足，则立即返航。
4. **返航不是失败，而是条带循环的一部分**。

### 5.5 充电桩服务区管理与换桩策略

原方案的固定 `4x4` 网格分区不够贴近回充机制。更合理的做法是：**每个充电桩负责一片服务区，先吃净本区，再考虑跨桩。**

#### 5.5.1 服务区划分

对每个已知可通行格子，归属到“最容易回去的充电桩”：

```python
def assign_anchor_regions(self):
    for cell in known_reachable_cells:
        best_charger = min(
            self.charger_map,
            key=lambda c: self.path_cost(cell, c, avoid_dynamic_robot=False),
        )
        self.anchor_region_map[cell] = best_charger
```

这样得到的不是规则矩形，而是**按真实路径代价划分的充电桩 Voronoi 区域**。

#### 5.5.2 当前区域完成判定

满足以下任一条件，可以考虑换桩：

- 当前充电桩服务区清扫覆盖率超过 `85%`
- 当前区域已知污渍很少，边际收益明显下降
- 当前区域条带大多已执行完毕，剩余只是不规则碎片

#### 5.5.3 换桩约束

换桩不是随时都能做，必须同时满足：

1. 当前在某个充电桩上或距离充电桩很近；
2. 电量接近满电；
3. 到目标充电桩的转场路径可行；
4. 路径不穿过高风险官方机器人走廊。

#### 5.5.4 下一个目标充电桩评分

```python
def score_next_charger(self, charger):
    uncleaned_ratio = self.calc_uncleaned_ratio(charger)
    dirt_density = self.calc_dirt_density(charger)
    transfer_cost = self.path_cost(self.cur_pos, charger, avoid_dynamic_robot=True)
    robot_risk = self.estimate_robot_risk_on_path(self.cur_pos, charger)

    return (
        2.0 * uncleaned_ratio
        + 1.2 * dirt_density
        - 0.03 * transfer_cost
        - 0.8 * robot_risk
    )
```

目标很明确：**先把当前锚点附近扫干净，再按“剩余收益 / 转场成本”选择下一桩。**

### 5.6 模式优先级重排

原方案里“学习微调”和“探索”比重偏高，实际比赛里不够稳。这里重新定义模式优先级：

| 优先级 | 模式 | 触发条件 | 说明 |
|---|---|---|---|
| P0 | `EMERGENCY_EVADE` | 2-3 步内预测会与官方机器人冲突 | 先让路再谈其他 |
| P1 | `RETURN_TO_CHARGER` | `battery <= safe_energy` | 立刻返航，不继续清扫 |
| P2 | `STUCK_RECOVERY` | 连续振荡或原地绕圈 | 快速脱困，避免无效耗电 |
| P3 | `CHARGER_TRANSFER` | 当前服务区收益低且满电可转场 | 去下一个充电桩 |
| P4 | `STRIPE_CLEANING` | 当前锚点区域仍值得扫且电量充足 | 主工作模式 |
| P5 | `DIRECT_DIRT_PICKUP` | 视野内有近距离污渍且不破坏返航约束 | 顺手清掉局部高价值污渍 |
| P6 | `SAFE_EXPLORATION` | 尚未发现足够充电桩或区域边界未知 | 小半径保守探索 |

模式切换加冷却时间，避免在 `DIRECT_DIRT_PICKUP` 和 `STRIPE_CLEANING` 之间来回抖动。

## 6. 学习模块重新定位

方案03仍可保留学习模块，但它只能做**局部选择微调**，不能决定安全动作。

### 6.1 建议新增特征

```python
nearest_charger_path_len     # 到最近充电桩的 A* 路径长度
charger_buffer_gap           # battery - safe_energy
other_robot_min_dist         # 最近官方机器人距离
other_robot_rel_speed        # 最近官方机器人相对速度
robot_danger_action_mask     # 会进入危险走廊的动作掩码
stripe_heading_alignment     # 当前动作与条带主方向是否一致
revisit_penalty_local        # 下一格的重复访问惩罚
```

### 6.2 输出约束

学习策略输出前必须乘以两个掩码：

1. `legal_action_mask`
2. `robot_danger_action_mask`

这样做的目的很直接：**即便策略网络判断失误，也不能选出会撞机器人或导致返航失效的动作。**

## 7. 核心决策伪代码

```python
def decide_action(self, obs):
    self.update_memory(obs)
    self.update_chargers(obs)
    self.update_robot_tracks(obs, self.prev_obs)
    self.build_robot_danger_corridor()
    self.assign_anchor_regions()

    # P0: 官方机器人紧急避让
    if self.predict_robot_conflict(within_steps=3):
        return self.evade_robot()

    # P1: 电量硬约束返航
    if self.must_return_now(self.cur_pos, self.battery):
        return self.return_to_nearest_safe_charger()

    # P2: 脱困
    if self.is_stuck():
        return self.stuck_recovery()

    # P3: 当前区域已扫得差不多，且适合换桩
    if self.should_switch_anchor():
        return self.transfer_to_next_charger()

    # P4: 条带清扫
    if self.can_run_stripe_cleaning():
        return self.follow_or_rebuild_stripe_plan()

    # P5: 视野内顺手清局部污渍
    if self.has_high_value_visible_dirt():
        return self.pickup_visible_dirt_safely()

    # P6: 只做保守探索
    return self.safe_frontier_explore()
```

这段逻辑体现的就是一句话：**先活下来，再回得去，然后再讲清扫效率。**

```python
ROBOT_TRACK_MEMORY = 5

# 条带清扫
STRIPE_SHIFT = 1
STRIPE_MAX_LEN = 99           # 仅作上限，真实长度受返航约束裁剪
STRIPE_REJOIN_BUDGET = 5      # 条带断裂后最多尝试 5 步回到原计划
ANCHOR_FINISH_RATIO = 0.85

# 脱困与模式稳定
STUCK_WINDOW = 10
MODE_COOLDOWN = 5
MAX_LOCAL_OSCILLATION = 4
```

参数解释：

- `STRIPE_MAX_LEN = 99` 只是条带长度上限，**不是固定走法**。
- `ANCHOR_FINISH_RATIO = 0.85` 不是绝对值，可根据地图污渍密度调整到 `0.80-0.90`。
- `DETOUR_MARGIN` 要覆盖机器人避让和障碍绕行，宁可保守一些，也不要在返航路上耗尽电量。

## 10. 评测指标

本方案建议重点监控以下指标，而不是只看总分：

1. **官方机器人碰撞次数**：目标接近 `0`
2. **返航成功率**：目标尽量接近 `100%`
3. **路上耗尽电量次数**：目标严格为 `0`
4. **单位电量清扫效率**：`clean_score / battery_consumed`
5. **重复覆盖率**：同一格高频访问比例
6. **条带完成率**：生成的条带计划中真正执行完成的比例
7. **换桩收益**：每次跨桩后带来的新增清扫收益

如果总分上来了，但碰撞次数仍高、路上断电仍多，那这个方案仍然不算完成。

---

## 11. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 初始视野没有充电桩 | 无法立刻做回桩规划 | 使用小半径保守探索，首个充电桩一出现立即锁定 |
| 官方机器人把返航通道短暂堵住 | 可能误判成无路可走 | 先等待或横移让行，再重新规划，不硬挤 |
| 条带被障碍切碎 | 条带计划执行率下降 | 把长条带分段化，允许跳到后续条带入口 |
| 电量阈值过保守 | 清扫范围过小 | 按地图和机器人密度微调冗余项，不改硬约束结构 |
| 学习模块试图偏离安全策略 | 稳定性下降 | 学习输出永远受 legal mask 和 danger mask 约束 |

---

## 12. 总结

强化后的方案03不再把重点放在“泛化的区域探索”上，而是转成更贴合赛题实战的四件事：

1. **开局即找最近可达充电桩并建立返航路径**
2. **任何时刻都保证走下一步后仍能安全回桩**
3. **围绕当前充电桩做条带式直线清扫，少绕圈、多直行**
4. **把官方机器人当动态风险体处理，提前预测、提前避让**

如果按这个方向落地，方案03会比原版更稳、更可解释，也更符合你当前测试里暴露出的真实问题。
