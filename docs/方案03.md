# 清扫大作战 - 强化学习训练方案 03

基于对腾讯开悟“清扫大作战”赛题环境和当前 PPO 基线代码的分析，本方案设计了一套更完善的强化学习训练架构。现阶段基线特征与奖励均为占位符，本方案重点聚焦于**特征工程增强**、**奖励重塑 (Reward Shaping)** 以及**模型网络结构的升级**。

## 1. 任务概述
小悟机器人需要在 128×128 的栅格地图中，有限步数（1000步）和有限电量（200）的情况下，躲避 4 个随机巡逻的官方机器人，适时利用充电桩补充电量，并尽可能多地清扫污渍地面。

## 2. 状态与观测空间设计 (Observation Space)
基线代码目前只使用了全零的一维向量。我们需要充分利用环境提供的局部视野与全局状态信息，构建组合特征输入：

### 2.1 视觉感知特征 (Visual Features)
利用 `env_obs.map_info` 提取以小悟机器人为中心的局部视野（建议裁剪到 11×11 或保持 21×21）。
为了便于卷积神经网络（CNN）处理，可以将其按通道（Channel）拆分：
- **Channel 1 (障碍物/墙壁)**：1 表示障碍物，0 表示其他。
- **Channel 2 (可通行道路)**：1 表示空地/已清扫区域，0 表示其他。
- **Channel 3 (污渍区域)**：1 表示有污渍，0 表示其他。
- **Channel 4 (充电桩位置)**：在相对坐标上标注充电桩区域（3×3）。
- **Channel 5 (官方机器人)**：在相对坐标上标注 NPC 位置。

### 2.2 标量状态特征 (Scalar Features)
基于 `frame_state` 与 `env_info` 构建归一化的状态向量：
- **电量特征 (Battery)**：`当前电量 / 最大电量`。
- **时间特征 (Time/Steps)**：`当前步数 / 最大步数`。
- **危险感知 (NPC Proximity)**：与最近的官方机器人的曼哈顿距离/欧氏距离。
- **充电需求 (Charger Proximity)**：与最近的充电桩的距离。

## 3. 动作空间优化 (Action Space)
游戏原生支持 8 维离散动作空间（0-7 表示 8 个移动方向）。
- **合法动作掩码 (Action Masking)**：直接利用环境返回的 `legal_act` 屏蔽不可行走的动作（撞墙、斜穿角），在 Actor 网络输出阶段对非法动作赋予一个极大的负值，避免采样。

## 4. 奖励函数设计 (Reward Shaping)
原环境 `env.step` 返回的 reward 仅包含清扫得分，这不足以指导智能体学习复杂策略（如由于缺电导致的远期死亡、撞击 NPC 引起的突发死亡）。设计如下组合奖励函数：

1. **清扫奖励 (Cleaning Reward)**：
   - 每前进一步且清扫到新污渍：**+1.0**。
2. **时间惩罚 (Step Penalty)**：
   - 每存活一步消耗：**-0.01**（鼓励提高清扫效率，避免原地徘徊）。
3. **生存与死亡惩罚 (Survival & Fatal Penalty)**：
   - 撞击官方机器人死亡：**-50.0**。
   - 电量耗尽导致死亡：**-50.0**。
4. **电量管理奖励 (Battery Management)**：
   - 低电量时（例如低于 20%），朝最近充电桩移动的距离差值（Delta Distance）奖励：**+0.1**，远离惩罚。
   - 成功充电：**+10.0**，但增加冷却机制，避免满电重复刷充电奖励。
5. **安全距离惩罚 (Safety Penalty)**：
   - 如果官方机器人在周围 5 格以内，给予靠近惩罚：**-0.5**。

## 5. 模型架构升级 (Model Architecture)
基线的双层 MLP 无法有效处理 21×21 的空间特征。拟采用 **CNN + MLP 的双源输入网络**方案：

- **特征提取主干 (Backbone)**：
  - 对 21×21×5 的空间特征，通过 2 维卷积层（如 2x Conv2D + ReLU + Flatten）进行编码，提取局部感知特征（如输出 128 维）。
  - 对标量状态特征，进行 BatchNorm 并通过单层 MLP 编码（如输出 32 维）。
  - 将两者拼接（Concat），形成 160 维的融合特征。
- **Actor 头 (Policy)**：MLP (160 → 64 → 8)，配合 `legal_act` 掩码输出动作分布（Softmax）。
- **Critic 头 (Value)**：MLP (160 → 64 → 1)，输出当前的 State-Value 估计值。

## 6. PPO 超参数调优策略
参考环境特性，建议对 `conf.py` 以下参数进行初始调整：
- **`GAMMA`**: 维持 `0.99`（视野大，需考虑长远收益）。
- **`LAMDA`**: `0.95`。
- **`BETA_START` (Entropy Coef)**: 提高至 `0.01` 甚至 `0.05`。清扫大作战对探索要求高，若早期熵过低，智能体容易陷入局部清扫不愿往远处探索。
- **`INIT_LEARNING_RATE_START`**: `3e-4`。配合较小的 `BATCH_SIZE` 和合适的 `EPOCH` 以保证策略稳定更新。

## 7. 实施与迭代计划

1. **Phase 1: 数据流跑通**
   - 在 `agent_diy` (或 `agent_ppo`) 中修改 `definition.py`，更新 `DIM_OF_OBSERVATION` 维度。
   - 修改 `preprocessor.py` 写入实际的观测处理逻辑、生成空间+标量特征。
2. **Phase 2: 基础模型验证**
   - 更新 `model.py` 构建 CNN+MLP 拼接网络。
   - 部署清扫、生存、时间衰减的基础奖励。观察单地图上机器人是否学会基本寻路。
3. **Phase 3: 高级行为训练**
   - 引入 NPC 躲避和充电引导的 Reward Shaping。
   - 检查 TensorBoard 监控日志中的 Episode Length 和累计 Reward。
4. **Phase 4: 评估与泛化寻优**
   - 在多地图开启随机训练（`train_env_conf.toml` 设置 `map_random=true`）。
   - 微调截断系数（Clip Param）与熵系数（Entropy），追求泛化性能上限。
