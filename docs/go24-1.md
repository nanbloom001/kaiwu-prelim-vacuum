# go24-1: 性能优化方案 - 解决go23版本训练启动变慢

## 1. 问题诊断

基于go23版本代码分析，训练启动变慢的主要原因是**每帧特征预处理中引入了大量计算开销**：

### 1.1 go23相比go22的性能影响分析

| 新增/修改模块 | 操作内容 | 执行频率 | 计算复杂度 | 影响 |
|-------------|--------|--------|---------|------|
| charger region解析 | 为每个充电桩生成Set[Position] | **每帧** | O(n×w×h) | 🔴高 |
| pending_arrivals管理 | 遍历字典处理多个状态 | **每帧** | O(k×p) | 🔴高 |
| 全局状态特征扩展 | 77D→84D，新增7个维度计算 | **每帧** | O(m) | 🟡中 |
| 距离计算 | 到达/未达到的最近桩距离 | **每帧** | O(m) | 🟡中 |
| 新增数据结构 | 多个字典/集合的维护 | **每帧** | O(1)~O(k) | 🟡中 |

**关键发现**：
- `pb2struct()` 中的charger region解析是最大瓶颈
- `_resolve_pending_arrivals()` 在pending arrivals多时成为热点
- 特征计算维度增加导致整体特征提取变慢

### 1.2 初步性能评估

假设每个charger region平均10x10格子，4个chargers，每帧1000步：
- charger region解析: 4 × 100 × (遍历+集合操作) ≈ **0.5-1ms/帧**
- pending_arrivals遍历: 4~8 × 状态检查 ≈ **0.3-0.5ms/帧**
- 新增特征计算: 7个新维度 ≈ **0.1-0.2ms/帧**

**单帧累计**: **1-2ms**，1000步/局 = **1-2秒/局启动开销**

## 3. go24-1 优化策略

## 3.1 策略一：缓存charger regions，避免重复解析

**问题**: 当前每帧都调用 `_parse_charger_regions()`，重复解析organs数据。

**优化方案**：

```python
def __init__(self):
    self.reset()
    self._last_organs_hash = None  # 新增：缓存hash
    self._cached_charger_regions = []

def pb2struct(self, env_obs: dict, last_action: int):
    # 计算organs的hash值
    organs_tuple = tuple(
        (organ['sub_type'], organ['pos']['x'], organ['pos']['y'])
        for organ in env_obs.get('organs', [])
    )
    organs_hash = hash(organs_tuple)
    
    # 只在organs变化时重新解析
    if organs_hash != self._last_organs_hash:
        self.charger_regions = self._parse_charger_regions(env_obs.get("organs", []))
        self._last_organs_hash = organs_hash
    else:
        self.charger_regions = self._cached_charger_regions
```

**预期效果**: 
- organs通常不变（同一局游戏）
- 仅在地图变化或新局时解析
- **减少99%的charger region解析调用** ✅

---

## 3.2 策略二：增量更新pending_arrivals，不全量遍历

**问题**: `_resolve_pending_arrivals()` 每帧遍历所有pending arrivals，即使大多数状态不变。

**优化方案**：

引入"脏标记"(dirty flag)，仅处理可能状态改变的arrival：

```python
def _resolve_pending_arrivals(self, ...):
    reward = 0.0
    
    # 仅处理脏的到达记录
    for region_key, info in list(self.pending_arrivals.items()):
        # 快速路径：如果已final_confirmed且未进入高危，跳过
        if info.get("final_confirmed") and not info.get("_dirty"):
            continue
        
        # ... 原有状态检查逻辑 ...
        
        # 清除脏标记
        info["_dirty"] = False
    
    return reward

def pb2struct(self, ...):
    # ... 更新状态时标记脏 ...
    for region_key in self.pending_arrivals:
        # 当以下条件变化时，标记脏
        if self.charge_active or self.is_starving or battery_changed:
            self.pending_arrivals[region_key]["_dirty"] = True
```

**预期效果**:
- final_confirmed的到达记录基本不需要再处理
- 仅新进入pending的到达和高危情况需要检查
- **减少70-80%的状态检查次数** ✅

## 3.3 策略三：预计算常用距离，使用Grid索引加速

**问题**: 每帧计算 `_nearest_charger_distance()` 和 `_nearest_unarrived_charger_distance()` 需要O(m)次距离计算。

**优化方案**：

缓存charger positions在Grid中，快速查询：

```python
def reset(self):
    # ... 现有代码 ...
    self._charger_grid = {}  # 新增：网格索引
    self._charger_grid_cell_size = 10  # 10x10格子为一个grid cell

def _build_charger_grid(self):
    """构建charger position的grid索引"""
    self._charger_grid.clear()
    for cx, cz in self.charger_positions:
        grid_x = cx // self._charger_grid_cell_size
        grid_z = cz // self._charger_grid_cell_size
        key = (grid_x, grid_z)
        if key not in self._charger_grid:
            self._charger_grid[key] = []
        self._charger_grid[key].append((cx, cz))

def _nearest_charger_distance_fast(self) -> float:
    """使用grid索引的快速查询"""
    hx, hz = self.cur_pos
    grid_x = hx // self._charger_grid_cell_size
    grid_z = hz // self._charger_grid_cell_size
    
    # 只搜索周围9个grid cell，而不是所有chargers
    min_dist = self.MAX_DIST
    for dx in [-1, 0, 1]:
        for dz in [-1, 0, 1]:
            key = (grid_x + dx, grid_z + dz)
            if key not in self._charger_grid:
                continue
            for cx, cz in self._charger_grid[key]:
                dist = np.sqrt((cx - hx) ** 2 + (cz - hz) ** 2)
                min_dist = min(min_dist, dist)
    
    return float(min_dist)
```

**预期效果**:
- charger position查询从O(m)降至O(1)~O(9) ✅
- grid构建一次成本 << charger数查询成本
- **减少90%的距离计算** ✅

## 3.4 策略四：延迟计算非关键特征维度

**问题**: 全局状态从77D扩展到84D，新增7个维度计算每帧执行，但其中一些(如battery_capacity_norm)变化缓慢。

**优化方案**：

对变化缓慢的特征使用缓存：

```python
def _get_global_state_feature(self) -> np.ndarray:
    """构造27D全局手工特征向量"""
    hx, hz = self.cur_pos
    
    step_norm = _norm(self.step_no, 2000)
    battery_ratio = _norm(self.battery, self.battery_max)
    cleaning_progress = _norm(self.dirt_cleaned, self.total_dirt)
    # ... 基础特征 ...
    
    # 缓存计算：这些特征变化缓慢
    if self.step_no % 10 == 0 or self._recalc_slow_features:
        self._battery_capacity_norm = _norm(self.battery_max, 999, 100)
        self._charger_count_norm = _norm(self.episode_charger_count, 4, 1)
        self._observed_charger_ratio = min(
            len(self.charger_positions) / max(self.episode_charger_count, 1), 1.0
        )
        self._recalc_slow_features = False
    
    battery_capacity_norm = self._battery_capacity_norm
    charger_count_norm = self._charger_count_norm
    observed_charger_ratio = self._observed_charger_ratio
    
    # ... 拼接特征 ...
```

**预期效果**:
- 约25%的新特征计算延迟到每10步
- 不影响最终特征完整性，仅延迟10步（可感知的动态变化时间 > 10步）
- **减少20-30%的特征计算开销** ✅

## 3.5 策略五：批量处理arrival确认窗口，分离关键路径

**问题**: `_resolve_pending_arrivals()` 在单一函数中处理多个复杂判断，难以优化。

**优化方案**：

拆分为"关键路径"和"背景处理"：

```python
def _resolve_pending_arrivals_fast(self, ...) -> float:
    """快速路径：仅处理当前帧可能改变的状态"""
    reward = 0.0
    
    for region_key, info in list(self.pending_arrivals.items()):
        age = self.step_no - int(info["arrival_step"])
        params = self._arrival_confirm_params(int(info["arrival_order"]))
        
        # 快速过滤：不在确认窗口内的，跳过
        if age < int(params["candidate_min_delay"]):
            continue
        if age > int(params["final_deadline"]) + 100:
            continue
        
        # ... 仅处理候选确认/最终确认/高风险检查 ...
    
    return reward

def _resolve_pending_arrivals_cleanup(self):
    """后台清理：周期性清理过期的arrivals"""
    # 每10帧执行一次
    if self.step_no % 10 != 0:
        return
    
    for region_key, info in list(self.pending_arrivals.items()):
        age = self.step_no - int(info["arrival_step"])
        if age > 500:  # 超过500步的arrival全部清理
            del self.pending_arrivals[region_key]
```

**预期效果**:
- 关键路径逻辑提炼，更容易编译器优化
- 后台清理不影响推理路径
- **减少30-40%的条件判断** ✅
