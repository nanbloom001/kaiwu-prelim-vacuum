# go18

目标：针对当前训练中“能活但不够高分”的问题，专门提升 `900+` 分高分段占比，而不是优先追求单纯的存活率提升。

从当前日志看，策略已经具备一定生存能力，但还没有把“活下来”稳定转化成“高效覆盖”。  
因此 `go18` 的优化核心不是继续单纯防暴毙，而是：

- **把大量 `700~850` 的低效存活局，推进到 `900+` 的高分局。**

---

## 1. 当前问题结论

基于现有训练日志，当前回合大致分成三类：

### 1.1 高质量高分局

特征：

- `score >= 900`
- 多数情况下 `charger_arrivals = 3`
- 能稳定跑满 `1000` 步

这说明当前策略在部分局里已经学会了：

- 多充电桩利用
- 更完整的地图覆盖
- 更高效的清扫路径

---

### 1.2 低效存活局

特征：

- 可以跑满 `1000`
- 但 `charger_arrivals = 1`
- 分数常见在 `733 / 777 / 810 / 836 / 853 / 875`

这类局数量很多，是当前高分占比上不去的主因。

本质上是：

- 活下来了
- 但仍停留在“单桩吸附 + 局部低效覆盖”状态

---

### 1.3 charge 崩溃局

特征：

- `mode=charge FAIL`
- 分数掉到 `150~700`

这类局仍然存在，但从“提升高分占比”的角度看，它并不是当前最大头的问题。

因为：

- 当前更大的问题不是“完全不会活”
- 而是“活下来但活得不够漂亮”

---

## 2. go18 核心判断

如果只看高分占比，当前最关键的问题不是：

- 第一个桩到不了
- 或 learner 不收敛

而是：

1. **第二个充电桩到达不稳定**
2. **第三个充电桩到达不稳定**
3. **大量局停留在“只到 1 个桩但能跑满”的中低效状态**

所以 go18 的核心任务是：

- **把“单桩可活”继续推成“多桩高效覆盖”。**

---

## 3. 方案原则

`go18` 继续遵守低风险原则：

1. 不改网络结构
2. 不改 planner 主状态机
3. 不引入黑名单、换桩等高复杂逻辑
4. 主要通过：
   - reward 结构重分配
   - 局部热点惩罚
   - 未到达桩接近奖励
   - 少量 charge 边界保持现状

这样做的原因是：

- 当前问题已不是系统性崩坏
- 而是行为层偏好还没有完全压缩

---

## 4. go18 方案总览

go18 的思路可以概括为三句话：

1. **让第二桩更值得去**
2. **让旧热点更不值得留**
3. **把低效满步局推成高效满步局**

---

## 5. 具体方案设计

### 5.1 重新定义充电桩首次到达奖励

当前问题不是第一个桩难到，而是第二、第三个桩不稳定。

所以 go18 建议按到达序号重新分配奖励：

```python
first_arrival  = 0.16
second_arrival = 0.32
third_arrival  = 0.24
```

并配一个更缓和的衰减：

```python
arrival_scale = max(0.65, 1.0 - 0.25 * cleaning_progress)
```

设计逻辑：

1. 第一个桩本来就容易到
   - 不需要继续加重激励
2. 第二个桩是从 `800` 分段迈向 `900+` 分段的关键
   - 奖励最高
3. 第三个桩继续鼓励
   - 但略低于第二个桩

预期效果：

- 第二个桩首次到达比例上升
- `charger_arrivals=1` 的局占比下降

---

### 5.2 增强“靠近未到达桩”的阶段奖励

只奖励最终到达还不够，很多局会在接近时被局部路径吸回去。

go18 建议：

```python
if nearest_unarrived_dist < 20:
    bonus += 0.012
if nearest_unarrived_dist < 12:
    bonus += 0.015
if nearest_unarrived_dist < 6:
    bonus += 0.010
```

触发条件：

- 当前仍存在未到达桩
- 非 starving
- 当前不在 charger 上
- 电量高于安全返航线

作用：

- 把“接近第二/第三个桩”的过程本身也变成正反馈
- 减少“已经快到了，又回去绕近桩”的现象

---

### 5.3 专项打击“低效热点循环”

当前很多低分满步局，本质上是：

- 在旧区域重复走
- 没开新图
- 也没新增清扫

go18 建议继续加一个专项惩罚：

```python
if cur_revisit_count >= 3 and new_observed_cells == 0 and cleaned_this_step == 0:
    loop_penalty = -0.012
else:
    loop_penalty = 0.0
```

再加限制：

- `not starving`

这样做比全局继续扩大 `revisit_penalty` 更稳，因为它只打击：

- “重复走老路”
- “没有探索收益”
- “没有清扫收益”

这正是低效满步局的典型模式。

---

### 5.4 继续区分“新路”和“旧路”

当前 `fresh_path_reward` 已有一定效果，但仍偏保守。

go18 建议改为：

```python
if cur_revisit_count == 0:
    fresh_path_reward = 0.015
elif cur_revisit_count == 1:
    fresh_path_reward = 0.006
else:
    fresh_path_reward = 0.0

fresh_path_reward *= max(0.45, 1.0 - 0.45 * cleaning_progress)
```

作用：

- 对真正新路径再增强一点吸引
- 但仍远小于主清扫收益

---

### 5.5 charge 安全边界不作为主优化点

go18 的目标是高分占比，不是进一步偏保守。

所以 charge 边界只建议保持当前较稳的版本，不继续明显收紧：

```python
is_starving = battery <= nearest_charger_dist + 22

if battery <= charger_distance + 16:
    alpha = 0.0
elif battery <= charger_distance + 22:
    alpha = min(alpha, 0.001)
```

原因：

- 当前最大问题不是“还不够保命”
- 而是“保住命之后没有继续做高效覆盖”

---

## 7. 预期效果

如果 go18 有效，预计会先看到：

1. `charger_arrivals=1` 的满步局明显减少
2. `charger_arrivals=2/3` 的局比例上升
3. `900+` 分局占比提升
4. `700~850` 分段缩小
5. `max_steps=1000` 比例不明显下降

真正说明 go18 生效的关键指标是：

- `charger_arrived_count`
- `charger_second_arrival_step`
- `charger_third_arrival_step`
- `900+` 分局占比
- `1000步但<850分` 的局占比

---

## 8. 风险与控制

### 风险 1：为了找第二桩而牺牲清扫效率

控制方式：

- 第一桩奖励降低
- 第二桩最高、第三桩次高
- 保留衰减，不让 charger reward 无限占优

### 风险 2：热点惩罚过强导致策略躁动

控制方式：

- 只在“重复 + 无探索 + 无清扫”时触发
- 不做全局粗暴惩罚

### 风险 3：高分占比提升，但 charge 失败反弹

控制方式：

- 不动当前较稳的 charge 安全边界
- 先把优化重点放在覆盖效率层

---

## 9. 结论

go18 的一句话总结：

- **不是继续泛化地强化探索，而是专门提高“第二桩到达率”和“高效覆盖率”，把大量低效满步局推进到高分局。**

也就是说：

1. 现在不是“先活下来”阶段了
2. 而是“活下来之后，尽量别只拿一个中等分”
3. go18 的任务，就是提升 `900+` 高分段占比
