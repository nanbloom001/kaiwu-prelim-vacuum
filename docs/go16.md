# ho16

目标：针对当前训练中普遍存在的“某个靠近起点、靠近狭窄封闭区域的充电桩把机器人吸住，机器人在局部重复路径打转，对另外两个充电桩探索不足”的问题，在保留 `go16-1` 安全边界与吸收 `go16-2` 低风险优化项的基础上，提出一版更适合当前阶段的综合微调方案。

本轮仍然坚持一个基本原则：

- **优先做低风险、可归因、不会再次引入卡死的调整**

所以 `ho16` 的核心不是重写 planner，而是：

1. 保留 `go16-1` 的 charge 安全边界
2. 吸收 `go16-2` 的低风险优化项
3. 重新设计 reward 中“首次到达充电桩”与“非重复路径”这两部分的量级关系

---

## 1. 当前问题定义

从训练可视化与日志表现看，当前策略已经具备：

- 大多数局可以正常训练并稳定结束
- 多数地图能打到较高分数
- learner / aisrv / env 三侧链路正常

但仍存在一类非常典型的局部最优：

1. 某个充电桩靠近起点
2. 该充电桩又靠近较窄、较封闭区域
3. 机器人较早发现并到达这个桩后
4. 后续长时间围绕该桩附近做局部往返
5. 对另外两个充电桩探索不足，甚至完全不去到达

这类现象的直接后果是：

- 多桩资源利用不足
- 地图探索范围偏小
- 路径重复率升高
- 中后期容易在局部区域被官方机器人/NPC 干扰
- 某些地图上会进一步放大 charge 模式风险

所以 `ho16` 的问题不是“不会充电”，而是：

- **会充一个近桩，但不愿意为更优的全局布局去探索其余充电桩**

---

## 2. 当前 reward 权重分析

当前 `agent_ppo/feature/preprocessor.py` 中与这个问题直接相关的 reward 量级如下。

### 2.1 清扫主收益

```python
cleaning_reward = 0.22 * cleaned_this_step
```

含义：

- 每清掉 1 格污渍，直接得到 `+0.22`

这个量级很强，是当前策略的主驱动力，没有问题，不建议动。

---

### 2.2 探图收益

```python
explore_reward = 0.003 * min(self.new_observed_cells, 12) * max(0.0, 1.0 - cleaning_progress)
```

上限大约是：

```python
0.003 * 12 = 0.036
```

含义：

- 每步如果能开新图，会得到最多约 `+0.036`

这个量级不大，但持续性强。

---

### 2.3 接近污渍收益

```python
approach_reward = 0.01
```

这是一个小引导项，本身问题也不大。

---

### 2.4 当前首次到达充电桩奖励

当前实现来自 go12：

```python
self.new_charger_arrival_reward += 0.12
charger_arrival_reward = self.new_charger_arrival_reward * max(0.55, 1.0 - 0.45 * cleaning_progress)
```

也就是说：

- 单个新充电桩首次到达，奖励基值是 `+0.12`
- 再乘一个衰减因子
- 实际常见有效值大约落在：
  - `0.066 ~ 0.12`

这个量级与主 reward 对比后会发现明显偏弱：

1. `0.12` 只相当于清掉 **不到 1 格**污渍的一半多一点
2. 机器人如果为了去第二个桩要额外走几十步，这个一次性收益很容易被局部清扫收益覆盖
3. 对“愿不愿意脱离当前近桩吸引区”来说，这个奖励不够强

结论：

- **当前首次到达充电桩奖励确实偏弱**

---

### 2.5 当前重复路径惩罚

当前实现：

```python
revisit_penalty = -0.0025 * min(3, self.cur_revisit_count) * (0.35 + cleaning_progress)
```

其量级大致是：

- 早期重复一步，惩罚很小
- 即便 `cur_revisit_count >= 3`
- 中后期单步惩罚通常也只在 `-0.003 ~ -0.010` 左右

这意味着：

1. 机器人在局部打转很多步，累计惩罚虽然有，但太慢
2. 对比局部继续清污渍的收益，这个惩罚抑制力不够
3. 在“近桩 + 窄区域 + 局部热点”这种场景下，策略仍容易接受这点惩罚

结论：

- **当前重复路径惩罚也偏弱**

---

## 3. 根因总结

当前“近桩吸附、远桩不探索”的根因，不是单点问题，而是 reward 相对关系的问题：

1. 首次到达新充电桩奖励太小
   - 无法覆盖为探索第二、第三个桩付出的路径成本
2. 重复路径惩罚太弱
   - 无法有效逼迫机器人离开当前局部热点
3. 局部清扫收益持续存在
   - 即使在狭窄区域绕圈，也可能继续拿到小额清扫收益

所以 `ho16` 的方向应当是：

- **适度提高“去到新桩”的吸引力**
- **适度提高“长期在旧路打转”的代价**
- 但不能强到破坏现有高分稳定性

---

## 4. ho16 方案总览

`ho16` 由三部分组成：

### 4.1 继承 go16-1

保留 `go16-1` 的 charge 安全边界：

1. starvation 判定前移
2. residual alpha 的危急区硬接管前移
3. 不改 planner 状态机

这是当前防止再次出现卡死和 charge 暴毙的基础。

---

### 4.2 吸收 go16-2 的低风险优化项

只吸收 `go16-2` 中最低风险、最不影响行为语义的 Tier 1 项：

```python
PLANNER_PRIOR_TEMPERATURE: 0.58 -> 0.54
BC_COEF_MIN:              0.32 -> 0.28
```

说明：

- 不直接照搬 go16-2 的更激进版本
- 先采取中间值
- 目标是让学习策略在不脱离 planner 的前提下，保留适度自主探索能力

理由：

- 当前问题并不是 planner 完全失效
- 而是策略在局部热点附近缺少跳出动力
- 所以只做小幅松绑，不做大幅解耦

---

### 4.3 新增 ho16 的 reward 微调

这是本轮的核心。

---

## 5. ho16 的 reward 微调设计

### 5.1 适度增大首次到达充电桩奖励

当前：

```python
base = 0.12
effective = 0.12 * max(0.55, 1.0 - 0.45 * cleaning_progress)
```

`ho16` 建议改为：

```python
base = 0.18
effective = 0.18 * max(0.60, 1.0 - 0.35 * cleaning_progress)
```

含义：

1. 基础奖励从 `0.12` 提升到 `0.18`
   - 提升 50%
2. 衰减变缓
   - 从 `1 - 0.45 * progress`
   - 改为 `1 - 0.35 * progress`
3. floor 从 `0.55` 提到 `0.60`

效果预期：

- 第一个新桩的吸引力更明显
- 第二、第三个桩在中后期仍然有足够的“到达价值”
- 更愿意为到达新桩多走一小段路

为什么不是直接提到 `0.25` 或更高：

- 当前局部最优虽然明显，但整体策略已较稳定
- 到桩奖励过高会反过来诱导“为了桩而桩”
- `0.18` 属于比较稳妥的中幅提升

---

### 5.2 新增“非重复路径奖励”而不只依赖惩罚

当前只有 `revisit_penalty`，缺少正向鼓励。

`ho16` 建议新增一个轻量正向项：

```python
fresh_path_reward =
    0.012 * indicator(self.cur_revisit_count == 0)
  + 0.006 * indicator(self.cur_revisit_count == 1)
```

再乘一个小的探索系数：

```python
fresh_path_reward *= max(0.4, 1.0 - 0.5 * cleaning_progress)
```

含义：

1. 第一次走到一个新位置，奖励更高
2. 第二次走到该位置，仍给很小正反馈
3. 从第三次开始不再给奖励
4. 后期该项自然衰减，不抢主任务

这样设计的原因：

- 只靠“重复惩罚”通常是被动的
- 当前问题更需要一个“主动离开旧路、去新路”的正向信号
- 但这个正向信号必须比清扫主收益小很多

`0.012 / 0.006` 的量级是刻意保守的：

- 小于 `approach_reward`
- 远小于清掉一格污渍的 `0.22`
- 但连续作用时，足以把短距离选路从“原地绕圈”推向“走新格”

---

### 5.3 同时增强重复路径惩罚，但只小幅增强

当前：

```python
revisit_penalty = -0.0025 * min(3, self.cur_revisit_count) * (0.35 + cleaning_progress)
```

`ho16` 建议改为：

```python
revisit_penalty = -0.0040 * min(4, self.cur_revisit_count) * (0.40 + cleaning_progress)
```

变化点：

1. 系数：`0.0025 -> 0.0040`
2. 截断：`min(3, ...) -> min(4, ...)`
3. 底数：`0.35 -> 0.40`

设计理由：

- 让“已经明显在重复路径里打转”的成本变得更快可见
- 但仍然保持这个惩罚远小于主任务 reward
- 不把策略逼到为了躲惩罚而乱跑

这部分要和 `fresh_path_reward` 配合看：

- `fresh_path_reward` 负责把策略往新路推
- `revisit_penalty` 负责把策略从旧路拉走

两者联合，才更适合解决“近桩封闭区域反复打转”的问题

is_starving: battery <= nearest_charger_dist + 20

if battery <= charger_distance + 14:

### 6.2 吸收 go16-2 的低风险优化项

```python
PLANNER_PRIOR_TEMPERATURE: 0.58 -> 0.54
BC_COEF_MIN:              0.32 -> 0.28
```

---

### 6.3 ho16 的 reward 微调项

```python
# 首次到达新充电桩奖励
base_arrival_reward = 0.18
charger_arrival_reward = 0.18 * max(0.60, 1.0 - 0.35 * cleaning_progress)

# 非重复路径奖励
fresh_path_reward =
    0.012 if cur_revisit_count == 0 else
    0.006 if cur_revisit_count == 1 else
    0.0
fresh_path_reward *= max(0.4, 1.0 - 0.5 * cleaning_progress)

# 重复路径惩罚
revisit_penalty = -0.0040 * min(4, cur_revisit_count) * (0.40 + cleaning_progress)
```

## 7. 预期效果

如果 `ho16` 有效，预计会看到以下改善：

1. 地图 4 这一类“近桩 + 封闭窄区”场景下
   - 围绕第一个桩反复打转的现象减少
2. 第二、第三个充电桩到达率提升
3. `charger_arrivals=1` 的局占比下降
4. `arrival_steps=[x,-1,-1]` 的局减少
5. 多数高分局仍然保持，不明显掉分

更具体地说，真正说明 `ho16` 生效的标志是：

1. `charger_arrived_count` 平均值上升
2. 第二个桩首次到达步数提前
3. 第三个桩首次到达比例提升
4. 低分但未死的“局部打转局”减少
5. charge 暴毙没有因为新探索倾向而反弹

---

## 8. 风险与控制

`ho16` 的主要风险有三个：

### 风险 1：到桩奖励过强，导致“为了找桩而放弃清扫”

控制方式：

- 不把到桩奖励提得过高，只升到 `0.18`
- 仍保留进度衰减

### 风险 2：反重复路径过强，导致策略变得躁动

控制方式：

- 同时给正向的新路奖励与适度的重复惩罚
- 不走纯惩罚路线
- 惩罚仍保持在小量级

### 风险 3：更愿意探索后，charge 风险反弹

控制方式：

- 保留 `go16-1` 的 starvation 与 alpha 强接管逻辑
- 不降低 charge 安全边界

---

## 9. ho16 的实施顺序

建议实施顺序如下：

1. 先保留 go16-1 安全边界不动
2. 吸收 go16-2 的低风险 Tier 1 项
3. 再上 ho16 的 reward 微调

不建议一开始就同时引入 go16-2 的全部 Tier 2 / Tier 3 项。

原因：

- 当前最直接的问题是“探索不足 + 路径重复”
- 不是优化器本身先要大动

---

## 10. ho16 结论

`ho16` 的一句话总结：

- **在保留 go16-1 安全兜底的前提下，适度提高“去到新充电桩”的收益，同时明显但不过激地提高“长期走旧路”的代价。**

它不是激进重构，而是一版更贴近当前问题本质的中等强度方案：

1. `go16-1` 负责防暴毙、防卡死
2. `go16-2` 负责做少量低风险优化
3. `ho16` 自己负责修正“近桩吸附、远桩不探索”的 reward 结构

如果这轮方向正确，预期最先改善的将不是 learner loss 曲线，而是：

- **第二、第三个充电桩的到达率与到达时机**
