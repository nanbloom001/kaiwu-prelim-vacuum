# go08

目标：在当前单一目标配置：

- `robot_count = 4`
- `charger_count = 3`
- `max_step = 1000`
- `battery_max = 150`

下，抑制策略继续向“过度保守”漂移，重新把训练重点从“只求不死”拉回到“安全前提下的高效清扫”。

## 1. 问题背景

从当前目标桶训练表现看，主要问题不是：

- 完全不会回桩
- 完全不会探索

而是：

- 失败仍集中在 `mode=charge`
- 成功局容易越来越保守
- 分数和有效步数在中后期训练中会出现回落

这更像是：

- 策略逐渐被推向“保命局部最优”

## 2. 本轮实际落地

### 2.1 修改文件

- `code/agent_ppo/feature/preprocessor.py`
- `agent_ppo/feature/preprocessor.py`
- `code/agent_ppo/algorithm/algorithm.py`
- `agent_ppo/algorithm/algorithm.py`

### 2.2 reward 微调方向

本轮对 reward 的核心调整是：

1. **提高中后段持续清扫奖励**

```python
late_game_efficiency_reward:
0.05 + 0.03 * target_profile_boost
-> 0.07 + 0.04 * target_profile_boost
```

2. **新增中后段探索推进奖励**

```python
late_progress_reward = 0.02 * late_game_factor * ...
```

作用：

- 避免后半段完全转成保命巡航
- 鼓励在安全前提下继续推进地图覆盖

3. **适度抑制过早充电**

对明显早充区间：

```python
prev_battery_ratio <= 0.60
```

加重惩罚。

4. **小幅缓和过强保守压力**

通过：

```python
safety_pressure = resource_pressure - 0.16 * target_profile_boost
```

让目标配置不至于被过度推向“早回桩”。

### 2.3 planner 小回调

本轮只对目标配置做了很小的 planner 回调：

- `effective_return_margin` 减 `2.0`
- `effective_low_battery_ratio` 减 `0.015`

作用：

- 避免部分本可继续安全清扫的局过早切入 `charge`
- 但仍保留 `charge` 阶段的安全边界

## 3. 当前主策略说明

当前主策略可以概括为：

- **planner-guided residual PPO**
- 先由 planner 提供安全动作先验
- policy 在安全空间内做 residual 微调
- reward 重点同时约束：
  - 清扫效率
  - 探索推进
  - 充电时机
  - 低电风险

在当前 `go08` 后，这个主策略相比之前的变化是：

- 不再继续单纯强化“保命”
- 而是开始更明确地鼓励：
  - 中后段仍持续有效清扫
  - 避免过早充电导致效率损失

## 4. 预期效果

go08 预期主要改善：

- 目标配置桶 `avg_score`
- 目标配置桶 `avg finished_steps`
- 减少 `mode=charge` 下的非必要塌局

## 5. 当前边界

这轮没有做：

- reward 的大规模重构
- planner 的大幅度参数改写
- PPO 主参数调整

所以 go08 的定位是：

- **去过保守化微调**

而不是重新定义策略主框架。
