# go06

目标：优先围绕指定验收配置做最优化训练，同时保留少量邻近配置样本，避免模型完全失去泛化能力。

目标配置：

- `robot_count = 4`
- `charger_count = 3`
- `max_step = 1000`
- `battery_max = 150`

## 1. 为什么需要 go06

当前 `go04/go05` 已经把训练扩到了多配置泛化，但如果你现在最关心的是：

- 优先把某一组具体验收配置打好

那么训练分布就不应该继续均匀覆盖所有组合，而应该：

- 以目标配置为主
- 以少量邻近配置为辅

这样做的目的不是放弃泛化，而是：

- 把有限训练预算优先投注到最重要的目标桶上

## 2. 训练分布策略

go06 采用“加权代表性轮换”：

### 2.1 主桶

目标配置重复出现：

```python
{"robot_count": 4, "charger_count": 3, "max_step": 1000, "battery_max": 150}
```

当前实现为：

- 每个训练轮换周期中重复 `6` 次

### 2.2 邻近桶

保留少量与目标配置相近的扰动组合：

- `battery_max = 200`
- `charger_count = 2`
- `charger_count = 4`
- `robot_count = 3`
- `max_step = 2000`
- `battery_max = 250`

目的是：

- 不让模型完全只记住单一配置
- 保留对相邻配置的一定适配能力

## 3. 本轮实际落地

### 3.1 修改文件

- `code/agent_ppo/conf/train_env_conf.toml`
- `agent_ppo/conf/train_env_conf.toml`
- `code/agent_ppo/workflow/train_workflow.py`
- `agent_ppo/workflow/train_workflow.py`

### 3.2 配置默认值调整

将训练配置默认值调整到目标配置：

```toml
robot_count = 4
charger_count = 3
max_step = 1000
battery_max = 150
```

### 3.3 Episode 调度策略

新增：

- `self.primary_target_config`

并将训练轮换改为：

- 目标配置重复 `6` 次
- 再穿插 `6` 个邻近配置

即当前每个周期内：

- `target : neighbor = 6 : 6`

但由于主桶在周期开始连续出现，训练前段会更快聚焦目标配置。

### 3.4 日志补充

在日志中新增：

- `profile=target`
- `profile=neighbor`

方便后续直接从日志区分：

- 当前局是否属于目标桶
- 当前局是否属于邻近扰动桶

### 3.5 训练监控补充

本轮进一步在 monitor 指标中新增：

- `target_profile`
- `neighbor_profile`
- `target_score`
- `neighbor_score`
- `target_steps`
- `neighbor_steps`

作用：

- 让训练面板里可以直接区分目标桶与邻近桶的表现
- 方便判断“目标配置是否真的在优先抬升”

## 4. 当前边界

这轮没有继续调整：

- reward 结构
- planner 公式
- 网络结构

也就是说，go06 的本质是：

- **训练分布重加权**

而不是新的策略机制。

## 5. 预期效果

预期短期内最容易改善的是：

- 目标配置桶的 success rate
- 目标配置桶的 avg score
- 目标配置桶的 min_steps / min_score

同时希望：

- 邻近桶不要明显崩坏

## 6. 风险

主要风险是：

- 过度偏向目标配置后，泛化能力变差

所以 go06 仍然保留了少量邻近桶，而不是纯单配置训练。
