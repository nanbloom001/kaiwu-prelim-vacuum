# go15

目标：在实现 `go14` 的动态回充保护的基础上，进一步处理强化学习(RL)模型在关键阶段“固执己见”导致的暴毙，切断因为贪婪得分造成的过长滞留，引入“奖励整形解耦 (Reward Shaping Decoupling)”和“安全模式强接管 (Hard-coded Fallback)”。

---

## 1. 问题回顾与分析

通过之前对 `testlog` 和 `train log` 的分析可得：
1. **奖励毒性 (Reward Toxicity)**：当电量处于危险线（如剩余不足以走到充电桩+20步安全冗余）时，策略网络(Actor)依然可能被局部的 `cleaning_reward` 或 `explore_reward` 吸引。因为短期扫地的正反馈立刻到达，虽然最终会因为没电暴毙，但对于折扣因子带来的远期死亡惩罚，网络往往由于“短视”而无法有效抑制贪婪行为。
2. **残差策略失效 (Residual Policy Failure)**：在架构设计中，最终的动作概率是 `(1 - alpha) * planner_prob + alpha * policy_prob`。在回充紧急时刻，哪怕 Planner（规则）指明了必须沿最短路径回充，只要 `alpha` 仍具备一定比例赋予 RL 模型，模型偶尔一次“探索性”的反方向动作就足以断送整局（特别是那些恰好需要卡着电量回充的边缘局）。

---

## 2. 优化方案设计与实现

为了解决上述问题，`go15` 在特征后处理（Reward 分配）和动作概率融合（Alpha 加权）两个关键节点上进行了修改：

### 2.1 奖惩信号的绝对物理隔离 (Reward Decoupling)
修改位置：`agent_ppo/feature/preprocessor.py` 中的 `reward_process()`

- **机制**：计算 `nearest_charger_dist = self._nearest_charger_distance()`，只在“已知充电桩、当前不在桩上、且 `battery <= nearest_charger_dist + 18.0`”时视为 `is_starving`。
- **斩断诱惑**：如果处于 `is_starving` 状态，将该步产生的 `cleaning_reward`、`explore_reward` 和 `approach_reward` 归零。
- **生存倒逼**：保留充电相关 reward 与到桩 reward，不破坏原有 charge 语义；同时仅把常规 `step_penalty` 放大到 `2.5x`，避免惩罚过猛导致 value 抖动。
- **防卡死约束**：
  - 若当前还没观测到充电桩，不触发该逻辑，避免“信息不足时被错误压制”。
  - 若当前已经站在充电桩区域内，不触发该逻辑，避免充电帧 reward 被误伤。

### 2.2 极端危机下的强制安全接管 (Hard-coded Fallback)
修改位置：`agent_ppo/agent.py` 中的 `_effective_residual_alpha()`

- **机制**：只在以下条件同时满足时才拦截：
  - `policy_info.should_charge == True`
  - `policy_info.target_mode == "charge"`
  - `charger_distance` 有效
- **分级接管**：
  - 若 `battery <= charger_distance + 12.0`，直接把 `residual_alpha` 压到 `0.0`
  - 若 `battery <= charger_distance + 18.0`，只把 `residual_alpha` 压到最多 `0.002`
  - 其他阶段仍维持原来的 `charge cap = 0.010`
- **效果**：只在真正接近生死线时把控制权完全交给 planner，避免把整个 `charge` 模式都锁死。
- **防卡死约束**：
  - 不新增任何 planner 状态机变量
  - 不引入黑名单、换桩、循环计数之类的历史状态
  - 仅做当前帧的纯函数式拦截，避免再次出现“状态残留导致首局卡死”

---

## 3. 预期成效

在经过本轮 `go15` 设置底层强硬拦截与奖励剥夺后，预期可以达到：
1. **断绝贪小命长的暴毙模式**：策略网络将不会在没电的时刻强行吃脏污地面。
2. **杜绝“临门一脚”因为随机性卡死**：强力保证在充电桩门前/极限回充路径上的步态零失误，预计单桩跑图的电量存活率将大幅上升，通过率得到兜底保证。

## 4. 本轮实际落地

本轮已按“保守 go15”落地以下文件：

- `agent_ppo/feature/preprocessor.py`
- `agent_ppo/agent.py`
- `code/agent_ppo/feature/preprocessor.py`
- `code/agent_ppo/agent.py`

本轮刻意**不修改 planner 状态机**，原因是之前已经出现过与充电逻辑相关的卡死风险。本次只改 reward 与 residual alpha，两处都是无状态、单帧可判定逻辑，便于回归和排障。
