# go24-4: 提升得分率与完成度的策略优化方案

## 1. 问题诊断 - 为什么需要go24-4

### 1.1 当前的关键问题：完成度低、得分率不稳定

基于 go24-1 测试数据分析（20局完整日志）：

| 指标 | 值 | 问题 |
|------|-----|------|
| 完成率(finished_steps=1000) | 17/20 = 85% | 15%的局提前结束 |
| 提前结束的局数 | 3局 | Ep2(666步), Ep6(499步)都是**低分** |
| 提前结束时的平均分数 | **545** | vs 完整局的**859** 低37% |
| 完整局的平均分数 | 859 | 正常表现 |
| 完整局的最低分 | 733 | 仍可接受 |
| 完整局的最高分 | 928 | 健康上限 |

**关键发现**：
- 完成度不足直接导致得分崩盘（-37%）
- 提前结束的局全是**charge相关失败**（电量耗尽）
- 完成1000步的局，即使分数低也能保持合理水平

### 1.2 go24-1只解决了性能问题，未解决策略问题

- ✅ go24-1: 解决内存累积导致的速度下降
- ❌ go24-1: 不能解决策略导致的**早死**问题
- ❌ go24-1: 不能解决**过度依赖充电**导致的失败

**结论**: 需要go24-4专注于策略和奖励优化，目标是：
- **保证每局到达1000步**
- **提升低分局的得分**
- **稳定充电策略**

## 2. 当前go23版本的策略问题分析

### 2.1 go23的arrival gating过于严格

**现象**: 3局提前结束都在charge阶段，意味着到达charger后的策略仍然有严重问题

**原因分析**：

go23实现的 `_resolve_pending_arrivals()` 有两个问题：

1. **确认窗口太长** (80-160步)
   - 过程中可能反复检查"是否应该取消"
   - 导致arrival credit时松时严，策略学不到稳定的到达-充电链接

2. **completion条件过高**
   ```python
   # 必须同时满足收益+生存
   # 但"生存"的定义过于保守
   final_value = (
       coverage_gain >= int(params["final_coverage"])  # 需要6+个格子
       or observed_gain >= int(params["final_observed"])  # 需要40+个格子
       or (left_region and ...)  # 需要离开区域
   )
   ```
   
   对于**小房间**或**高密度charger**，这些条件根本无法满足

### 2.2 go23的arrival reward基础太弱

```python
def _arrival_base_reward(self, arrival_order: int) -> float:
    if arrival_order == 0:
        return 0.10  # 第1个桩只有0.10
    if arrival_order == 1:
        return 0.05  # 第2个桩只有0.05
    return 0.02    # 第3+个桩只有0.02
```

这导致：
- 策略不够激励"安全到达充电桩"
- 优先选择"继续清扫"而不是"主动补电"
- 最终在第600-700步因电量不足失败

### 2.3 go23的充电循环检测反而制造了早死

```python
if charge_active and charge_loop_frames >= 6:
    # 认为进入循环，取消arrival
    penalty = -(paid + 0.04)
    reward += penalty
```

**问题**：
- charge_loop_frames统计的是"同一帧多次进入charge"
- 但实际充电过程**必然会反复进出charger区域**（边充边清）
- 导致正常充电被误判为"loop"并惩罚
- 策略不敢充电，反而更容易失败

## 3. 基于go22的核心思路扩展 - go24-4方案

### 核心理念

**从"严格的arrival gating"改为"激励-保障的平衡"**：
- 充分激励"安全到达充电桩"这个关键决策
- 但同时防止"无限循环充电"
- 目标是让策略学会"适时补电、及时脱困"

---

## 3.1 策略一：重新设计arrival reward基础值

### 问题
go23的基础值(0.10/0.05/0.02)太弱，且go22后的multiple gate导致最终获得的奖励<0.01

### 方案

**新的基础值层次（与环境反馈相匹配）**：

```python
def _arrival_base_reward(self, arrival_order: int) -> float:
    # 第1个新桩：0.18 (原始奖励更强)
    # - 这是全局最重要的决策点（首次找到充电资源）
    # - 需要明确的正向信号
    if arrival_order == 0:
        return 0.18
    
    # 第2个新桩：0.12 (第一个的2/3)
    # - 备选桩，但仍有价值
    if arrival_order == 1:
        return 0.12
    
    # 第3+个新桩：0.06 (备选备选)
    # - 保留弱激励，但不过度鼓励
    return 0.06
```

**理由**：
- go22建议0.10~0.14，我们用0.18是因为有多层gate衰减
- 最终实际获得 = 基础值 × candidate_scale × early_discount × survival_gate × ...
- 经过多层衰减后，0.18的基础能保留0.01-0.05的实际奖励

---

## 3.2 策略二：简化并重新定义charge_loop检测

### 问题
```python
charge_loop_frames >= 6  # 这个阈值太低
```

正常充电过程：
1. 进入charger区域，开启charge_active
2. 清理几步，获得新观测
3. 离开区域取得高价值目标
4. 回到charger继续补电
5. 重复2-4

这个过程中`charge_loop_frames`必然 >= 6，但这是**正常行为**，不是bug

### 方案

**重定义charge_loop为真正的"无限循环"**：

```python
def _is_charge_loop_failure(self, arrival_info: dict) -> bool:
    """判断是否进入了真正的无限循环（无法脱困）"""
    
    # 条件1：在charge_active期间，连续N步没有任何进展
    steps_in_charge = self.step_no - arrival_info.get("arrival_step", 0)
    
    # 条件2：充电期间无新观测、无清扫、无移动
    if (self.new_observed_cells == 0 and 
        self.cleaned_this_step == 0 and
        steps_in_charge > 80):  # 80步无进展 = 真正的loop
        return True
    
    # 条件3：反复进出charger区域>20次（真正的困境）
    if arrival_info.get("revisit_count", 0) > 20:
        return True
    
    return False
```

**优势**：
- 只在真正陷入困境时才取消arrival
- 允许正常的多次充电行为
- 减少误惩罚

## 3.3 策略三：增强NPC躲避在charge阶段的作用

### 问题
当前NPC信息只在arrival gating中做"风险削弱"，但：
- 提前结束的3局都是**因为策略卡在charger附近无法脱困**
- 这说明**charger选址往往接近NPC**（游戏设计的风险区）

### 方案

**新增"charge期间主动换桩"逻辑**：

```python
def should_switch_charger(self) -> bool:
    """
    判断当前桩是否太危险，是否应该换桩
    """
    
    if not self.charge_active:
        return False
    
    # 条件1：当前桩附近NPC太近且无安全出口
    nearest_npc = self._nearest_npc_distance()
    if nearest_npc < 3:  # NPC距离<3格
        # 检查是否有安全的非charge动作
        safe_non_charge_actions = sum(
            1 for i, legal in enumerate(self.legal_action)
            if legal and self._action_is_escape(i)
        )
        if safe_non_charge_actions < 2:  # 只有<2个安全出口
            return True  # 应该主动放弃当前桩，换其他的
    
    # 条件2：连续多步无法安全充电（不断被挤出）
    if self.charge_active_frames > 50 and self.battery_gain < 0.05 * 50:
        # 50步内电量增长<50，说明充电效率太低
        return True
    
    return False
```

**对奖励的影响**：
- 不取消已有的arrival reward
- 但在planner中标记"这个桩不安全，优先考虑其他桩"
- 策略学会"即使已到达，不安全的桩也应该放弃"

## 3.4 策略四：优化终局reward，防止早死

### 问题
当前终局奖励只计算"胜/负"，但对**提前结束(finished_steps < 1000)**没有专门处理

```python
if truncated:  # WIN
    final_reward = 2.5 * cleaning_ratio + 1.5 * score_ratio + quality_bonus
else:  # FAIL
    final_reward = -2.5 - 0.5 * max(0.0, 0.9 - cleaning_ratio) + quality_bonus
```

这无法区分"1000步失败"和"666步失败"（都是-2.5起步）

### 方案

**新增"完成度奖励"**：

```python
def calculate_completion_bonus(self, finished_steps: int, max_steps: int = 1000) -> float:
    """
    奖励完成度
    - 完全完成(1000步)：+0.0 (不额外奖励，这是基准)
    - 90%完成(900步)：+0.1
    - 80%完成(800步)：+0.2
    - <50%(<500步)：+0.5 (严重惩罚)
    """
    completion_ratio = finished_steps / max_steps
    
    if completion_ratio >= 0.95:
        return 0.0  # 基准
    elif completion_ratio >= 0.85:
        return 0.05
    elif completion_ratio >= 0.70:
        return 0.10
    elif completion_ratio >= 0.50:
        return 0.20
    else:
        return 0.50  # 严重早死奖励
```

**使用方式**：
```python
final_reward += self.calculate_completion_bonus(finished_steps)

# 这样做的效果：
# - 完整局(1000步)失败：-2.5 + quality_bonus
# - 早死局(500步)失败：-2.5 + quality_bonus + 0.50 = -2.0 + quality_bonus
# 通过正奖励部分弥补失败惩罚，激励策略至少完成基础探索
```

## 3.5 策略五：增强battery状态意识

### 问题
当前特征中有battery_ratio，但缺少"电量趋势"信息

```python
battery_ratio = _norm(self.battery, self.battery_max)  # 当前电量
```

但策略需要知道：
- 电量在**下降**还是**上升**？
- 下降速度快吗？
- 还能撑多久？

### 方案

**新增"battery trend"特征**：

```python
def _get_battery_trend(self) -> float:
    """
    计算电量趋势
    返回 [-1, 1]：
    - -1: 快速下降，即将没电
    - 0: 稳定
    - +1: 快速上升，正在充电
    """
    if self.step_no < 10:
        return 0.0  # 初期无趋势
    
    battery_change = self.battery - self.prev_battery
    
    # 根据变化速度计算趋势
    trend = np.clip(battery_change / 5.0, -1.0, 1.0)  # 5是单步最大变化量
    
    return float(trend)

# 在_get_global_state_feature()中添加
# battery_trend = self._get_battery_trend()  # 新增1个维度
```

**作用**：
- 帮助策略及时识别"即将没电"的危险
- 促进主动充电而不是被动等死
- 85D → 85D + 1 = 86D特征

## 3.6 策略六：修复arrival reward的时间阶段性

### 问题
go23的arrival reward在step-level和terminal-level都给，导致信号混乱

### 方案

**明确分工**：

```python
# Step-level (每帧)：只给"首次到达"的弱激励
# - 第1个桩：0.18 * candidate_scale × early_discount × ...
# - 目标：激励策略主动前往未探索的区域

# Terminal-level (局结束)：给"生存价值"激励
# - 到达2+个桩且活到1000步：+0.2
# - 到达3+个桩且活到1000步：+0.3
# - 目标：防止早死，鼓励探索后也要活下来

def calculate_arrival_quality_bonus(self, 
                                     charger_arrivals: int,
                                     finished_steps: int,
                                     max_steps: int = 1000) -> float:
    """
    终局arrival质量奖励
    """
    bonus = 0.0
    
    # 必须完成足够步数才有奖励
    if finished_steps < 900:
        return bonus
    
    if charger_arrivals >= 3:
        bonus += 0.30
    elif charger_arrivals >= 2:
        bonus += 0.15
    elif charger_arrivals >= 1:
        bonus += 0.05
    
    return bonus
```

**优势**：
- Step-level激励主动性（0.18基础）
- Terminal-level激励可持续性（+0.05-0.30）
- 避免"只到不活"的轨迹
