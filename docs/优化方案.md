## 2. 从日志看到的主要问题

### 2.1 清扫收益提升了，但成功率几乎没起来

`aisrv` 日志后段常见如下模式：
- `steps=200`
- `total_reward` 提升到 `180~200+`
- `dirt_cleaned` 提升到 `180~200`
- 结果仍然是 `FAIL`

这说明当前策略已经能稳定“刷局部收益”，但没有跨过任务完成阈值。也就是说，策略更像是局部贪心清扫，而不是全局规划型清扫。

### 2.2 充电行为基本缺失

环境日志显示：
- `charge_count_positive = 4 / 175`
- 绝大多数 episode 的 `remaining_charge = 0`
- 大量对局在 `200` 步附近结束

这组信号基本可以判定：低电量去充电这件事没有进入稳定策略。当前 agent 主要靠“有限电量内尽量多扫一点”拿分，而不是“清扫 -> 回充 -> 再清扫”的闭环。

### 2.3 存在少量异常局，说明策略稳定性不足

日志里出现了一些非常差的尾部 episode：

这类样本占比不高，但说明策略还有明显不稳定区间，可能与以下因素有关：
- 局部卡住后没有脱困机制
- 某些地图上的泛化较差
- 价值函数虽然下降了，但策略分布仍在局部模式之间抖动

- 即使偶尔能赢，也不是可复制的稳定策略。

## 3. 根因判断

结合日志，我认为当前最可能的根因有四个。

### 3.1 奖励函数过度偏向即时清扫

现象：
- reward 持续上涨，但 win 基本不涨
- 高 reward 仍经常 `FAIL`

判断：
- 即时清扫奖励占比过高
- 终局成功、续航管理、回充成功、覆盖率提升没有被足够强地奖励

### 3.2 状态表达缺少“长程任务信息”

现象：
- 清扫量上来后，仍然无法形成“阶段切换”
- 充电行为几乎不出现

判断：
- 观测里可能缺少足够强的“低电量导航信号”
- 也缺少“已访问/未访问区域”这类覆盖率相关信息
- agent 只能看到局部脏污收益，学不到全局任务节奏

### 3.3 卡死/重复游走没有被显式压制

现象：
- 出现极差局和短局
- 少数对局步数拉长到 `400/533/1000`，但多数仍回落到 `200`

判断：
- 没有针对“重复位置访问”“局部振荡”“原地打转”的惩罚
- 也没有为“脱困成功”提供正反馈

### 3.4 评估体系还不够贴近优化目标

现象：
- 目前日志里可直接看到 reward / score / cleaned / steps
- 但看不到覆盖率、回充成功率、重复访问率、卡死率

判断：
- 训练已经走到“需要更细指标驱动”的阶段
- 只看 reward 会把优化方向带偏

## 4. 优化优先级

建议按 `P0 -> P1 -> P2` 推进，不要同时大改网络、奖励、特征。

### P0：先补监控，不然下一轮很难判断改动是否有效

下一轮训练必须新增以下日志指标：
- `coverage_rate`: 已访问可清扫区域 / 可达可清扫区域
- `repeat_visit_ratio`: 最近 N 步重复访问比例
- `low_battery_trigger_cnt`
- `charge_attempt_cnt`
- `charge_success_cnt`
- `stuck_cnt`: 连续 N 步位移极小或反复回环
- `success_rate_by_map`
- `avg_cleaned_by_map`

目标：
- 把“为什么失败”从猜测变成可量化诊断。

### P1：优先修奖励，不先动大模型

当前最值得先做的是 reward shaping，而不是先上更复杂网络。

建议调整方向：
- 增加“终局成功奖励”，幅度要明显高于单步清扫累计收益。
- 增加“低电量后接近充电桩”的距离差分奖励。
- 增加“成功完成充电”的一次性奖励，同时限制重复刷充电。
- 增加“首次访问区域奖励”，引导覆盖率而不是局部往返。
- 增加“重复访问惩罚”与“卡死惩罚”。
- 对“剩余电量耗尽失败”增加更明确惩罚。

落地原则：
- 先只改奖励，保持模型与采样参数不变。
- 一次只改一组主因子，避免多变量耦合。

### P1.5：补充最关键的状态特征

如果当前特征里还没有，建议优先补这几类：
- 当前电量占比
- 到最近充电桩的相对方向和距离
- 最近若干步位置变化量
- 最近若干步动作直方图
- 最近访问热度或局部访问记忆
- 当前区域未清扫密度估计

理由：
- 这几类特征直接服务于“续航决策”和“覆盖率决策”。
- 它们比单纯扩大网络更可能带来确定性收益。

### P2：再做训练稳定性与泛化优化

当 reward 和特征修完之后，再做下面这些：
- 熵系数分段退火：前期高探索，后期收敛
- 课程学习：先简单地图/高容错，再切全地图
- 按地图均衡采样或至少保持严格轮转统计
- 检查 PPO clip、value loss 权重、学习率是否导致后期策略抖动

从当前日志看，这一层现在不是最紧急的，但它会决定后续上限。

## 5. 下一轮实验设计

建议直接跑一个四组对照，不要散点试错。

### 实验 A：奖励对齐终局

改动：
- 增大成功奖励
- 增大耗尽失败惩罚
- 保持其他逻辑不动

关注指标：
- 胜率是否从 `0.9%` 明显提升
- 是否出现 reward 略降但 success 提升的情况

### 实验 B：补充低电量导航奖励

在实验 A 基础上增加：
- 低电量阶段，接近充电桩给正奖励
- 远离充电桩给负奖励
- 成功充电奖励

关注指标：
- `charge_success_cnt`
- `steps=200` 的占比是否下降
- `steps>200` 的高质量局是否增加

### 实验 C：补覆盖率与重复访问约束

在实验 B 基础上增加：
- 首次访问奖励
- 重复访问惩罚
- 卡死惩罚

关注指标：
- `coverage_rate`
- `repeat_visit_ratio`
- 各地图平均 `clean_score`

### 实验 D：只补轻量记忆特征

在实验 C 基础上增加：
- 最近位置变化
- 最近动作统计
- 最近访问热度

关注指标：
- 极差局是否减少
- 地图间方差是否下降

## 6. 验收标准

建议下一轮不要只看总 reward，至少看下面五项：
- 胜率从 `0.9%` 提升到 `>= 5%`
- `charge_count>0` 的 episode 占比显著提升，目标先到 `>= 15%`
- `steps=200` 的占比下降
- 地图平均分最低组明显抬升，优先看 `map 1 / 5 / 9 / 10`
- 极差局比例下降，例如 `reward < 20` 或 `dirt_cleaned < 30` 的局数下降

如果只能设一个主验收目标，我建议先设：

`先把稳定回充学出来，再追求更高覆盖率。`

原因很简单：当前日志里最硬的短板不是“不会扫”，而是“扫了之后活不长”。

## 7. 结论

这批日志说明当前 PPO 基线已经脱离随机策略，具备了稳定清扫增益，但仍停留在“局部收益优化”阶段。下一轮最值得投入的方向不是盲目加大模型，而是：

- 让 reward 对齐终局目标
- 让特征显式表达电量与覆盖率
- 让监控指标能直接暴露回充、卡死和重复访问问题

建议执行顺序：
1. 先补指标日志
2. 再改 reward
3. 再补轻量状态特征
4. 最后才做超参和模型结构微调

按这个顺序推进，收益最稳，也最容易从日志中验证每一步是否真的有效。
