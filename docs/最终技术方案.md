# 最终技术方案：安全优先的充电桩锚点 + 全局记忆 + 条带清扫 + PPO 微调

## 1. 方案定位

本方案综合 `方案01`、`方案02`、`方案03` 的优点，形成一套更适合当前仓库的最终落地版本：

1. 吸收 `方案01` 的优点：保留 PPO 微调、特征工程、奖励 shaping 和训练细节。
2. 吸收 `方案02` 的优点：保留全局记忆地图、动态危险区、状态机、A* 路径规划和脱困策略。
3. 吸收 `方案03` 的优点：把安全硬约束、充电桩锚点、条带清扫、动作级回桩可行性检查作为主框架。

最终结论是：**高层由规则和规划保证安全与效率，低层由 PPO 只做局部动作微调，学习模块不能覆盖安全规则。**

---

## 2. 统一环境约束

以当前仓库配置为准，统一采用以下约束：

- 地图大小：`128 x 128`
- 局部视野：`21 x 21`
- 动作空间：`8` 方向移动
- 官方机器人数量：`4`
- 充电桩数量：`4`
- 最大步数：`1000`
- 满电电量：`200`

说明：

1. `方案01` 中的 `battery_max = 600`、`max_step = 2000` 与当前仓库不一致，不作为最终约束。
2. `方案02`、`方案03` 与当前配置更接近，其中电量和步数应统一到当前环境配置。
3. 技术方案必须围绕 `battery_max = 200` 和 `max_step = 1000` 设计，否则回桩策略和条带长度都会失真。

---

## 3. 设计原则

1. **安全优先于收益**：不撞官方机器人、不在返航路上没电，优先级高于任何清扫收益。
2. **充电桩是锚点，不是补救点**：开局就要找桩、记桩、算回桩代价，不能等低电才回想起来返航。
3. **全局记忆优先于局部贪心**：必须持续维护已知地图、污渍分布、访问热度和危险区，避免绕圈和重复覆盖。
4. **条带清扫优先于圆形扩散**：主清扫轨迹采用长直线往返 + 单格换道，减少无效转向。
5. **规则主导，PPO 微调**：高层模式切换、回桩、避碰、换桩由规则控制，PPO 只在可行动作集合内做精细选择。

## 5. 全局记忆与地图维护

整局维护以下状态：

```python
self.static_obstacle_map   # 静态墙体
self.free_map              # 已知可通行区域
self.dirt_map              # 已观测但未清扫污渍
self.cleaned_map           # 已清扫区域
self.visit_count_map       # 访问次数，抑制重复覆盖
self.charger_map           # 已发现充电桩坐标
self.anchor_region_map     # 每个格子归属哪个充电桩服务区
self.robot_tracks          # 官方机器人轨迹、速度、置信度
self.robot_danger_map      # 动态危险代价图
self.return_cost_cache     # 到各充电桩的最短路代价缓存
self.current_anchor        # 当前服务中的充电桩
self.current_stripe_plan   # 当前条带清扫计划
```

地图分为两层：

1. **静态层**：障碍、可通行区域、污渍、已清扫区域、充电桩。
2. **动态层**：官方机器人轨迹、危险走廊、短期不可通行区域。

静态层持续累计，动态层按帧衰减，避免把机器人旧位置永久当作障碍。

## 6. 安全层设计

### 6.1 开局即找最近可达充电桩

开局先解析初始视野中的充电桩，选择**路径代价最小**而不是欧氏距离最近的充电桩作为当前锚点：

```python
current_anchor = argmin_charger(path_cost(cur_pos, charger))
```

若初始视野没有桩，则进入**保守探索模式**，只在小半径内探索，直到发现首个充电桩。

### 6.2 动态安全电量

最终使用动态安全电量，而不是固定低电阈值：

```python
safe_energy = min_return_cost + detour_margin + unknown_margin + dock_buffer
```

建议参数：

- `detour_margin = 8`
- `unknown_margin = 6`
- `dock_buffer = 6`

含义：

1. `min_return_cost`：当前位置到任一已知充电桩的最短可达路径代价。
2. `detour_margin`：覆盖动态避碰和局部绕障冗余。
3. `unknown_margin`：覆盖未观测区域误差。
4. `dock_buffer`：保证到桩前不贴底电量。

### 6.3 动作级可行性检查

不仅要判断“现在该不该回去”，还要判断“走完下一步后还回不回得来”：

```python
def action_is_energy_feasible(next_pos, battery_after_move):
    return battery_after_move >= calc_safe_energy(next_pos)
```

规则：

1. 只要 `battery <= safe_energy`，立即切换返航模式。
2. 任何候选动作若导致下一步后不可安全回桩，直接屏蔽。
3. 条带清扫、直接捡污渍、换桩转场都必须经过该检查。

### 6.4 官方机器人动态避碰

官方机器人必须按动态障碍处理：

1. 对比连续多帧视野中的障碍变化，识别移动目标。
2. 维护 `3-5` 帧轨迹，估计速度方向。
3. 对未来 `3-5` 步构造危险走廊，而不是只在当前位置画一个圆。

```python
for t in range(0, 5):
    pred = track.pos + t * track.velocity
    inflate_danger(pred, radius=2 if t <= 2 else 1)
```

执行策略：

- 路径规划时把危险走廊作为高代价区或不可通行区。
- 若 `2-3` 步内预测会交汇，优先横向避让。
- 窄路返航时允许等待 `1-2` 步，不强行抢道。

## 7. 任务层设计

### 7.1 充电桩锚点服务区

采用 `方案03` 的锚点思想，但融合 `方案02` 的地图记忆：

1. 每个格子按“回到哪个充电桩代价最小”划归服务区。
2. 当前机器人优先处理 `current_anchor` 对应区域。
3. 只有当前区域收益明显下降，才考虑换桩。

```python
anchor_region_map[cell] = argmin_charger(path_cost(cell, charger))
```

这样比固定 `4x4` 分区更合理，因为它直接贴合回桩成本。

### 7.2 条带清扫主策略

条带清扫是最终主工作模式，核心规则是：

1. 优先长直线。
2. 每次只换 `1` 格道。
3. 每条条带都带返航可行性检查。
4. 条带被障碍或机器人打断后，优先局部重连，重连失败再跳下一条。

`99` 步不是固定值，只是上限示意。真实条带终点由以下条件决定：

```python
cost_to_endpoint + cost_back_to_any_charger + reserve <= battery
```

建议参数：

- `STRIPE_SHIFT = 1`
- `STRIPE_MAX_LEN = 99`
- `STRIPE_REJOIN_BUDGET = 5`
- `FULL_BATTERY_RATIO = 0.90`

### 7.3 直接清扫与子目标探索

在当前锚点区域内，条带清扫是主模式，但允许两个补充机制：

1. **Direct Dirt Pickup**：视野内有近距离高价值污渍，且不破坏返航约束时，允许顺手清掉。
2. **Frontier Exploration**：若当前条带区域信息不足或首个充电桩未发现，则在当前服务区内做保守前沿探索。

这里保留原最终方案中的**粗网格 frontier 思想**，但只把它作为锚点区域内部的子目标选择器，不再替代充电桩锚点主逻辑。

### 7.4 换桩策略

当满足以下任一条件时，可考虑换桩：

- 当前服务区覆盖率超过 `85%`
- 当前区域已知污渍密度明显下降
- 当前条带大部分已执行完，仅剩零碎角落

换桩时必须同时满足：

1. 当前接近充电桩或就在桩上。
2. 电量接近满电。
3. 到目标桩的转场路径可行。
4. 路径不穿过高风险机器人走廊。

可使用如下评分：

```python
score = 2.0 * uncleaned_ratio \
      + 1.2 * dirt_density \
      + 0.8 * frontier_score \
      - 0.03 * transfer_cost \
      - 0.8 * robot_risk
```

## 8. 模式优先级与状态机

最终模式优先级如下：

| 优先级 | 模式 | 触发条件 | 说明 |
|---|---|---|---|
| P0 | `EMERGENCY_EVADE` | 预测 `2-3` 步内与官方机器人冲突 | 先让路，避免碰撞 |
| P1 | `RETURN_TO_CHARGER` | `battery <= safe_energy` 或下一步不可回桩 | 立即返航 |
| P2 | `STUCK_RECOVERY` | 连续振荡、原地绕圈、条带重连失败 | 快速脱困 |
| P3 | `CHARGER_TRANSFER` | 当前服务区收益低且满足满电转场条件 | 切换锚点 |
| P4 | `STRIPE_CLEANING` | 当前区域仍值得扫且电量充足 | 主工作模式 |
| P5 | `DIRECT_DIRT_PICKUP` | 视野内有近距离高价值污渍 | 顺手补扫 |
| P6 | `SAFE_EXPLORATION` | 未发现足够桩或局部边界未知 | 小半径探索 |

补充规则：

1. 模式切换必须设置冷却时间，避免频繁抖动。
2. `EMERGENCY_EVADE` 和 `RETURN_TO_CHARGER` 属于硬切换，不受冷却限制。
3. `STRIPE_CLEANING` 与 `DIRECT_DIRT_PICKUP` 之间允许短切换，但要保留条带恢复能力。

## 9. 感知特征与学习输入

最终学习模块采用**多尺度局部视野 + 关键全局标量**的混合输入，兼顾 `方案01` 的显式特征和原最终方案的多尺度感知：

### 9.1 局部视觉输入

1. `L0 = 21x21`：完整局部视野，用于避障、识别机器人和近距离污渍。
2. `L1 = 11x11`：中尺度目标选择。
3. `L2 = 7x7`：局部姿态、边界与安全动作微调。

### 9.2 全局标量输入

建议至少包含以下特征：

- `step_norm`
- `battery_ratio`
- `cleaning_progress`
- `remaining_dirt_ratio`
- `pos_x_norm`
- `pos_z_norm`
- `nearest_dirt_dist`
- `ray_cast_n/e/s/w`
- `nearest_charger_path_len`
- `charger_buffer_gap`
- `charger_direction_encoding`
- `other_robot_min_dist`
- `other_robot_rel_speed`
- `stripe_heading_alignment`
- `revisit_penalty_local`

### 9.3 动作掩码

PPO 输出前必须依次施加三个掩码：

1. `legal_action_mask`
2. `energy_feasible_mask`
3. `robot_danger_action_mask`

这一步是最终方案的关键：**即便策略网络判断错误，也不能选出会撞机器人或走完就回不来的动作。**

## 10. 学习模块设计

### 10.1 学习职责

PPO 只负责以下问题：

1. 多个安全动作之间如何选更平滑、更少绕路的动作。
2. 条带执行中的细粒度绕障与回并线。
3. 近距离污渍拾取时的局部路径微调。

PPO 不负责：

1. 是否返航
2. 是否换桩
3. 是否进入危险走廊
4. 是否打破电量护栏

### 10.2 训练流程

推荐采用两阶段训练：

1. **行为克隆预训练**
   - 用规则策略采集约 `100k` 步轨迹
   - 动作头用交叉熵监督
   - 价值头用 MSE 拟合回报
   - 获得稳定 warm start

2. **PPO 微调**
   - clip = `0.2`
   - gamma = `0.99`
   - lambda = `0.95`
   - vf_coef = `0.5`
   - lr = `3e-4`
   - grad_clip = `0.5`
   - entropy：建议从 `0.01` 线性衰减到 `0.001`

### 10.3 网络结构

推荐网络：

```text
CNN(L0) + CNN(L1) + CNN(L2)
          ↓
     concat with scalar features
          ↓
       FC(融合层)
          ↓
   Actor Head(8) + Critic Head(1)
```

如果计算预算有限，可先退化为 `方案01` 的 `82D MLP` 基线，再逐步切到多尺度 CNN 版本。

## 11. 奖励设计

最终奖励采用“环境原始奖励为主，shaping 为辅”的思路，避免奖励主导策略跑偏。

### 11.1 基础奖励

- 新清扫污渍：正奖励
- 每步时间成本：小负奖励
- 长时间停滞、无效振荡：负奖励

### 11.2 辅助 shaping

```python
reward = env_reward \
       + step_penalty \
       + dirt_approach_bonus \
       + stripe_bonus \
       + safe_return_bonus \
       + revisit_penalty \
       + near_robot_penalty \
       + collision_penalty
```

建议项：

1. `dirt_approach_bonus`：鼓励靠近近处污渍。
2. `stripe_bonus`：鼓励连续直线条带。
3. `safe_return_bonus`：返航模式下保持安全 buffer 给小正奖励。
4. `revisit_penalty`：压制高频重复覆盖。
5. `near_robot_penalty` 和 `collision_penalty`：区分“贴近风险”和“真实碰撞”。

注意：

- 安全问题主要靠**硬约束**解决，不依赖奖励“学会安全”。
- 奖励只做微调，不能替代规则层。

## 12. 路径规划与脱困

### 12.1 路径规划

路径规划采用：

1. 主规划：`A*`
2. 失败回退：`BFS`
3. 代价项：基础距离 + 访问次数惩罚 + 机器人危险代价

```python
cost = move_cost + 0.1 * visit_count + danger_cost
```

### 12.2 脱困策略

保留 `方案02` 的脱困思路：

1. 若最近 `10` 步内有效位移过小，则判定为卡住。
2. 若出现左右来回、上下振荡，则判定为卡住。
3. 脱困时临时提高最近访问点的惩罚，强制跳出局部循环。

## 14. 评测指标

最终评测不能只看总分，建议同时监控：

1. `clean_score / cleaned_ratio`
2. 官方机器人碰撞次数
3. 返航成功率
4. 路上耗尽电量次数
5. 单位电量清扫效率 `clean_score / battery_consumed`
6. 重复覆盖率
7. 条带完成率
8. 换桩收益

硬目标：

- **碰撞次数尽量接近 0**
- **路上耗尽电量次数必须为 0**
- **返航成功率尽量接近 100%**

## 15. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 电量阈值过保守 | 清扫范围过小 | 微调 margin，但不取消动作级可行性检查 |
| 官方机器人短暂堵路 | 返航失败或误判无路 | 允许等待 1-2 步后重规划 |
| 条带被障碍切碎 | 计划执行率下降 | 分段条带 + 局部重连 + 跳下一条 |
| 学习模块偏离规则 | 稳定性下降 | PPO 只在 mask 后动作空间内工作 |
| 地图记忆噪声积累 | 路径规划变差 | 动态层衰减、周期性重采样 frontier |

## 16. 最终结论

综合三份方案后，最终技术路线应明确为：

1. **以充电桩为锚点组织任务，而不是全图盲扫。**
2. **以动态安全电量和动作级可行性检查保证任何时刻都能回桩。**
3. **以全局记忆 + 动态危险地图解决绕圈、撞机器人和重复覆盖问题。**
4. **以条带清扫作为主清扫模式，以 frontier 和直接拾取作为补充。**
5. **以 PPO 做局部动作微调，而不是让学习模块接管高层安全决策。**

这套方案比原 `最终技术方案.md` 更接近当前仓库环境，也比单独采用任一方案更稳、更可解释、更适合实际落地。
