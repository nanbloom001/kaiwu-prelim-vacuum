## 1. go11 最终方案

go11 采用的基线不是“当前仓库的混合版本”，而是：

- 以 `robot_vacuum-ppo-352` 为稳定高分基线
- 以 `go10` 的三层协同原则为约束
- 在不改 PPO 主框架的前提下，统一：
  - 特征
  - reward
  - planner
  - 配置

最终方案固定为四层：

### 1.1 特征层：恢复 84D 资源风险上下文

输入恢复为：

- `49D` 局部 `7x7` 视野
- `27D` 全局状态
- `8D` 合法动作 mask

其中 go10 要求必须保留的三类资源风险语义已经恢复到全局特征：

- `time_left_ratio`
- `observed_charger_ratio`
- `return_pressure`

同时保留：

- 当前电量
- 当前清扫进度
- 最近 dirt 接近趋势
- 局部未访问比例
- 探索进度
- 充电桩数量
- 电池容量

这一步的目标很明确：

- 不再让策略只看“当前状态”
- 让策略显式知道“还能不能继续扫”

### 1.2 reward 层：回到充电时机双侧约束

go11 固化的 reward 结构如下：

1. `cleaning_reward`
   - `+0.22 * cleaned_this_step`
2. `explore_reward`
   - `+0.003 * min(new_observed_cells, 12) * (1 - cleaning_progress)`
3. `approach_reward`
   - 接近最近 dirt 且本步未清扫时 `+0.01`
4. `charge_efficiency_reward`
   - 按充电前电量是否落在合理区间决定充电收益折算
5. `charge_event_reward`
   - `<18%` 晚充惩罚
   - `18%~45%` 合理充电奖励
   - `45%~60%` 早充轻惩罚
   - `>60%` 早充重惩罚
6. `low_battery_penalty`
   - 针对低于动态低电目标区的持续惩罚
7. `critical_battery_penalty`
   - 针对极低电区的强惩罚
8. `revisit_penalty`
   - `-0.0025 * min(3, revisit_count) * (0.35 + cleaning_progress)`
9. `step_penalty`
   - `-(0.001 + 0.002 * cleaning_progress)`

这里明确遵守 go10 的约束：

- 充电时机是区间最优，不是单阈值最优
- 不能只防晚充，也要防早充
- 清扫收益仍然保持主导

### 1.3 planner 层：回到动态安全边界

go11 固化的 planner 不是固定阈值，而是三组动态函数：

1. `dynamic_return_margin`
   - `BASE_RETURN_MARGIN`
   - `+ 6.0 * charger_scarcity`
   - `+ 4.0 * low_capacity_factor`
   - `+ 2.0` if `max_step >= 1500`
2. `dynamic_low_battery_ratio`
   - `LOW_BATTERY_RATIO`
   - `+ 0.05 * charger_scarcity`
   - `+ 0.03 * low_capacity_factor`
   - `+ 0.02` if `max_step >= 1500`
   - clip 到 `[0.28, 0.42]`
3. `dynamic_exit_return_ratio`
   - `EXIT_RETURN_RATIO`
   - `+ 0.02 * charger_scarcity`
   - `+ 0.01 * low_capacity_factor`
   - clip 到 `[0.93, 0.99]`

驱动因子只保留 go10 明确认可的三类：

- 充电桩稀缺程度
- 电池容量压力
- 回合长度压力

不再额外混入针对单一桶的特判松绑逻辑。

### 1.4 局部动作层：恢复近 NPC 脱险优先

go11 对动作打分固定两点：

1. 近 NPC 风险惩罚增强
   - `npc_penalty = max(0, 7.5 - npc_dist) * 1.05`
2. 极近距离脱险奖励恢复
   - 当 `current_npc_distance <= 3`
   - 若动作能拉开与 NPC 的距离
   - 追加 `+1.2 * npc_escape_progress`

这一步对应 go10 的核心要求：

- 局部避险优先级高于一小步短期清扫收益
- 极短局问题优先在动作排序层处理

## 3. go11 配置口径

后续训练与继续迭代时，go11 的配置口径固定如下。

### 3.1 必须固定不动的基线

- `84D` 输入结构
- PPO 主超参
- residual PPO + planner prior + BC regularization 框架
- 充电甜区 reward 结构
- 动态返航阈值函数
- 近 NPC 脱险优先

### 3.2 后续只允许微调的参数

后续若继续实验，优先只允许在以下位置小步微调：

1. planner 动态阈值斜率
   - `return_margin` 的加权系数
   - `low_battery_ratio` 的加权系数
   - `exit_return_ratio` 的加权系数
2. charge sweet zone 边界
   - `0.18`
   - `0.28`
   - `0.45`
   - `0.60`
3. 局部避险权重
   - `7.5 - npc_dist`
   - `1.05`
   - `npc_escape_progress` 的 `1.2`
4. residual / BC 微调
   - `RESIDUAL_SCORE_EMA_DECAY`
   - `BC_COEF_MIN`

### 3.3 暂时不建议改动

- 网络结构
- PPO clip / gamma / lambda / lr
- planner prior 混合框架
- 7x7 局部视野大小
- 将动态阈值改回固定阈值
- 把充电 reward 简化成单一奖励或单一惩罚

## 4. 验证重点

go11 之后建议至少同时观察：

- `avg_score`
- `win_rate`
- `avg_finished_steps`
- `charge` 模式死亡占比
- 极短局占比
- 充电成功率
- 充电前电量分布
- 低电触发次数
- 近 NPC 高风险步数

判断 go11 是否真的比当前版本更好，标准应是：

- 平均分不降
- 极短局下降
- `charge` 模式死亡下降
- 不是靠更保守换来的低波动

## 5. go11 结论

本轮 go11 的核心不是“新发明一套策略”，而是把当前代码重新统一到 go10 指定的正确基线：

- 特征恢复到 `84D`
- reward 恢复到充电时机双侧约束
- planner 恢复到动态安全边界
- 局部动作恢复近 NPC 脱险优先

后续迭代必须在这个基线上做单层、小步、可归因的微调，不再回到：

- 固定阈值
- 单点充电 reward
- 针对单桶特判
- 同时乱改 reward / planner / PPO 主超参
