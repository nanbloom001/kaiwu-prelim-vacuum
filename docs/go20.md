# go20

目标：基于当前最新训练日志，对 `go19` 之后的策略表现进行复盘，提出下一轮更稳妥的优化方向，使策略能够：

1. 保持高分局优势
2. 降低 `charge` 模式失败局占比
3. 减少“高质量失败局被错误鼓励”与“低质量存活局惩罚不足”这两种偏差

go20 的核心不是继续加大所有奖励，而是：

- **把终局质量加权做得更精确**
- **把“高质量失败局”和“低质量存活局”分开处理**

---

## 1. 当前日志结论

从最新 `2026-04-24 19:44` 之后这轮训练日志看，当前策略已经具备：

- learner 正常训练，且收敛在继续推进
- 大量回合可以稳定 `1000` 步
- 一部分局能够稳定达到 `900+`

但仍然存在以下三个明显问题。

### 1.1 charge 失败仍然频繁

当前日志中仍有多次：

- `mode=charge`
- 中途 `FAIL`

典型如：

- `ep1 steps=885 FAIL score=801 charger_arrivals=3 quality_bonus=0.450`
- `ep2 steps=761 FAIL score=658 charger_arrivals=2 quality_bonus=0.250`
- `ep5 steps=666 FAIL score=597 charger_arrivals=2 quality_bonus=0.250`
- `ep25 steps=650 FAIL score=550 charger_arrivals=2 quality_bonus=0.250`
- `ep27 steps=409 FAIL score=376 charger_arrivals=1 quality_bonus=-0.420`
- `ep29 steps=150 FAIL score=141 charger_arrivals=0 quality_bonus=0.000`

说明：

- 当前策略仍然没有稳定解决 charge 崩溃
- 终局质量 bonus 不能掩盖 survival 问题

---

### 1.2 go19 会错误奖励“高质量失败局”

这是当前最值得修正的问题。

例如：

- `ep1`
  - `FAIL`
  - `charger_arrivals=3`
  - `quality_bonus=+0.450`
- `ep2`
  - `FAIL`
  - `charger_arrivals=2`
  - `quality_bonus=+0.250`

这说明 go19 当前终局质量加权存在一个结构性问题：

- 只看轨迹结构是否像“高质量局”
- 但没有足够区分“最后有没有活下来”

结果就是：

- learner 可能会把某些“本来应该被明确判成失败”的局
- 仍然视作半个好局

这会直接削弱对 charge 失败的纠偏能力。

---

### 1.3 对低质量存活局的打击还不够强

虽然 go19 已经会给：

- 单桩低分局负 bonus

但从日志看，这类局仍然很多：

- `WIN`
- `1000` 步
- `charger_arrivals=1`
- 分数在 `800` 左右

例如：

- `ep4 WIN score=801 charger_arrivals=1 quality_bonus=-0.300`
- `ep6 WIN score=841 charger_arrivals=1 quality_bonus=-0.300`
- `ep24 WIN score=870 charger_arrivals=1 quality_bonus=-0.300`

说明：

- 现在已经在惩罚
- 但还不足以把“单桩满步局”彻底压下去

---

## 2. go20 核心判断

当前问题不是 reward 完全错，而是 **终局质量区分逻辑的优先级还不对**：

1. 失败局应该先按 survival 判负
2. 然后才看它是不是“结构上比较像高质量局”
3. 现在 go19 把第 2 点提得太前了

因此 go20 的第一原则是：

- **活下来是前提，质量奖励不能覆盖失败事实**

---

## 3. go20 方案总览

go20 主要包含三条主线：

### 3.1 把终局质量 bonus 改成“先判存活，再判质量”

失败局不允许再拿到正质量加分。

### 3.2 降低对“多桩但失败局”的正向误导

多桩到达可以作为轨迹结构参考，但在失败局里只能减轻惩罚，不能转正。

### 3.3 继续增强对“单桩满步低效局”的压制

把大量 `800` 左右但只到 1 个桩的局继续往下压，使其不再成为训练主流。

---

## 4. 具体方案设计

### 4.1 终局 quality bonus 分成两套逻辑

当前 go19 的问题是：

- `WIN` 和 `FAIL` 共用同一套 quality bonus

go20 建议改成：

#### 4.1.1 若 `truncated == True`（即 WIN）

继续使用质量加分逻辑：

```python
quality_bonus = 0.0

if charger_arrived_count >= 3:
    quality_bonus += 0.30
elif charger_arrived_count == 2:
    quality_bonus += 0.12

if charger_arrived_count >= 2 and second_arrival_step > 0 and second_arrival_step <= 500:
    quality_bonus += 0.08

if charger_arrived_count == 1 and episode_score < 880:
    quality_bonus -= 0.14

if charger_arrived_count == 1 and episode_score < 800:
    quality_bonus -= 0.12
```

这里的调整思路是：

- 保留质量区分
- 但比 go19 略微收敛
- 避免正向 bonus 过强

---

#### 4.1.2 若 `truncated == False`（即 FAIL）

改成“失败局只允许减罚，不允许奖励”：

```python
quality_bonus = 0.0

if charger_arrived_count >= 3:
    quality_bonus += 0.05
elif charger_arrived_count == 2:
    quality_bonus += 0.02
else:
    quality_bonus += 0.0
```

也就是说：

- 多桩失败局最多只略微减轻处罚
- 不再像 go19 那样直接拿 `+0.25 / +0.45`

这样做的意义：

- learner 仍然能知道“这个失败局不是最差的”
- 但不会把它误认为好轨迹

---

### 4.2 对 charge 失败局单独增加终局惩罚

当前失败很多都集中在 `mode=charge`。

go20 建议：

```python
if result_str == "FAIL" and last_mode == "charge":
    quality_bonus -= 0.20
```

注意：

- 这是回合级别处罚
- 不替代行为层安全边界
- 作用是让 learner 更明确地区分：
  - 普通失败
  - charge 失败

因为当前实际最伤训练稳定性的就是后者。

---

### 4.3 对“单桩满步局”继续压制

当前大量 `WIN + 1000步 + charger_arrivals=1` 的局，仍是高分占比提升的最大障碍。

go20 建议把这类局终局惩罚再略增强：

```python
if truncated and charger_arrived_count == 1 and episode_score < 900:
    quality_bonus -= 0.18
```

如果：

```python
truncated and charger_arrived_count == 1 and episode_score < 820:
    quality_bonus -= 0.25
```

这样能更明确地告诉 learner：

- “只围着一个桩活下来”不是优质解

---

### 4.4 保留 go18/go19 的行为层引导，不再继续加重

go20 不建议继续再加：

- 第二桩奖励
- 未到达桩接近 bonus
- loop penalty

原因是：

- 当前日志已经显示这些信号不是完全无效
- 问题主要出在终局级别的错误归因

所以 go20 的重点不是继续堆行为层 reward，而是修正 **终局标签质量**。

## 5. 推荐参数方向

### 5.1 WIN 局质量 bonus

```python
quality_bonus = 0.0

if charger_arrived_count >= 3:
    quality_bonus += 0.30

    quality_bonus += 0.12

    quality_bonus += 0.08

    quality_bonus -= 0.18

if charger_arrived_count == 1 and episode_score < 820:
    quality_bonus -= 0.25
```

### 5.2 FAIL 局质量 bonus

```python
quality_bonus = 0.0

if charger_arrived_count >= 3:
    quality_bonus += 0.05
elif charger_arrived_count == 2:
    quality_bonus += 0.02

if last_mode == "charge":
    quality_bonus -= 0.20
```

## 6. 预期效果

如果 go20 有效，应该看到：

1. `FAIL` 局的正向误导明显减少
2. charge 失败局对 learner 的污染降低
3. 单桩满步局进一步减少
4. `900+` 高分局占比上升
5. 高分平台更稳，不容易被一小段坏局重新拉下去

---

## 7. 重点观察指标

go20 上线后建议重点看：

- `quality_bonus` 在 `WIN` 与 `FAIL` 中的分布是否分离
- `mode=charge FAIL` 的数量
- `charger_arrivals=1 and WIN` 的局占比
- `900+` 占比
- 峰值后 30~60 分钟回落幅度

特别要关注：

- 失败局是不是还会拿到明显正 bonus

如果仍然会，就说明终局质量区分还不够硬。

---

## 8. 结论

go20 的一句话总结：

- **不是继续加大奖励，而是修正 go19 中“高质量失败局被误奖励”的问题，让终局奖励先服从 survival，再谈质量。**

这一步的本质是：

- 让 learner 更清楚地知道：  
  **“活下来并高质量覆盖” 才是好轨迹，  
  “虽然结构好但最后死了” 依然不是好轨迹。**
