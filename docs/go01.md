# go01

目标：在不立即修改代码的前提下，设计一套“`max_step = 1000 / 2000` 双步数训练”方案，作为扩大训练分布、提升模型泛化能力的第一阶段设计稿。

本方案原始版本是设计稿；当前已完成第二阶段代码落地。

## 1. 背景

当前基线训练配置固定为：

- `max_step = 1000`

这意味着当前策略学到的是：

- 在 `1000` 步预算下的探索节奏
- 在 `1000` 步上限下的回桩时机
- 在 `1000` 步截断规则下的收益分配

因此当环境切到：

- `max_step = 2000`

时，策略很可能出现以下问题：

- 前期过于保守，没能利用更长时间窗
- 仍然按 `1000` 步节奏做探索，导致后半段效率低
- reward 与回桩逻辑仍然隐式绑定在 `1000` 步尺度上
- finished_steps、charge_count、score 的关系发生漂移

结论：

如果要提升泛化能力，必须把 `1000 / 2000` 都纳入训练分布，而不是只在评估时切换。

## 2. go01 总体原则

go01 的原则不是“直接全量切双步数训练”，而是：

1. 先让训练分布覆盖 `1000 / 2000`
2. 再让特征和规则显式感知 `max_step`
3. 最后观察策略是否形成跨步数的稳定节奏

也就是说，go01 是“训练步数维度上的泛化扩展方案”。

## 3. 训练分布设计

### 3.1 基础目标

训练时不再只固定：

```toml
max_step = 1000
```

而是让单局训练在两个配置之间切换：

- `max_step = 1000`
- `max_step = 2000`

### 3.2 推荐的采样方式

初期不建议完全随机混成一锅，建议分阶段：

#### 阶段 A：顺序块训练

例如：

- 连续若干局 `1000`
- 连续若干局 `2000`
- 再切回 `1000`

优点：

- 训练曲线更容易读
- 能清楚看出模型在两种步数下是否都在学习

#### 阶段 B：逐局随机

等基础稳定后，再切成：

- 每局随机从 `{1000, 2000}` 中采样

优点：

- 泛化压力更真实
- 不容易让策略记住固定批次顺序

### 3.3 推荐初始比例

第一轮建议：

- `1000 : 2000 = 2 : 1`

原因：

- 当前 baseline 是从 `1000` 步配置长出来的
- 如果一开始就 `1:1`，训练分布变化过猛，容易造成曲线抖动
- 先让 `2000` 步逐步加入，比直接平权更稳

等训练稳定后，再改为：

- `1000 : 2000 = 1 : 1`

## 4. 特征设计方向

如果后面要真正落代码，go01 必须让策略知道当前局的步数上限。

建议新增至少两个特征：

- `max_step_norm`
  - 当前局步数上限归一化
- `step_ratio`
  - 当前步数占该局总步数的比例

原因：

- 同样是第 `500` 步，在 `1000` 步局里已经到中后期
- 在 `2000` 步局里却仍然只是前期

如果模型不知道当前 `max_step`，它就无法学出真正的跨步数策略。

## 5. planner 逻辑设计方向

当前很多 planner 决策默认隐含了“这是一个 1000 步局”。

例如：

- 回桩节奏
- 探索扩张阶段长度
- 是否继续冒险扫图

go01 后续落代码时，建议做的不是大改，而是轻量参数化：

- 让部分阈值对 `max_step` 有感知

重点不是把所有阈值都重写，而是优先改这些：

### 5.1 扩张阶段长度

当前类似：

- `AGGRESSIVE_EDGE_STEPS = 500`

在 `2000` 步局里可能偏短。

建议未来改成与 `max_step` 关联，例如：

- `1000` 步时保持当前值
- `2000` 步时适度增加

### 5.2 回桩保守度

在 `2000` 步局里，策略应允许更长时间的探索，但不能仍然沿用完全相同的“时间压力假设”。

因此建议未来观察：

- `should_charge`
- `charge_count`
- `remaining_charge`

是否在 `2000` 步局里明显失衡。

## 6. reward 设计方向

go01 阶段暂时不建议大改 reward，但要明确后续风险：

- 如果 reward 仍默认按 `1000` 步尺度设计
- 那么 `2000` 步局中同一行为的相对意义会变化

最容易出问题的是：

- step penalty
- 中后期探索收益
- 清扫进度与时间压力之间的平衡

所以 go01 第一阶段建议：

- 先不急着改 reward
- 先看双步数训练下是否已经出现明显失衡

如果出现，再在后续阶段处理。

## 7. 验证指标设计

引入双步数训练后，不能只看整体均值。

必须拆开看：

- `max_step = 1000`
- `max_step = 2000`

每一类都要看：

- success rate
- avg score
- avg finished_steps
- charge_count
- remaining_charge
- 最差局表现

否则会出现：

- 总均值看起来没问题
- 但其中一类步数配置其实已经崩掉

## 8. 风险判断

go01 推进双步数训练，主要有三类风险：

### 8.1 学习曲线波动变大

因为训练分布突然变宽：

- 数据方差会增大
- 同一轮训练里 reward 统计会更难看

### 8.2 策略短期退化

尤其是从只训练 `1000` 步，变成混入 `2000` 步后：

- 模型原本的单配置最优行为可能被打散
- 分数可能短期下降

### 8.3 planner 与策略节奏不一致

如果训练分布先变了，但 planner 还完全按旧步数假设工作，就可能出现：

- policy 想延长探索
- planner 仍然过早或过晚切换行为

## 9. 实施建议

go01 不建议一步到位，而建议分三步：

### 第一步：只做训练配置双步数切换

目标：

- 先确认训练系统能稳定同时跑 `1000 / 2000`

### 第二步：补 `max_step` 感知特征

目标：

- 让模型知道自己正处于哪种步数配置

### 第三步：按验证结果微调 planner 阈值

目标：

- 只修“明显与步数尺度冲突”的规则

## 10. go01 成功标准

本阶段的成功标准不是“立刻双配置都最优”，而是：

1. 训练能稳定覆盖 `1000 / 2000`
2. 两种步数下都能收敛，不出现明显塌局
3. `2000` 步局不是简单重复 `1000` 步节奏
4. 验证指标能按双步数拆开评估

如果做到这四点，go01 就算成功。

## 11. 结论

go01 的本质不是“把 `max_step` 从 1000 改成 2000”，而是：

- 把训练从单一时间尺度扩展为双时间尺度
- 为后续泛化能力拓展打基础

它是一个“训练分布扩容”的起点，而不是一次单纯调参。

### 12.2 实际实现内容

新增了训练内的 `max_step` 调度逻辑：

```python
self.max_step_schedule = (1000, 1000, 2000)
```

每局 reset 前：

1. 基于 `usr_conf` 深拷贝生成 `runtime_usr_conf`
2. 取出 `env_conf`
3. 按 `1000 -> 1000 -> 2000` 循环设置：

```python
env_conf["max_step"] = episode_max_step
```

然后将 `runtime_usr_conf` 传给：

```python
env.reset(runtime_usr_conf)
```

### 12.3 当前策略

当前 go01 训练步数分布为：

- `1000 : 2000 = 2 : 1`

对应循环：

- 第 1 局：`1000`
- 第 2 局：`1000`
- 第 3 局：`2000`
- 然后重复

### 12.4 max_step 感知特征

当前已新增两项配置感知特征：

- `max_step_norm`
- `step_ratio`

对应改动：

- `global_state: 20D -> 22D`
- 总输入维度：

```python
49 + 22 + 8 = 79D
```

模型现在不仅知道“当前已经走了多少步”，还知道：

- 当前局总步数上限是多少
- 当前进度在该局总长度里处于什么位置

### 12.5 训练可视化监控补充

为了后续分析训练曲线，这次还补充了日志输出：

- Episode start 时打印 `max_step`
- GAMEOVER 时打印 `max_step`

同时，监控里新增了四个拆分指标：

- `max_step_target_1000`
- `finished_steps_actual_1000`
- `max_step_target_2000`
- `finished_steps_actual_2000`

这样在训练可视化里可以看到四条线：

- `1000` 步局目标步数线
- `1000` 步局实际步数线
- `2000` 步局目标步数线
- `2000` 步局实际步数线

用于直接观察：

- `1000` 步局是否稳定跑满
- `2000` 步局实际步数是否接近 `2000`

### 12.6 当前边界

这一轮没有做：

- planner 与 `max_step` 的条件阈值化
- reward 的步数尺度修正

因此这一轮的定位是：

- 先把训练分布扩到 `1000 / 2000`
- 观察模型在双步数配置下是否已经出现明显不适配

而不是一步到位解决双步数泛化问题。
