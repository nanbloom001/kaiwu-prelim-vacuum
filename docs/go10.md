# go10

目标：参考 `robot_vacuum-ppo-352` 这版当前最佳方案，明确总结一套可复用的策略配置原则，用于后续继续迭代时，尽量同时保证：

- 高分上限
- 训练稳定性
- 实战存活率
- 不再次滑回“过度保守”或“激进暴毙”

本轮只确定方案，不改代码。

## 1. 结论先行

`robot_vacuum-ppo-352` 的效果最好，不是因为某一个参数特别大或特别小，而是因为它形成了一个完整闭环：

1. **特征层补足“资源风险上下文”**
   - 让策略显式感知：
     - 剩余步数压力
     - 已发现充电桩比例
     - 当前返航压力
   - 对应 `84D` 输入，而不是旧版 `82D`

2. **reward 层把“何时充电”从单点阈值改成区间引导**
   - 不是只惩罚低电
   - 而是同时约束：
     - 太晚充电
     - 太早充电
     - 进入危险低电区
     - 充电收益是否发生在合理电量区间

3. **planner 层把安全边界改成动态安全边界**
   - 安全余量不再固定
   - 而是随：
     - 充电桩稀缺程度
     - 电池容量
     - 回合时长
   - 自动调整返航 margin 和低电阈值

4. **局部动作选择进一步提高近 NPC 风险规避权重**
   - 轻量加强近身 NPC 惩罚
   - 在极近距离时给“拉开距离”的动作额外奖励

5. **训练主框架保持克制**
   - PPO 主超参基本稳定
   - residual PPO + planner prior + BC regularization 框架不大改
   - 重点放在“输入语义 + reward + planner”三层协同

也就是说，`352` 的关键不是“更激进”或“更保守”，而是：

- **把保命条件显式建模**
- **把高效清扫留在安全边界内优化**

## 2. 建议继承的核心配置原则

### 2.1 特征原则：必须保留资源风险语义

后续版本建议继续保留 `352` 的全局状态增强思路，至少保留以下信息：

- `time_left_ratio`
- `observed_charger_ratio`
- `return_pressure`

原因：

- 旧版策略能看到“当前状态”，但较弱地看到“未来返航风险”
- `352` 把“当前还能不能继续扫”这件事显式输入给策略
- 这会直接改善：
  - 早充
  - 晚充
  - 中后期无效巡航

因此，go10 的原则是：

- **后续特征不能再回退到只描述局部地图和当前电量**
- 必须保留“资源余量 + 返航风险 + 充电桩发现进度”三类上下文

### 2.2 reward 原则：充电时机必须做双侧约束

`352` 的 reward 里最有价值的不是简单提高充电奖励，而是把充电时机拆成了四部分：

1. 清扫本身仍然是主收益
2. 低电危险区有持续惩罚
3. 合理区间充电有奖励
4. 过早/过晚充电都要付出代价

这比旧版单纯“低电惩罚 + 充电奖励”更稳定，原因是：

- 只惩罚低电，策略容易学成“越早回桩越安全”
- 只奖励充电，策略容易学成“反复保守充电”
- 双侧约束之后，策略才会逼近“既不拖太晚，也不回太早”

因此 go10 建议后续 reward 继续遵守：

- **充电时机是区间最优，不是单点最优**
- **不能只优化存活率，必须同时限制早充损失**

### 2.3 planner 原则：安全阈值必须动态化

`352` 最值得保留的 planner 思路是：

- `return_margin` 动态化
- `low_battery_ratio` 动态化
- `exit_return_ratio` 动态化

由环境资源条件驱动：

- 充电桩越少，越保守
- 电池容量越低，越保守
- 回合越长，越保守

这比固定阈值好，原因很直接：

- 不同配置桶的风险结构不同
- 固定阈值只能在少数桶里刚好合适
- 动态阈值更容易同时兼顾泛化与稳定

因此 go10 的策略约束是：

- **不再回到固定返航阈值体系**
- 后续若调 planner，应只在动态函数的斜率和上下界上微调
- 不建议重新改回针对单一桶硬编码特判

### 2.4 动作排序原则：NPC 规避要在近距离显式升权

`352` 在动作打分里做了两件小但有效的事：

1. 近 NPC 的惩罚更强
2. 当前已经很靠近 NPC 时，奖励能够拉开距离的动作

这类修改重要的原因是：

- 大部分短局暴毙，不是长期路径错误
- 而是局部一两步没有及时脱离危险区

因此 go10 建议：

- **局部避险优先级要高于短期清扫收益**
- 尤其在 `npc_dist <= 3` 这类极近距离区间，允许牺牲局部得分换稳定脱险

### 2.5 训练框架原则：大框架保持稳定，不要同时乱动

从 `352` 看，真正稳定的是下面这组组合，而不是单个参数：

- residual PPO
- planner prior
- BC 正则随 alpha 退火
- PPO 主超参基本不折腾

因此 go10 明确建议：

- 后续迭代优先级：
  1. 先动特征语义
  2. 再动 reward 结构
  3. 再动 planner 阈值函数
  4. 最后才考虑 PPO 主超参

否则风险很高：

- 一次同时改 reward、planner、alpha、熵系数、网络结构
- 结果即使分数变化，也很难知道是哪一层生效

## 3. 后续版本的推荐实施方向

go10 建议把后续迭代限定为下面三条主线，不要发散。

### 3.1 主线一：继续沿“动态资源安全边界”微调

优先保留并微调：

- 返航 margin 的系数
- 低电阈值的上下界
- 退出充电模式的阈值

调优目标：

- 减少 `charge` 模式下死亡
- 但不能明显增加早充导致的中后期低分

判断标准：

- `charge` 模式死亡下降
- 平均分不掉
- 有效完成步数不上演“活得更久但分更低”

### 3.2 主线二：继续沿“充电时机区间奖励”微调

优先微调：

- 合理充电区间上下边界
- 过早充电惩罚强度
- 极低电晚充惩罚强度

目标不是鼓励更多充电，而是：

- **提高充电成功质量**
- **减少坏时机充电**

建议观察：

- 低电触发次数
- 充电尝试次数
- 充电成功率
- 充电前电量分布

### 3.3 主线三：继续沿“近身 NPC 局部脱险”微调

优先微调：

- 近 NPC 惩罚半径
- 极近距离逃离奖励
- 局部动作排序中的安全权重

目标：

- 降低极短局
- 降低地图局部死角反复碰撞
- 不明显损失正常局的覆盖效率

## 4. 不建议做的方向

根据 `352` 的经验，以下方向现阶段不应作为 go10 主方案：

1. **回到单一目标桶硬编码**
   - 会提升局部成绩
   - 但泛化和稳定性会变差

2. **大幅提高保守阈值**
   - 容易把策略重新推回“只求不死”
   - 平均分和上限都可能回落

3. **大改 PPO 主超参**
   - 容易把可解释问题变成训练噪声问题
   - 当前没有证据说明瓶颈在优化器层

4. **同时改网络结构和 reward/planner**
   - 会破坏归因
   - 很难知道收益来自哪里

## 5. go10 方案落地口径

如果按 go10 往后推进，建议把后续改动口径固定为：

- 保持 `352` 的总体方法论不变
- 继续使用：
  - 增强资源上下文特征
  - 充电时机双侧 reward
  - 动态返航安全边界
  - 近 NPC 局部脱险优先
- 每轮只改一层主逻辑

推荐迭代顺序：

1. 先验证 planner 动态阈值的上下界是否还可再小幅优化
2. 再验证 reward 中早充/晚充区间系数
3. 最后才考虑 residual alpha 或 BC 系数微调

## 6. 后续评估指标

go10 之后建议不再只看平均分，至少同时看：

- `avg_score`
- `win_rate`
- `avg finished_steps`
- `charge` 模式死亡占比
- 极短局占比
- 充电成功率
- 低电触发次数
- 近 NPC 高风险步数

判断“真的更好”的标准应改为：

- 分数不降或上升
- 死亡结构更健康
- 不是靠极端保守换来的稳定

## 7. 最终方案摘要

go10 最核心的方案结论只有一句话：

- **以后继续迭代时，必须以 `352` 的三层协同结构为基线：特征显式表达资源风险，reward 用区间方式约束充电时机，planner 用动态阈值管理返航安全边界。**

在这个基线之上，再做：

- 小步微调
- 单层验证
- 指标分解评估

而不是重新回到：

- 固定阈值
- 单点 reward
- 只追求保命的训练方向
