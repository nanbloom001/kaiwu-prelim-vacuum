# go05

目标：在 `go04` 的多配置训练基础上，针对目前最敏感的两个配置维度：

- `battery_max`
- `charger_count`

对 reward 和 planner 做条件化增强，优先提升低资源场景下的鲁棒性。

本文件原始版本即本轮代码落地说明。

## 1. 问题背景

从最新的分桶验证结果看，在相同：

- `robot_count=1`
- `charger_count=1`
- `max_step=1000`

条件下，`battery_max` 的变化对结果影响非常明显：

- `battery_max=200`：失败，`steps=841`，`score=758`
- `battery_max=400`：成功，`steps=1000`，`score=908`
- `battery_max=800`：成功，`steps=1000`，`score=929`

说明当前模型的主要短板之一是：

- 对低 `battery_max` 场景不够鲁棒

同时，`charger_count` 变少时也会加剧回桩失败和长尾塌局。

## 2. 设计目标

go05 不改变训练分布，而是在已有多配置训练框架上强化：

1. 低 `battery_max` 场景下更早、更稳地建立回桩闭环
2. 低 `charger_count` 场景下减少高风险外扩
3. 高 `battery_max` / 高 `charger_count` 场景下不要过度保守

## 3. 本轮实际修改

### 3.1 reward 条件化增强

修改文件：

- `code/agent_ppo/feature/preprocessor.py`
- `agent_ppo/feature/preprocessor.py`

引入三个条件因子：

- `charger_scarcity`
- `low_capacity_factor`
- `long_horizon_factor`

并组合成：

- `resource_pressure`
- `late_game_factor`

在此基础上，强化了以下 reward 项：

#### 充电 sweet zone 条件化

```python
target_low = 0.32 + 0.05 * resource_pressure
target_high = 0.58 + 0.04 * resource_pressure
```

解释：

- 资源越紧张（charger 少 / 电池小 / 长局），sweet zone 越前移

#### 充电效率奖励增强

```python
charge_efficiency_reward = (1.20 + 0.20 * resource_pressure) * ...
```

解释：

- 在低资源场景下，正确回桩获得更强学习信号

#### 过晚充电惩罚增强

```python
danger_floor = 0.18 + 0.04 * resource_pressure
```

解释：

- 资源越紧张，拖到过低电量才回桩的惩罚越重

#### 低电量 / 危险区停留惩罚增强

```python
low_battery_penalty = -(0.035 + 0.020 * resource_pressure) * ...
critical_battery_penalty = -(0.090 + 0.050 * resource_pressure) * ...
```

解释：

- 对低资源组合下的危险停留施加更强负反馈

#### 长局中后段效率奖励

新增：

```python
late_game_efficiency_reward = 0.04 * cleaned_this_step * late_game_factor * (1.0 + 0.5 * resource_pressure)
```

解释：

- 在长局后半段，如果仍能持续有效清扫，给予额外正向信号
- 解决“会活但不会高效打长局”的问题

### 3.2 当前 planner 条件化的关系

go05 本轮没有继续大改 planner 公式，只延续 `go04` 中已存在的配置条件化逻辑：

- `effective_return_margin`
- `effective_low_battery_ratio`
- `effective_exit_return_ratio`
- `effective_aggressive_edge_steps`

也就是说：

- planner 负责先保住安全闭环
- reward 负责把低资源场景下的高质量节奏学稳

## 4. 预期效果

本轮预期主要改善：

- `battery_max=200` 场景下的早停
- `charger_count=1` 场景下的失败率
- 长局后半段的清扫效率

尤其应重点观察：

- 低资源桶的 success rate 是否上升
- 低资源桶的 min_steps / min_score 是否抬升

## 5. 当前边界

这一轮仍然没有做：

- `step_penalty` 的完全比例化重写
- `robot_count` 相关 reward 条件化
- 更细粒度的 charge path 安全奖励

因此 go05 仍然属于：

- 在 `go04` 基础上，对低资源场景做定向增强

而不是完整的 reward 重构。
