# go21

目标：基于 `2026-04-24 22:41` 到 `2026-04-25 00:36` 这一轮最新训练日志，并结合最新验证中“机器人仍容易陷入狭窄房间打转”的现象，针对 `go20` 之后仍然存在的 `charge` 崩溃问题，提出一版**只聚焦 charge 阶段**的更窄修正方案。

这版不再继续改：

- `WIN / FAIL` 的终局质量分层
- 单桩满步局惩罚
- 非 `charge` 模式行为逻辑

go21 的唯一目标是：

- **降低 `mode=charge` 下的中途 FAIL，占住 survival 底线。**
- **抑制 charge 场景下进入狭窄房间后的局部循环。**

---

## 1. 当前日志结论

本轮日志统计结果：

- 总局数：`54`
- `WIN = 34`
- `FAIL = 20`
- 其中 `charge FAIL = 18`

也就是说：

- 本轮 `FAIL` 几乎都发生在 `charge` 阶段
- `go20` 已经解决了“失败局被误奖励”的问题
- 但还没有解决“为什么大量局仍死在 charge”这个主问题

### 1.1 go20 已经起效的地方

从本轮日志看：

- `FAIL` 局不再出现正 `quality_bonus`
- `FAIL` 局的 `quality_bonus` 只出现：
  - `-0.20`
  - `-0.18`
  - `0.00`

说明：

- go20 的终局标签纠偏是有效的
- learner 不再把失败局当成半个好局

---

### 1.2 当前真正剩下的问题

当前核心不是“奖励方向错了”，而是：

- `charge` 阶段的**行为过程本身**仍不稳

典型失败样例如下：

- `ep42 steps=150 FAIL mode=charge score=140 charger_arrivals=0 quality_bonus=-0.200`
- `ep53 steps=150 FAIL mode=charge score=135 charger_arrivals=0 quality_bonus=-0.200`
- `ep52 steps=203 FAIL mode=charge score=188 charger_arrivals=1 quality_bonus=-0.200`
- `ep45 steps=542 FAIL mode=charge score=488 charger_arrivals=1 quality_bonus=-0.200`
- `ep40 steps=759 FAIL mode=charge score=705 charger_arrivals=1 quality_bonus=-0.200`

结合验证中“狭窄房间打转”的现象，当前 `charge` 崩溃并不只是一种情况，而是至少有三类：

#### A. 早期 charge 崩溃

特征：

- `steps` 很低，常见 `150~250`
- `charger_arrivals = 0/1`
- 说明进入 charge 后很快就死

#### B. 中后期 charge 崩溃

特征：

- `steps` 在 `500~760`
- 已有一定覆盖和至少 1 次到桩
- 但在后续 charge 处理中仍然崩

#### C. 窄空间 charge 循环

特征：

- 机器人进入狭窄房间或狭长通道
- 反复在局部区域来回摆动
- `new_observed_cells` 很少
- 没有清扫增量，也没有有效充电收益

这类问题的危险点在于：

- 表面上机器人仍在移动
- 但本质上已经失去 `charge` 阶段的有效推进
- 很容易进一步演化成晚期 `charge FAIL`

这说明 go21 不应该继续只靠“回合末处罚”，而应该对 `charge` 过程本身补更直接的约束，尤其要把“charge 中的窄空间打转”单独视为目标问题。

---

## 2. go21 核心判断

当前训练已经足够说明：

1. `charge` 不是辅助小问题，而是主失败源
2. go20 已经把失败归因修正到位
3. 下一步应该把改动范围收窄到 `charge` 阶段本身

因此 go21 的第一原则是：

- **只修 charge survival，不扩散修改范围。**

换句话说：

- go20 解决的是“死了以后别再被奖励”
- go21 解决的是“别那么容易死在 charge 里”

---

## 3. go21 方案总览

go21 只做四条窄修正：

### 3.1 对 `charge` 过程增加更强的逐步负反馈

让 learner 更早知道：

- 在 `charge` 状态里拖延、抖动、乱走，不是中性行为

### 3.2 对 `charge` 窄空间打转增加专门处罚

让 learner 更明确地区分：

- 正在逼近充电桩
- 还是只是卡在窄空间里原地消耗时间

### 3.3 对 `charge` 早死局额外打标

把 `150~250` 步就死掉的局，与普通 `charge FAIL` 分开处理。

### 3.4 对 `charge` 成功存活给小幅正反馈

不是鼓励所有 `charge`，而是鼓励：

- 成功从 `charge` 阶段活着出来
- 或在 `charge` 主导下跑满 `1000`

---

## 4. 具体方案设计

### 4.1 在 `charge` 模式增加逐步生存代价

当前 go20 主要是回合末处罚：

```python
if last_mode == "charge":
    quality_bonus -= 0.20
```

这能纠偏，但太晚。

go21 建议补一个轻量的**过程级**惩罚：

```python
if current_mode == "charge":
    reward -= 0.0025
```

如果连续处于 `charge`，则每步都持续扣一点。

目的不是重罚，而是：

- 抑制 charge 中无效停留
- 让策略更倾向于尽快完成补能并离开危险阶段

注意：

- 这个惩罚只在 `charge` 模式下生效
- 不影响 `explore / dirt / edge_frontier`

---

### 4.2 对 charge 窄空间打转单独处罚

现有代码里已经有通用：

- `revisit_penalty`
- `loop_penalty`

但从验证结果看，这对“狭窄房间 + charge”还不够硬。

原因是：

- 通用 `loop_penalty` 只是在所有模式里轻量生效
- 它没有区分“普通探索回摆”和“低电量下卡在窄空间”

go21 建议在 `charge` 场景追加一个更窄的反循环条件：

```python
charge_loop_penalty = 0.0

if (
    current_mode == "charge"
    and cur_revisit_count >= 2
    and new_observed_cells == 0
    and cleaned_this_step == 0
    and charge_gain_ratio < 0.01
):
    charge_loop_penalty -= 0.020
```

如果还想更明确压制“狭窄房间打转”，可以再叠加一个局部可探索性门槛：

```python
if current_mode == "charge" and unvisited_ratio < 0.18:
    charge_loop_penalty -= 0.006
```

这一条的含义不是惩罚所有低 `unvisited_ratio` 场景，而是：

- 当机器人已经在 `charge` 中
- 周围又几乎没有新空间
- 同时还在重复回访

就说明它大概率不是在正常找路，而是在窄区域里打转。

这样做的目的：

- 把“charge 中无效回摆”从普通拖延里剥离出来
- 尤其针对验证里暴露出的狭窄房间循环

---

### 4.3 对 charge 早期崩溃单独加重

本轮最危险的不是所有 charge fail，而是这种：

- 刚进入 charge 不久就死
- `steps <= 250`

go21 建议把它作为单独类别：

```python
if result_str == "FAIL" and last_mode == "charge":
    quality_bonus -= 0.20

    if step <= 250:
        quality_bonus -= 0.15
```

也就是说：

- 普通 `charge FAIL` 仍是 `-0.20`
- 早死 `charge FAIL` 变成 `-0.35`

这样做的意义：

- learner 会更明确地区分：
  - 晚期复杂失败
  - 刚进 charge 就崩的明显坏轨迹

---

### 4.4 对 charge 存活完成给小幅回补

当前日志里也存在一些：

- `mode=charge`
- 但最终 `WIN`
- 甚至能拿到 `900+`

例如：

- `ep15 WIN mode=charge score=939 charger_arrivals=3 quality_bonus=0.380`
- `ep51 WIN mode=charge score=919 charger_arrivals=3 quality_bonus=0.380`

这说明 `charge` 不是不能学，而是稳定性不足。

go21 建议只对“成功穿过 charge 并活下来”的局给一个很小的结构奖励：

```python
if truncated and last_mode == "charge":
    quality_bonus += 0.05
```

注意边界：

- 只加很小幅度
- 不是鼓励“多 charge”
- 只是告诉 learner：  
  `charge` 可以是安全完成的，而不是天然高风险阶段

---

### 4.5 不改其他终局质量逻辑

go21 刻意不动：

- `WIN` 局多桩奖励
- 单桩满步惩罚
- `FAIL` 局非 charge 处理

原因是：

- 这些逻辑在 go20 中已经方向正确
- 当前问题高度集中在 `charge`
- 如果这时继续一起改，会把因果重新搅混

---

## 5. 推荐参数方向

### 5.1 charge 过程惩罚

```python
if current_mode == "charge":
    reward -= 0.0025
```

推荐范围：

- `0.002 ~ 0.004`

首选：

- `0.0025`

---

### 5.2 charge 窄空间反循环惩罚

```python
charge_loop_penalty = 0.0

if (
    current_mode == "charge"
    and cur_revisit_count >= 2
    and new_observed_cells == 0
    and cleaned_this_step == 0
    and charge_gain_ratio < 0.01
):
    charge_loop_penalty -= 0.020

if current_mode == "charge" and unvisited_ratio < 0.18:
    charge_loop_penalty -= 0.006
```

推荐原则：

- 主惩罚先用 `-0.020`
- 局部狭窄附加项先用 `-0.006`
- 不建议第一次就加得更重

---

### 5.3 charge FAIL 终局惩罚

```python
if result_str == "FAIL" and last_mode == "charge":
    quality_bonus -= 0.20

    if step <= 250:
        quality_bonus -= 0.15
```

---

### 5.4 charge WIN 微弱回补

```python
if truncated and last_mode == "charge":
    quality_bonus += 0.05
```

这个值不要太大，避免重新把 `charge` 变成过强偏好。

如果 go21 有效，应该看到：

2. 验证里“狭窄房间打转”现象明显减少
3. `charge FAIL` 总数下降

5. 后半段训练里 `charge` 不再持续成为主失败源
6. 高分局维持能力更稳

go21 不要求这一轮就把所有 `charge FAIL` 清零，真正合理的目标是：

- **先把“早进早死”这类坏失败压下去**

## 7. 重点观察指标

go21 上线后建议重点看：

- `mode=charge FAIL` 总数
- `steps <= 250 and mode=charge FAIL` 数量
- `mode=charge WIN` 数量
- `charge` 模式平均持续步数
- `charge` 状态下 `cur_revisit_count >= 2` 的帧占比
- `charge` 状态下 `new_observed_cells == 0` 的连续长度
- `900+` 局占比是否保持

特别要关注：

- `charge FAIL` 是否从“早死为主”变成“少量晚期失败”

如果这点发生，说明 go21 方向是对的。

---

## 8. 风险与控制

### 风险 1：charge 过程惩罚过强，导致策略回避 charge

控制方式：

- 每步惩罚只取很小值
- 首先从 `0.0025` 起步

### 风险 2：反循环惩罚误伤正常窄通道通过

控制方式：

- 只有在 `charge` 下才触发
- 必须同时满足“重复访问 + 无新观测 + 无清扫 + 几乎无充电收益”
- 不用单一条件就处罚

### 风险 3：charge WIN 回补引入新的偏好污染

控制方式：

- 回补只给 `+0.05`
- 明显小于多桩高质量奖励

### 风险 4：早死阈值过硬，误伤边界局

控制方式：

- 先用 `step <= 250`
- 不再叠加更多分段规则

## 9. 结论

go21 的一句话总结：

- **go20 已经修正了“失败怎么判”，而结合最新验证结果，go21 要修的是“为什么机器人会在 charge 阶段卡进狭窄房间打转并最终死掉”，因此只针对 charge 过程增加更早、更窄、更直接的生存与反循环约束。**

本轮关键边界：

- 只动 `charge`
- 不扩展到其他模式
- 不重新改大范围终局质量逻辑

这样下一轮日志如果继续改善，就能更清楚确认：

- 真正起作用的是 `charge` 定向修正，而不是其他变量混在一起。
