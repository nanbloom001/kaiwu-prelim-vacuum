# go19

目标：针对当前训练中频繁出现的“训练一段时间后峰值跌落、进入低分谷底”的问题，设计一版专门用于**抑制高分回落、提升高质量轨迹稳定占比**的方案。

当前问题不是简单的“还没学会”，而是：

- 会阶段性进入高分状态
- 但高分状态不能稳定保持
- 训练继续进行后，又会被低质量轨迹重新拉回低分区

所以 go19 的目标不是“再多冲一点高分”，而是：

- **让高分轨迹不再只是偶发，而逐步成为训练中的主流样本。**

---

## 1. 当前问题定义

从现有训练日志看，当前训练并不是单一分布，而是典型的多峰分布：

### 1.1 高质量轨迹

特征：

- `score >= 900`
- `charger_arrivals = 3`
- 通常跑满 `1000`
- 覆盖效率高，路径较完整

### 1.2 低效存活轨迹

特征：

- 跑满 `1000`
- 但 `charger_arrivals = 1`
- 分数通常在 `700~850`
- 典型表现是单桩吸附、局部热点循环

### 1.3 charge 失败轨迹

特征：

- `mode=charge FAIL`
- 中途暴毙
- 分数常见在 `150~700`

这三类轨迹会不断交替进入训练，导致：

- 有时高分局占优，曲线冲高
- 有时低效局和失败局占优，曲线回落

这就是当前“峰值跌落”的直接来源。

---

## 2. go19 核心判断

当前训练之所以会从高点掉回低谷，核心不是优化器突然失效，而是：

1. 高质量策略还未形成稳定主策略
2. 低质量样本仍持续大量进入 replay buffer
3. learner 在阶段性地被“低效活着”和“charge 失败”样本重新牵引

所以 go19 不是单纯继续做 reward 微调，而是要补一个新的目标：

- **压缩低质量轨迹在训练中的影响力**

---

## 3. 方案原则

go19 继续遵守低风险边界：

1. 不改网络结构
2. 不改 planner 主状态机
3. 不引入复杂黑名单或切桩记忆机制
4. 优先从训练样本分布与 reward 归因入手

也就是说：

- go17 / go18 解决的是“行为本身”
- go19 解决的是“行为分布为什么会反复退化”

---

## 4. go19 方案总览

go19 包含三条主线：

### 4.1 降低低质量满步轨迹的吸引力

让“虽然跑满但只到 1 个桩”的局，不再成为 learner 的强正反馈来源。

### 4.2 提升高质量轨迹的终局区分度

让多桩高覆盖局与单桩低效局在回合总 reward 上更明显拉开。

### 4.3 减少训练样本的阶段性污染

让 learner 不会被某一小段时期的大量差局重新拖回去。

---

## 5. 具体方案设计

### 5.1 增强终局奖励的“质量区分度”

当前很多低效局虽然分数不高，但只要跑满 `1000`，终局奖励结构仍可能给出较强正反馈。

go19 建议在终局奖励上增加“高质量覆盖加分 / 低质量覆盖折损”：

终局不再只看：

```python
final_reward = 2.5 * cleaning_ratio + 1.5 * score_ratio
```

而是建议加一个质量调节项：

```python
quality_bonus = 0.0

if charger_arrived_count >= 3:
    quality_bonus += 0.35
elif charger_arrived_count == 2:
    quality_bonus += 0.15
elif charger_arrived_count == 1 and cleaning_ratio < 0.75:
    quality_bonus -= 0.20
```

理由：

- 跑满 `1000` 但只到一个桩，本质上就是当前最典型的低质量满步局
- 这种局如果终局奖励仍然过强，就会不断污染 learner

---

### 5.2 对“高分但单桩”的局增加轻惩罚

有些局能到 `800+`，但路径结构依然是低效的。

go19 建议增加一个轻量结构惩罚：

```python
if charger_arrived_count == 1 and episode_score < 880:
    quality_bonus -= 0.10
```

这样做的意义：

- 把“高质量高分局”和“单桩勉强高分局”进一步拉开
- 防止策略继续把“单桩可活”学成稳定主解

---

### 5.3 保留并加强第二桩导向

go18 里已经在做：

- 第二桩奖励更高
- 未到达桩接近奖励更强

go19 不推翻这些，而是要求继续保持：

- 第二桩依然是最高价值目标

并额外引入一个“前 500 步第二桩到达加成”：

```python
if charger_arrived_count >= 2 and second_arrival_step > 0 and second_arrival_step <= 500:
    quality_bonus += 0.10
```

理由：

- 当前高质量局的一个关键特征，不只是最终到达 2/3 个桩
- 而是**到达得足够早**

---

### 5.4 对热点循环局增加回合级惩罚

当前已有逐步 `loop_penalty`，但 go19 还建议在回合末增加“结构性低效惩罚”：

例如：

```python
if charger_arrived_count == 1 and episode_score < 800:
    quality_bonus -= 0.12
```

这能更直接告诉 learner：

- 这种“只围着一个桩转，最后只拿到 700~800”的局，虽然活下来了，但并不是好轨迹

---

### 5.5 尽量减少 replay buffer 的阶段性污染

如果代码层允许，go19 最理想的方向是：

- 对高质量轨迹赋予更高采样权重
- 对明显低质量轨迹降低采样权重

如果当前框架不方便直接做优先级采样，也建议至少在逻辑上区分：

#### 高质量轨迹

- `charger_arrived_count >= 2`
- `score >= 880`

#### 低质量轨迹

- `charger_arrived_count == 1 and score < 850`
- 或 `mode=charge FAIL`

即便暂时不改 replay 采样逻辑，也应该在日志里明确记录这两类轨迹比例。

---

## 6. 推荐参数方向

### 6.1 终局质量加权

```python
quality_bonus = 0.0

if charger_arrived_count >= 3:
    quality_bonus += 0.35
elif charger_arrived_count == 2:
    quality_bonus += 0.15
elif charger_arrived_count == 1 and cleaning_ratio < 0.75:
    quality_bonus -= 0.20

if charger_arrived_count == 1 and episode_score < 880:
    quality_bonus -= 0.10

if charger_arrived_count >= 2 and second_arrival_step > 0 and second_arrival_step <= 500:
    quality_bonus += 0.10

if charger_arrived_count == 1 and episode_score < 800:
    quality_bonus -= 0.12
```

最终终局奖励变成：

```python
final_reward = base_terminal_reward + quality_bonus
```

---

### 6.2 维持现有行为层引导

保留：

- go17 / go18 的第二桩高奖励
- 未到达桩接近奖励
- 热点循环逐步惩罚
- charge 安全边界

go19 不替换这些，只是在回合级别增强“好局”和“差局”的可分性。

---

## 7. 预期效果

如果 go19 有效，预期会出现以下变化：

1. `900+` 分局占比上升
2. `700~850` 分满步局占比下降
3. `charger_arrivals=1` 的满步局减少
4. `charger_arrivals=2/3` 的局成为主流
5. 曲线峰值之后的跌幅变小
6. 高分状态维持时间更长

换句话说，go19 追求的不是“更高的单点峰值”，而是：

- **更稳定的高分平台**

---

## 8. 重点观察指标

go19 上线后，建议重点观察：

- `900+` 分局占比
- `700~850` 分局占比
- `charger_arrived_count` 分布
- `second_arrival_step` 分布
- `mode=charge FAIL` 次数
- 峰值后 30~60 分钟的回落幅度

特别要关注：

- 高分局是不是只是偶发
- 还是已经变成主流

---

## 9. 风险与控制

### 风险 1：终局奖励区分过强，导致训练不稳定

控制方式：

- `quality_bonus` 只做中小幅修正
- 不超过主终局奖励的主量级

### 风险 2：过度压制单桩局，导致探索初期更脆弱

控制方式：

- 只惩罚“单桩且低覆盖 / 低分”的局
- 不惩罚所有单桩局

### 风险 3：高分占比没起来，但 survival 先掉了

控制方式：

- charge 安全边界保持不变
- 先动终局质量区分，不继续加大行为层激进度

---

## 10. 结论

go19 的一句话总结：

- **不是再多做一点局部 reward 微调，而是让 learner 在回合层面更清楚地知道：哪些轨迹是高质量轨迹，哪些只是“低效活着”。**

换句话说：

- go17 / go18 解决的是“怎么做得更好”
- go19 解决的是“训练为什么总被差局重新拉回去”
