# go23

目标：基于当前 `go22` 版本的真实训练日志，落实一版更严格的 `arrival reward gating` 收紧策略，专门解决：

- `arrival_confirmed` 很高，但 `arrival_canceled=0`
- 大量失败发生在 `arrival` 之后
- 主失败模式仍然集中在 `mode=charge`

go23 不推翻 go22，而是对 go22 做一次 **方向正确但力度不足后的二次收紧**。

---

## 1. 核心判断

当前问题不是“看不到 charger”，也不是“reward 太少”，而是：

- `arrival` 奖励确认过早
- 很多轨迹只是短期上看似有一点价值
- 但中短期内仍会落入 `charge FAIL`

因此 go23 的核心目标是：

- **把 `arrival reward` 从“短期即时信用”收紧成“中短期 survival-aware credit”。**

## 3. go23 落地后的策略结构

### 3.1 双阶段确认

每次首次到达新 charger 后，不再直接发完整 reward，而是经历两段：

1. `candidate_confirmed`
2. `final_confirmed`

含义：

- `candidate_confirmed`：仅说明短期收益开始显现
- `final_confirmed`：说明中短期收益和生存条件都通过

---

### 3.2 延迟窗口

#### 第 1 个桩

- `candidate_min_delay = 20`
- `candidate_deadline = 40`
- `final_min_delay = 80`
- `final_deadline = 160`

#### 第 2 个桩

- `candidate_min_delay = 24`
- `candidate_deadline = 48`
- `final_min_delay = 96`
- `final_deadline = 176`

#### 第 3 个及之后

- `candidate_min_delay = 28`
- `candidate_deadline = 56`
- `final_min_delay = 120`
- `final_deadline = 200`

---

### 3.3 收益确认条件

#### Candidate 阶段

第 1 个桩：

- `coverage_gain >= 4`
- 或 `observed_gain >= 30`
- 或 `left_region == True && coverage_gain >= 2`

第 2 个桩：

- `coverage_gain >= 5`
- 或 `observed_gain >= 36`
- 或 `left_region == True && coverage_gain >= 3`

第 3 个及之后：

- `coverage_gain >= 6`
- 或 `observed_gain >= 44`
- 或 `left_region == True && coverage_gain >= 4`

#### Final 阶段

第 1 个桩：

- `coverage_gain >= 6`
- 或 `observed_gain >= 40`
- 或 `left_region == True && (coverage_gain >= 3 or observed_gain >= 20 or battery_gain >= 0.08)`

第 2 个桩：

- `coverage_gain >= 8`
- 或 `observed_gain >= 52`
- 或 `left_region == True && (coverage_gain >= 4 or observed_gain >= 26 or battery_gain >= 0.10)`

第 3 个及之后：

- `coverage_gain >= 10`
- 或 `observed_gain >= 64`
- 或 `left_region == True && (coverage_gain >= 5 or observed_gain >= 32 or battery_gain >= 0.12)`

---

### 3.4 Base reward 与候选比例

#### Base reward

- 第 1 个桩：`0.10`
- 第 2 个桩：`0.05`
- 第 3 个及之后：`0.02`

#### Candidate reward 比例

- 第 1 个桩：`0.35`
- 第 2 个桩：`0.25`
- 第 3 个及之后：`0.15`

Candidate 阶段只提前支付少量 reward，剩余部分在 `final_confirmed` 时支付。

---

### 3.5 Early arrival 折损

为了抑制过早摸桩带来的错误吸引，go23 加入早期折损：

- `arrival_step <= 100`：乘 `0.35`
- `100 < arrival_step <= 150`：乘 `0.55`
- `150 < arrival_step <= 220`：乘 `0.75`
- `> 220`：乘 `1.0`

---

## 4. 取消与回滚机制

### 4.1 直接取消条件

若在确认窗口内满足以下任一条件，则取消该次 arrival：

- `is_starving == True`
- `charge_active && charge_loop_flag && not left_region`
- `charge_active && charge_loop_frames >= 6`
- `battery_ratio <= 0.18`

这对应日志里“到桩后其实已经进入高风险态”的样本。

---

### 4.2 Candidate 过期取消

若在 `candidate_deadline` 之前仍未满足 candidate 价值条件：

- 记为 `candidate_expired`
- 追加小额取消 penalty

落地 penalty：

- `-0.02 * early_discount`

---

### 4.3 Final 过期取消

若已 candidate confirmed，但在 `final_deadline` 前仍未满足 final 条件：

- 记为 `final_expired`
- 撤销已给的 candidate credit

落地 penalty：

- `-max(0.02, candidate_reward_paid)`

---

### 4.4 终局回滚

如果：

- 当前 episode 最终 `FAIL`
- 且满足以下任一条件：
  - `final_mode == "charge"`
  - `charge_fail_after_arrival == 1`
- 且某次 `final_confirmed` 后 `<= 200` 步内失败

则触发 `retro_cancel`：

- 回滚该次 final credit
- 追加惩罚

落地 penalty：

- `-(final_reward_paid + 0.04)`

并记录：

- `arrival_retro_canceled_count`
- `arrival_confirm_to_fail_gap`
- `retro_canceled_arrivals`

---

## 5. 新增日志与监控字段

go23 为了验证 credit 是否真的收紧，新增并上报：

- `arrival_candidate_confirmed_count`
- `arrival_confirmed_count`
- `arrival_canceled_count`
- `arrival_retro_canceled_count`
- `arrival_pending_count`
- `charger_first_candidate_confirmed_step`
- `charger_first_confirmed_arrival_step`
- `arrival_confirm_to_fail_gap`
- `first_confirmed_arrival_is_early`
- `go23_terminal_adjust`

GAMEOVER 日志中同步输出这些字段，便于区分：

- 到桩但未通过 candidate
- 通过 candidate 但未通过 final
- 通过 final 但在终局被回滚

## 6. 本次修改后的参数汇总

### Arrival reward

- `base_reward(first) = 0.10`
- `base_reward(second) = 0.05`
- `base_reward(third+) = 0.02`

### Candidate reward scale

- `candidate_scale(first) = 0.35`
- `candidate_scale(second) = 0.25`
- `candidate_scale(third+) = 0.15`

### Delay windows

- first: `20/40/80/160`
- second: `24/48/96/176`
- third+: `28/56/120/200`

### Early discount

- `<=100 -> 0.35`
- `<=150 -> 0.55`
- `<=220 -> 0.75`
- `>220 -> 1.0`

### Risk thresholds

- `battery_ratio <= 0.18`
- `charge_loop_frames >= 6`
- `retro_cancel_window = 200`

### Retro cancel penalty

- `-(final_reward_paid + 0.04)`

### Retro cancel fail condition

- `result_str == "FAIL"`
- 且 `final_mode == "charge" or charge_fail_after_arrival == 1`

---

## 7. 预期效果

go23 落地后，预期看到下面变化：

- `arrival_confirmed` 明显下降
- `arrival_canceled` 不再接近 0
- `retro_canceled` 开始出现
- `fail_after_arrival / fail` 下降
- 早期到桩但后续 `charge FAIL` 的轨迹减少

允许出现的副作用：

- 短期 reward 上升速度变慢
- 第二桩、第三桩确认明显更少
- 某些看似“到桩成功”的样本不再计正信用

这是合理的，因为 go23 的目标不是让 `arrival_confirmed` 更好看，而是把错误正样本真正切掉。

---

## 8. 一句话总结

go23 的本质是：

- **把 charger arrival 奖励从“只要短期有一点收益就确认”收紧成“必须在中短期内同时证明收益与生存，否则取消，甚至在 charge FAIL 时回滚”。**
