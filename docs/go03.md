# go03

目标：在确认 `go02` 没有带来明显提升之后，停止继续沿“长局 planner 阈值微调”方向加码，转而重组双步数训练方案，优先解决：

- `1000 / 2000` 混训造成的训练分布冲突
- 当前 reward 仍偏 `1000` 步尺度的问题
- 无法明确判断到底是哪一类步数配置拖累整体表现的问题

本文件原始版本是方案设计；当前已完成第一轮代码落地。

## 1. 为什么需要 go03

`go02` 的核心假设是：

- 当前问题主要来自 `2000` 步局回桩稳定性不够
- 只要在 planner 里对 `2000` 步局做条件化保守增强，就能改善整体表现

但现在反馈是：

- **效果并没有明显得到提升**

这说明：

1. 问题不一定主要在 planner 回桩阈值
2. 即使 `charge` 阶段看起来像问题点，也可能只是结果而不是根因
3. 当前双步数训练组织方式本身，可能比 planner 参数更值得优先处理

所以 go03 的目标不是继续“局部补丁式”调 planner，而是重新审视双步数训练方法。

## 2. 当前更合理的问题判断

在 `go01/go02` 阶段，已经确认了几件事：

### 2.1 双步数训练本身是跑起来了

日志已经证明：

- `1000 / 1000 / 2000` 确实在实际 rollout 中交替出现
- `2000` 步局成功时能打出高分

所以问题不是“切换配置没生效”。

### 2.2 `2000` 步局不是完全不会打

成功局能打到：

- `1700+`
- 甚至接近 `1900`

这说明模型在部分场景下已经具备长局探索能力。

### 2.3 当前真正的问题更像是训练组织冲突

如果：

- 有些 `2000` 局明显成功
- 但整体效果仍不稳定
- 而 `go02` 进一步调 planner 也没明显改善

那更合理的推断是：

- 当前训练组织方式让模型在 `1000` 与 `2000` 两套节奏之间来回折中
- 最终形成“并不完全适配任何一类”的折中策略

也就是说，问题更像是：

- **双步数混训方式不优**

而不是：

- “再加一点回桩 margin 就能解决”

## 3. go03 总体策略

go03 的总原则是：

- 先把 `1000` 与 `2000` 拆开分析
- 再决定是否继续混训
- 如果混训，要先让 reward/统计/验证体系支持分桶观察

也就是说，go03 的重心从：

- “调单个阈值”

切到：

- “重组训练与验证框架”

## 4. go03 推荐路线

## 4.1 路线 A：分阶段训练，优先推荐

这是我最推荐的方案。

### 阶段 1：固定 `1000`

目标：

- 保住当前 `1000` 步局能力
- 作为稳定基线

### 阶段 2：固定 `2000`

目标：

- 单独观察模型在长局下是否能稳定学习

重点看：

- 是否仍出现大量 `charge` 模式早停
- 分数是否逐步拉升
- success rate 是否可收敛

### 阶段 3：再决定是否恢复混训

只有在：

- `1000` 单训稳定
- `2000` 单训也稳定

之后，再考虑恢复混训。

原因：

- 如果单独训练都不稳定，混训只会把问题掩盖
- 如果单独训练都稳定，混训才有意义

## 4.2 路线 B：继续混训，但必须分桶优化

如果你坚持继续混训，那么必须先补全分桶统计。

至少要拆：

- `1000` 步局 success rate
- `2000` 步局 success rate
- `1000` 步局 avg score
- `2000` 步局 avg score
- `1000` 步局 avg finished_steps
- `2000` 步局 avg finished_steps
- `1000` 步局 charge_count
- `2000` 步局 charge_count

否则：

- “整体没提升”这个结论没有足够定位能力

## 5. go03 对 reward 的判断

## 5.1 当前 reward 更像是为 `1000` 步局生长出来的

当前 reward 设计的主要问题不是方向错，而是：

- 节奏尺度默认隐含 `1000` 步

典型风险点包括：

- `step_penalty`
- 探索收益时间分布
- 终局奖励在 `1000 / 2000` 下的相对权重

所以 go03 更建议做的是：

- **reward 条件化**

而不是再继续强化 planner 条件化。

## 5.2 go03 的 reward 调整方向

如果后续落代码，优先考虑：

### 方向 1：step penalty 条件化

让 `step_penalty` 不再完全固定，而和：

- `max_step`
- `step_ratio`

挂钩。

目的：

- 避免 `2000` 步局仍按 `1000` 步的时间惩罚节奏被压制

### 方向 2：终局奖励按步数尺度归一化

当前终局奖励：

- `WIN`
- `FAIL`

虽然用了 `cleaning_ratio`，但训练本身可能仍更偏短局节奏。

后续建议：

- 在长局中更强调“中后段持续效率”
- 不是只在终局一次性结算

### 方向 3：针对 `2000` 步局增加中后段效率信号

目前模型可能更容易学会：

- 别死
- 多回桩

但不容易学会：

- 在长局里持续高效清扫

因此后续需要引入更强的：

- 中后段有效清扫奖励
- 中后段探索收益

## 6. go03 对 planner 的判断

go03 不是完全不改 planner，而是：

- planner 不再是第一优先级

当前最合理的定位是：

- planner 保持 baseline 主逻辑
- 只做非常小的、已证明有效的条件化

不建议继续：

- 不断堆回桩 margin
- 不断前移低电量阈值

因为 `go02` 已经说明，这条路径收益有限。

## 7. go03 的实施建议

### 第一步：先固定训练模式

在真正改 reward 前，先决定：

- 是走单独 `2000` 训练
- 还是继续混训

推荐：

- 先单独 `2000`

### 第二步：补统计分桶

不管选哪条路线，都要补：

- `1000 / 2000` 分桶统计

### 第三步：优先改 reward，不优先继续改 planner

如果统计显示：

- `2000` 局始终高波动
- 成功局和失败局差异主要来自后半段效率

那就优先改 reward。

### 第四步：最后再决定是否恢复混训

如果 `2000` 单训稳定了，再恢复混训，才更有意义。

## 8. go03 成功标准

go03 的成功标准不是立即让整体均值上升，而是：

1. 能明确区分问题来自 `1000` 还是 `2000`
2. `2000` 步局的失败模式得到收敛
3. 双步数训练不再是“平均后看不清”的状态
4. 后续调参能明确知道自己在修哪一类问题

## 9. 结论

`go02` 没明显提升，说明当前问题不该继续按“调长局回桩阈值”理解。

更合理的方向是：

- **重组双步数训练方式**
- **补分桶统计**
- **优先考虑 reward 的步数尺度条件化**

所以 go03 应该被定义为：

- **双步数训练重组方案**

而不是 planner 参数的继续微调版。

## 10. 本轮实际落地

本轮按 go03 的第一步落地：

- 暂停 `1000 / 2000` 混训
- 改成固定 `2000` 步训练
- 不改 reward
- 不改 planner 额外阈值
- 不改网络结构

### 10.1 修改文件

- `code/agent_ppo/conf/train_env_conf.toml`
- `agent_ppo/conf/train_env_conf.toml`
- `code/agent_ppo/workflow/train_workflow.py`
- `agent_ppo/workflow/train_workflow.py`

### 10.2 实际改动

#### 训练环境配置

将训练配置里的：

```toml
max_step = 1000
```

改为：

```toml
max_step = 2000
```

#### workflow 调度逻辑

删除混训调度：

```python
self.max_step_schedule = (1000, 1000, 2000)
```

并改为直接使用配置文件中的：

```python
env_conf["max_step"]
```

也就是说：

- 当前训练不再在 `1000 / 2000` 间切换
- 而是固定跑 `2000` 步局

### 10.3 这样做的目的

这一步的目标不是提升整体均值，而是先回答一个更基础的问题：

- 模型在单独 `2000` 步训练下，是否能形成稳定的长局策略？

只有先把这一点确认下来，后面才有必要考虑是否重新回到混训。

### 10.4 当前边界

这一轮仍然没有做：

- `1000 / 2000` 分桶监控增强
- reward 的步数尺度条件化
- planner 更深层的 `max_step` 参数化

所以当前 go03 的定位是：

- 先把长局单独训稳
- 再决定是否继续往 reward 条件化推进
