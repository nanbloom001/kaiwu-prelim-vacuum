# go16-1

目标：在不改 planner 状态机的前提下，继续降低 `charge` 模式下的小概率暴毙，特别是当前日志中这类：

- `steps=278 result=FAIL mode=charge`

同时尽量不破坏当前已经形成的高分稳定性与训练链路稳定性。

---

## 1. 当前问题结论

基于 `2026-04-24` 最新训练日志，当前策略已经具备：

- learner 正常训练，未再出现全局卡死
- 大多数局能够稳定 `WIN`
- 分数常见在 `880~925`
- 多充电桩利用已经明显存在，`charger_arrivals=2/3` 已经比较常见

但当前仍有一个尚未解决的核心问题：

- **`charge` 模式下仍然存在低频但高损失的失败局**

典型表现：

1. 少数局会在进入 `charge` 模式后中途暴毙
2. 失败步数常落在 `150~300` 或中后期回充边缘区间
3. 某些地图上回充触发仍偏晚，导致一旦进入危险区就没有足够冗余

所以 `go16-1` 的目标不是“重新设计策略”，而是：

- **在 go15 的基础上，把安全边界再向前轻推一步**

---

## 2. 方案原则

`go16-1` 明确遵守以下约束：

1. 不改 planner 状态机
   - 不新增历史记忆变量
   - 不新增黑名单
   - 不新增换桩逻辑
2. 不改网络结构
3. 不改 PPO 主超参
4. 不大改 reward 主体结构
5. 只调两个无状态安全边界：
   - reward 去毒阈值
   - residual alpha 强接管阈值

这样做的原因很明确：

- 当前最大风险不是“策略不会学”
- 而是“为了修复少量 charge 失败，再次引入复杂状态逻辑导致卡死”

---

## 3. go16-1 方案

### 3.1 轻微提前 starvation 区间

当前 go15 的 starvation 条件是：

```python
battery <= nearest_charger_dist + 18
```

`go16-1` 建议改为：

```python
battery <= nearest_charger_dist + 20
```

含义：

- 当剩余电量距离“最近已知充电桩路径距离”只多出 20 步以内时
- 认为已经进入高风险期
- 提前切断清扫/探索诱惑

设计理由：

- 当前失败局说明 `+18` 对部分地图仍然偏紧
- 只前移 `2` 步，属于很小的保守增强
- 不至于像大幅提前那样过度压制探索

---

### 3.2 轻微增强硬接管区间

当前 go15 的强接管是：

```python
if battery <= charger_distance + 12:
    alpha = 0.0
elif battery <= charger_distance + 18:
    alpha = min(alpha, 0.002)
```

`go16-1` 建议改为：

```python
if battery <= charger_distance + 14:
    alpha = 0.0
elif battery <= charger_distance + 20:
    alpha = min(alpha, 0.002)
```

含义：

- 在“已经接近生死线”的回充阶段
- 更早把控制权完全交给 planner
- 在稍宽一点的危险带里，进一步压低 residual policy 的扰动

设计理由：

- 当前失败仍集中在 `mode=charge`
- 说明 RL 在“已经该完全回家”的阶段仍保留了少量错误空间
- 只增加 `2` 步安全窗，风险可控

---

### 3.3 保持 step penalty 放大倍数不变

当前 go15：

```python
step_penalty *= 2.5
```

`go16-1` 建议：

- **保持 `2.5` 不变**

原因：

1. 当前主要矛盾更像“触发偏晚”，不是“惩罚不够重”
2. 再提高惩罚强度，更容易让 reward 分布变硬
3. 这可能带来 value 抖动，得不偿失

---

### 3.4 保持 charge cap 不变

当前普通 `charge` 模式仍保留：

```python
RESIDUAL_ALPHA_CHARGE_CAP = 0.010
```

`go16-1` 建议：

- **不改**

原因：

- 当前大量 `mode=charge` 的回合已经能正常赢
- 说明整体 charge 策略并没有全面失控
- 问题只出现在极端边界，不需要把整个 charge 模式继续锁死

---

## 4. 预期效果

如果 `go16-1` 有效，预计会看到：

1. `charge` 模式 `FAIL` 次数进一步下降
2. `150~300` 步的早死局减少
3. `remaining_charge=0` 的失败局减少
4. 某些波动图（如地图 `1 / 5`）的极低分回合减少
5. 大多数高分局仍保持在当前区间，不明显掉分

---

## 5. 重点观察指标

下一轮训练建议重点看：

- `mode=charge` 的 `FAIL` 次数
- `steps < 400` 的失败局数量
- `charger_arrivals=0/1` 的失败占比
- `remaining_charge=0` 的回合数量
- `avg_score`
- `1000` 步完赛率

真正说明 `go16-1` 生效的标志是：

1. charge 失败数下降
2. 早死局减少
3. 总体分数不回退
4. 训练链路仍保持当前稳定状态

---

## 6. 本轮明确不做的事

`go16-1` 明确不包含以下内容：

1. 不增加新的 planner 状态变量
2. 不修改 `_plan_path_to_charger()`
3. 不引入自动换桩逻辑
4. 不改 PPO 超参
5. 不改 reward 主体结构
6. 不改网络输入维度或模型结构

这些内容都属于更高风险改动，不适合在当前“已经基本稳定，只剩低频 charge 暴毙”阶段继续叠加。

---

## 7. go16-1 结论

`go16-1` 是一个非常小的保守微调版：

- 把 go15 的 reward 去毒阈值从 `+18` 调到 `+20`
- 把 go15 的 alpha 强接管窗口整体前移 `2` 步
- 其余全部不动

一句话概括：

- **继续压 charge 暴毙，但不再冒引入新卡死逻辑的风险。**
