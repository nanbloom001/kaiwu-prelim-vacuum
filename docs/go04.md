# go04

目标：面向真实验收场景，设计单模型在**未知配置**下的泛化训练方案。

当前已知，验收时以下配置都可能变化：

- `robot_count: 1~4`
- `charger_count: 1~4`
- `max_step: 1~2000`
- `battery_max: 100~999`

因此 go04 的核心目标不是“固定配置最优”，而是：

- 同一个模型在不同配置组合下都尽量稳定
- 最差配置不塌局
- 整体 success rate 尽可能高
- 平均分尽可能高

本文件原始版本是方案设计；当前已完成第一轮代码落地，并补充了分桶验证工具。

## 1. 为什么需要 go04

在 go01/go02/go03 阶段，我们已经验证了几件事：

1. 双步数训练本身是可以跑起来的
2. `2000` 步局中存在高分成功局
3. 但固定 `2000` 单训也并不能自然解决长局稳定性问题

这说明：

- 真实问题不只是“如何适配 2000 步”
- 而是“如何适配未知配置”

如果验收时配置未知，那么后续路线就不能再围绕：

- 单独优化 `1000`
- 单独优化 `2000`
- 单独优化 `4 charger`

而必须转成：

- 多配置训练
- 条件感知特征
- 条件化 planner
- 比例化 reward

## 2. go04 的总体原则

go04 的总原则是：

1. 训练分布覆盖真实验收配置变化
2. 模型显式感知环境配置
3. planner 不再是固定常量逻辑，而是条件化规则
4. reward 逐步从绝对尺度转为比例尺度
5. 验证不再只看整体均值，而必须按配置桶拆分

## 3. 训练分布设计

## 3.1 必须覆盖的配置维度

训练时必须覆盖：

- `robot_count ∈ {1,2,3,4}`
- `charger_count ∈ {1,2,3,4}`
- `max_step ∈ {1000,2000}` 起步
- `battery_max` 先按分桶采样

### battery_max 建议分桶

第一阶段不建议直接 `100~999` 连续随机，而建议先做分桶：

- 低电量桶：`150~250`
- 中电量桶：`251~500`
- 高电量桶：`501~999`

原因：

- 连续随机范围太大，训练和诊断都会变得困难
- 分桶更容易观察泛化能力是否形成

## 3.2 推荐训练阶段

### 阶段 A：代表性组合覆盖

先不做全随机，而是用代表性组合训练，例如：

- `robot_count`: `1 / 2 / 4`
- `charger_count`: `1 / 2 / 4`
- `max_step`: `1000 / 2000`
- `battery_max`: `200 / 400 / 800`

这样可以快速覆盖：

- 稀疏资源
- 中等资源
- 充足资源
- 短局
- 长局

### 阶段 B：均衡采样

在阶段 A 基本稳定后，切换到更接近真实验收的训练方式：

- 每局随机采样组合
- 但要求组合分布尽量均衡

目标是避免训练长期偏向默认配置。

### 阶段 C：极端组合压测

重点提高最差情况表现，尤其关注：

- `robot_count=4`
- `charger_count=1`
- `max_step=2000`
- `battery_max` 较低

这类组合最容易暴露泛化缺陷。

## 4. 模型输入设计

## 4.1 必须补的配置感知特征

当前已经有：

- `max_step_norm`
- `step_ratio`

go04 继续建议新增：

- `robot_count_norm`
- `charger_count_norm`
- `battery_max_norm`

### 目标

让模型知道：

- 当前官方机器人数量多不多
- 当前 charger 是稀疏还是充足
- 当前电池容量是低、中还是高
- 当前局是短局还是长局

如果模型看不到这些，它就只能“盲打”，泛化会很差。

## 4.2 建议增加的派生特征

后续可以继续扩展：

- `observed_charger_ratio`
- `return_pressure`
- `time_pressure`
- `charger_density_hint`
- `battery_to_step_budget_ratio`

这些特征的目的，是让模型学到：

- 当前环境资源是否紧张
- 当前阶段是否该继续外扩
- 当前是否必须转入保命回桩

## 5. planner 设计方向

## 5.1 当前 planner 的问题

当前 planner 的很多阈值，仍然是固定常量，例如：

- `BASE_RETURN_MARGIN`
- `LOW_BATTERY_RATIO`
- `EXIT_RETURN_RATIO`
- `AGGRESSIVE_EDGE_STEPS`

这在固定配置下可以调优，但在多配置场景下会失效。

## 5.2 go04 的 planner 原则

不是为某个固定配置写死一套规则，而是：

- 根据当前配置动态调整

### 最优先条件化的规则

1. 回桩 margin
2. 低电量阈值
3. 充满退出阈值
4. 扩张阶段长度

### 条件来源

建议条件化依赖：

- `robot_count`
- `charger_count`
- `max_step`
- `battery_max`

### 原则

- `robot_count` 越多：越保守
- `charger_count` 越少：越保守
- `battery_max` 越低：越保守
- `max_step` 越长：前中期允许更长探索，但后段必须更稳定收尾

## 6. reward 设计方向

## 6.1 当前 reward 的局限

当前 reward 主要是在固定 `1000` 步与固定 `battery_max` 背景下长出来的。

因此在配置变化后，以下项的相对意义会变化：

- `step_penalty`
- 低电量惩罚
- 充电 sweet zone
- 终局奖励

## 6.2 go04 的 reward 原则

reward 后续应逐步从“绝对值驱动”改成“比例驱动”。

更应该依赖：

- `battery_ratio`
- `step_ratio`
- `cleaning_progress`
- `return_pressure`

而不是固定绝对阈值。

## 6.3 优先建议的 reward 改动

### 方向 1：step penalty 条件化

当前 step penalty 更像短局尺度。

建议未来改成：

- `1000` 步局保持相近节奏
- `2000` 步局放缓对前中期步数的惩罚

### 方向 2：长局中后段效率奖励

让模型在：

- `step_ratio > 0.5`

后，若仍持续有效清扫，获得额外正向信号。

### 方向 3：长局回桩失败惩罚更明确

如果：

- 长局后半段
- 因 `charge` 模式失败

则应有更清晰的负反馈，避免模型反复学到低效回桩路径。

## 7. 训练组织建议

## 7.1 不再长期固定单配置

go03 的固定 `2000` 单训适合诊断，不适合作为最终主线。

go04 最终应回到多配置训练，但必须是：

- 有组织的多配置训练
- 而不是简单混合

## 7.2 推荐训练组织方式

### 方案 A：组合分桶轮换

每若干局切一个配置桶，例如：

- 一段时间集中训练低 charger 组合
- 一段时间集中训练高 robot_count 组合
- 一段时间集中训练长局

优点：

- 曲线可读性更好
- 易于分析退化来源

### 方案 B：均衡随机

等系统成熟后，切换到：

- 按组合均衡随机采样

这是更接近真实验收的方式。

## 8. 验证体系设计

## 8.1 必须分桶统计

后续不能只看整体 `avg score`。

至少按以下维度拆：

- `robot_count`
- `charger_count`
- `max_step`
- `battery_max bucket`

## 8.2 每个桶要看什么

每个配置桶都要看：

- success rate
- avg score
- avg finished_steps
- charge_count
- remaining_charge
- fail mode

## 8.3 优先看地板

因为你的目标是：

- 未知配置下单模型尽可能最优

所以最关键的不是均值，而是：

- 最差桶不要崩
- 极端配置下也不能大面积塌局

## 9. go04 成功标准

go04 的成功标准不是某一个配置特别高分，而是：

1. 不同 `robot_count` 下 success rate 都较稳
2. 不同 `charger_count` 下没有明显塌局桶
3. `1000 / 2000` 步局都能形成合理节奏
4. `battery_max` 变化不会导致大幅失控
5. 整体均值提升，同时最差配置桶也提升

## 10. 结论

既然验收时：

- `robot_count`
- `charger_count`
- `max_step`
- `battery_max`

都可能变化，那么后续所有优化都必须服从一个目标：

- **泛化优先于单配置最优**

因此 go04 应定义为：

- **未知配置泛化训练方案**

它不是某个单一参数的微调，而是一套完整的多配置训练、特征、planner、reward、验证体系的升级方向。

- `effective_return_margin`

- `effective_aggressive_edge_steps`

方向原则是：

- `robot_count` 越多：更保守
- `charger_count` 越少：更保守
- `battery_max` 越低：更保守
- `max_step` 越长：更保守地建立安全闭环

### 11.6 分桶验证工具

新增脚本：

- `verify_bucket_summary.py`

当前功能：

- 解析 `train/log/aisrv` 中的 `Episode start / GAMEOVER`
- 按以下配置桶汇总：
  - `robot_count`
  - `charger_count`
  - `max_step`
  - `battery_max`
- 输出：
  - success rate
  - avg score
  - avg steps
  - min score
  - min steps
- 同时单独列出失败局清单

用途：

- 后续不再只看整体均值
- 可以直接定位是哪一类配置组合在拖累整体表现

所以这一轮属于：

- 先把训练分布和特征空间扩起来
- 让模型有机会学习未知配置
- 但 reward 和验证体系还没完全跟上
