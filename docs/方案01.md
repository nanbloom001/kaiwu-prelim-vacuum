# 清扫大作战强化学习训练执行方案（现阶段仅方案，不改代码/配置）

## 0. 多 Agent 分工结论
- Agent-规则分析：提炼赛题目标、约束、终止条件与评分机制。
- Agent-工程分析：梳理仓库当前可运行入口与 PPO/DIY 差异。
- Agent-策略设计：输出分阶段训练策略、评估指标、风险与迭代机制。

本方案基于当前仓库事实：`code/train_test.py` 可跑，`agent_ppo` 为可训练骨架，`agent_diy` 仍是模板占位（大量 `pass`）。

## 1. 任务目标与约束（必须对齐）
- 目标：最大化玩家机器人清扫格数（官方机器人清扫不计分）。
- 终止：达到 `max_step`（completed）或电量耗尽/碰撞 NPC（failed）。
- 关键约束：
  - 观测是 21×21 局部视野，动作 8 离散方向。
  - 每步耗电 1；撞障碍或非法斜走会原地不动但仍耗步耗电。
  - 进入 NPC 的 3×3 范围即失败。
  - 评测含隐藏地图，必须做泛化，不可只对单图过拟合。

## 2. 当前工程基线判断
- 可直接使用入口：`code/train_test.py`（算法可切 `ppo`/`diy`）。
- 当前主线建议：优先 `ppo`。
  - 原因：`agent_ppo` 含完整 `agent/algorithm/workflow/sample_process`。
  - 风险：当前 `agent_ppo` 是“blank ppo”占位实现（特征维度 1、动作维度 2、reward=0），不具备赛题有效性。
- `diy` 现状：`agent.py`、`feature/definition.py`、`workflow/train_workflow.py` 为模板，不适合当前阶段直接训练。

## 3. 分阶段训练路线（执行顺序）
## Phase A：基线可运行性验证（1-2 天）
- 目标：确认训练链路稳定、日志可读、模型能周期保存。
- 操作：
  - 本地仅运行 `python train_test.py`（不改参数）。
  - 记录每局：`episode_steps`、`reward`、是否 terminated/truncated。
  - 核查模型保存节奏（工作流默认约 30 分钟触发保存）。
- 通过标准：
  - 无崩溃、无配置校验错误、可持续采样与学习。

## Phase B：特征设计方案冻结（2-3 天）
- 目标：先定义“该看什么”，再进入编码。
- 特征优先级（从高到低）：
  - 电量安全：当前电量比、到最近充电桩路径距离/方向。
  - 风险感知：最近 NPC 距离、相对方向、近邻危险标记。
  - 清扫收益：局部污渍密度、前方可达污渍距离、重复访问惩罚信号。
  - 泛化支持：地图级粗栅格清扫进度（低分辨率全局记忆）。
- 产出：一版固定特征字典（字段名、维度、归一化方式、更新频率）。

## Phase C：奖励设计方案冻结（2-3 天）
- 目标：构建“主目标 + 安全 + 效率”的可调奖励体系。
- 建议结构：
  - 主奖励：新增清扫格数（核心权重最高）。
  - 时间成本：每步小惩罚（抑制空转）。
  - 生存约束：接近 NPC 距离惩罚（分段或平滑）。
  - 能量管理：低电量下朝充电桩接近给正奖励；低电量远离给负奖励。
  - 终局奖励：失败（碰撞/耗电）额外惩罚，completed 轻微正奖励。
- 产出：奖励表（触发条件、公式、权重初值、可调范围）。

## Phase D：监控与评估闭环（持续）
- 训练监控最小集：
  - 学习侧：`total_loss/policy_loss/value_loss/entropy_loss/reward`。
  - 环境侧：`clean_score`、`finished_steps`、`remaining_charge`、`charge_count`。
  - 失败结构：碰撞失败率、耗电失败率、completed 占比。
- 评估指标（主看）：
  - 平均清扫分、P50/P90 清扫分。
  - 存活步数占比（`finished_steps / max_step`）。
  - 单位步收益（score per step）。
  - 跨地图方差（泛化稳定性）。
- 评估切片：
  - 地图维度：训练图逐图统计 + 未见图模拟。
  - 场景维度：低电量段、NPC 高密区、障碍狭窄区。

## 4. 迭代节奏与里程碑
- 每轮迭代只改一个主因素（特征或奖励或模型其一），避免耦合。
- 推荐节奏：每日 1 轮小迭代，每 3-4 轮做一次回归评估。
- 里程碑：
  - M1：稳定跑通 + 指标看板齐全。
  - M2：失败率显著下降（先解决“活下来”）。
  - M3：清扫效率提升（再追求“扫得多”）。
  - M4：多地图方差收敛（最后追求“泛化稳”）。

## 5. 常见失败模式与预案
- 失败模式：早期碰撞多。
  - 预案：提高风险惩罚权重，加入“危险半径分层”特征。
- 失败模式：没电失败多。
  - 预案：增加低电量回充奖励，监控“低电量状态占比”。
- 失败模式：原地/回头路多。
  - 预案：加入访问记忆与重复惩罚，观察单位步收益变化。
- 失败模式：单图高分、多图崩溃。
  - 预案：固定多地图评估基线，按地图报告方差，不以单图峰值决策。
