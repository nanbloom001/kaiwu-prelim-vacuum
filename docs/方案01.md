# 清扫大作战（Robot Vacuum）赛题解决方案

## 1. 赛题背景与理解

### 1.1 问题描述
清扫大作战是一个基于网格地图的清扫机器人控制问题。机器人需要在有限的电量和步数限制内，尽可能高效地清扫地图上的污渍。

### 1.2 环境特点
- **地图规格**: 128×128 的网格地图
- **观测范围**: 机器人拥有 21×21 的局部视野（以自身为中心）
- **动作空间**: 8个方向移动（上下左右 + 四个对角线）
- **资源限制**:
  - 电量上限：600
  - 最大步数：2000
- **地图元素**:
  - 0: 障碍物（不可通行）
  - 1/2: 可通行区域（2表示有污渍）

### 1.3 目标
在电量耗尽或步数用尽之前，最大化清扫的污渍数量。

---

## 2. 解决方案概述

### 2.1 算法选择：PPO（Proximal Policy Optimization）

选择 PPO 作为主要算法，原因如下：
1. **稳定性**: PPO 通过 clipped surrogate objective 限制策略更新幅度，训练更稳定
2. **样本效率**: 支持多轮 epoch 更新，充分利用采集样本
3. **工程成熟**: 在离散动作空间的网格世界问题中表现优异
4. **调参友好**: 超参数相对不敏感，易于调试

### 2.2 整体架构

```
┌─────────────────────────────────────────────────────────┐
│                     Agent (PPO)                         │
├─────────────────────────────────────────────────────────┤
│  Observation Process → Model Forward → Action Process  │
│                                                          │
│  ┌──────────────┐    ┌──────────────┐    ┌──────────┐  │
│  │ Feature      │ →  │ MLP Network  │ →  │ Action   │  │
│  │ Preprocessor │    │ (Actor-Critic)│    │ Sampling │  │
│  │ (69D input)  │    │              │    │          │  │
│  └──────────────┘    └──────────────┘    └──────────┘  │
└─────────────────────────────────────────────────────────┘
                           ↓
┌─────────────────────────────────────────────────────────┐
│                   Algorithm (PPO Loss)                  │
│                                                          │
│  Loss = vf_coef × Value_Loss + Policy_Loss - β × Entropy│
└─────────────────────────────────────────────────────────┘
```

### 2.3 本次改进要点（避障 + 电量 + 充电桩规划）
- **开局即找桩建图**：启动后先在 21×21 视野内搜索最近充电桩，做一次 A*/BFS 估计，记录“到桩最短路长度 + 安全冗余”作为最低剩余电量阈值。
- **安全能量护栏**：行进中实时比较 `battery - (distance_to_charger + buffer)`，低于 0 立即切换“回桩模式”，保证途中不掉电。
- **官方机器人避碰**：把官方机器人当作动态障碍，使用最近距离 + 相对速度预测 8～12 步的潜在冲突，动态扩大其安全半径并在路径规划中提高代价。
- **充电桩周围条带清扫**：充满电后优先在桩周围执行“直线条带”模式（如向左 99 步→上 1 步→向右 99 步→回桩），减少绕圈，先扫净桩周再去下一个桩。
- **分层控制**：高层规则/规划（选桩、护栏、避碰限制）+ 低层 PPO 学习（微调动作分布），规则可直接屏蔽危险动作，保证安全。

## 3. 网络架构设计

### 3.1 模型结构
采用双头 MLP（Actor-Critic）架构：

```
Input (69D)
    ↓
FC(69 → 128) + ReLU
    ↓
FC(128 → 64) + ReLU  ← Shared Backbone
    ↓
┌─────────────┴─────────────┐
↓                           ↓
FC(64 → 8)              FC(64 → 1)
Actor Head              Critic Head
(Logits)                (State Value)
```

### 3.2 初始化策略
- 使用 **Orthogonal Initialization** 初始化全连接层权重
- Actor 和 Critic 输出层 gain=0.01（保守初始化，训练初期策略更随机）
- 偏置初始化为 0

### 3.3 设计理由
- **共享 backbone**: 提取通用的状态表示，减少参数数量
- **128→64 维度**: 在表达能力与计算效率之间取得平衡
- **ReLU 激活**: 计算简单，缓解梯度消失问题

## 4. 特征工程

### 4.1 特征构成（共 82 维）

| 特征组 | 维度 | 说明 |
|--------|------|------|
| 局部视野 | 49D (7×7) | 从 21×21 视野中心裁剪，归一化到 [0, 1] |
| 全局状态 | 15D | 原 12D + 充电桩/能量 3 项 |
| 动态避碰 | 10D | 官方机器人最近距离/相对速度 + 危险动作掩码 |
| 合法动作 | 8D | 当前状态下可执行的动作掩码 |

### 4.2 全局状态特征详解（15D）

| 维度 | 特征名 | 说明 |
|------|--------|------|
| 0 | step_norm | 步数归一化 [0, 1] |
| 1 | battery_ratio | 电量比例 [0, 1] |
| 2 | cleaning_progress | 已清扫比例 [0, 1] |
| 3 | remaining_dirt | 剩余污渍比例 [0, 1] |
| 4 | pos_x_norm | X 坐标归一化 [0, 1] |
| 5 | pos_z_norm | Z 坐标归一化 [0, 1] |
| 6-9 | ray_N/E/S/W_dirt | 四方向射线最近污渍距离 |
| 10 | nearest_dirt_norm | 最近污渍欧氏距离归一化 |
| 11 | dirt_delta | 是否正在接近污渍（1=是）|
| 12 | nearest_charger_dist_norm | 最近充电桩的路径长度（A*/BFS）归一化 |
| 13 | charger_buffer_gap | `battery - (path_len + safety_buffer)` 归一化，<0 表示必须回桩 |
| 14 | charger_direction_angle | 充电桩方位角的 sin/cos 压缩编码 |

### 4.3 动态避碰特征（10D）
- **other_bot_min_dist (1D)**：视野内官方机器人最小距离
- **other_bot_rel_speed (1D)**：最近机器人的径向相对速度（预测交汇）
- **danger_action_mask (8D)**：若某动作会使距离官方机器人低于安全半径，则置 0；训练/推理都乘后重新归一化

### 4.4 关键设计点

**射线特征（Ray Casting）**
- 向四个正方向发射射线，检测最近污渍距离
- 最大检测距离 30 格，超出则为最大值
- 帮助机器人感知“前方是否有污渍”

**dirt_delta 特征**
- 记录最近污渍距离的变化趋势
- 引导机器人向污渍靠近，避免盲目移动

**充电桩与能量护栏**
- `nearest_charger_dist_norm` + `charger_buffer_gap` 让策略学会区分“可以继续扫”与“必须回桩”
- 角度编码让 PPO 更容易学会直线回桩或绕障回桩

**官方机器人避碰**
- `other_bot_min_dist` 与 `danger_action_mask` 组合，显式压低潜在碰撞动作概率
- 相对速度特征允许提前 8～12 步预测交汇，减少贴脸才转向的情况

## 5. 奖励设计（Reward Shaping）

### 5.1 改进后的奖励函数

```python
reward = cleaning_reward \
         + step_penalty \
         + straight_bonus \
         + charger_safety_bonus \
         + collision_penalty
# 清扫奖励
cleaning_reward = 0.1 * cleaned_this_step
# 时间惩罚
step_penalty = -0.001
# 直线条带奖励：连续直线行走 >= k 步给一次 0.02 奖励，弯折重置
straight_bonus = 0.02 * I(consecutive_straight_steps >= k)
# 能量安全奖励：回桩模式且 buffer_gap>0，每步 +0.005，鼓励及时回桩
charger_safety_bonus = 0.005 * I(buffer_gap>0 and in_return_mode)
# 碰撞/逼近惩罚：与官方机器人距离 < R_penalty 时线性惩罚；实际碰撞 -1
collision_penalty = -0.05 * clip(R_penalty - dist_other_bot, 0, R_penalty) - I(collide)*1.0
```

### 5.2 设计意图
- **直线条带奖励**：减少小圆圈，鼓励大范围“割草机”式覆盖
- **能量安全奖励**：把“安全回桩”视为积极目标而非被动惩罚
- **避碰惩罚**：显式区分“靠得太近”与“真正碰撞”，让策略提前绕行

### 5.3 参数建议
- `k` 取 6～10（匹配 99 步长条带的子段），`R_penalty` 取 2.5～3.5
- `safety_buffer` 建议 `8 + 0.2 * nearest_charger_dist`，兼顾不确定性

## 6. 训练策略

### 6.1 PPO 超参数

| 参数 | 值 | 说明 |
|------|-----|------|
| γ (GAMMA) | 0.99 | 折扣因子，重视长期回报 |
| λ (LAMDA) | 0.95 | GAE 参数，平衡偏差与方差 |
| ε (CLIP_PARAM) | 0.2 | PPO 裁剪参数 |
| vf_coef | 0.5 | 价值损失系数 |
| β (entropy) | 0.001 | 熵正则系数，鼓励探索 |
| 学习率 | 3e-4 | Adam 优化器初始学习率 |
| 梯度裁剪 | 0.5 | 防止梯度爆炸 |

### 6.2 GAE（Generalized Advantage Estimation）

使用 GAE(λ) 计算优势函数，平衡价值估计的偏差与方差：

```
A_t = δ_t + (γλ)δ_{t+1} + (γλ)²δ_{t+2} + ...
where δ_t = r_t + γV(s_{t+1}) - V(s_t)
```

### 6.3 动作采样策略

- **训练时**: 按概率分布随机采样（exploration），但先与 `danger_action_mask` 相乘后再归一化，防止学习到“撞官方机器人”
- **评估时**: 取概率最大的动作（exploitation），若 mask 为 0 则选择次高概率动作

### 6.4 合法动作掩码

- 环境会返回当前状态下的合法动作列表
- 在 softmax 前将非法动作的概率置为极小值
- 确保不会选择会导致碰撞等非法行为的动作

### 6.5 分层控制与模式切换
- **高层规则**：最近充电桩规划、能量护栏、避碰半径、条带模式开关
- **低层 PPO**：在规则过滤后的动作分布上采样，负责细粒度绕障与微调
- **模式切换**：
  - `回桩模式`：当 `charger_buffer_gap < 0` 或电量低于阈值，执行 A* 回桩；若前方有官方机器人则尝试平行绕行
  - `条带清扫模式`：充满电后在当前桩周边做“往返直线”，遇到障碍/机器人时切换短期绕障，再回到条带
  - `探索模式`：桩周围清扫度 ≥90% 或多次回到同一路径时，规划到下一个最近桩

## 7. 实验计划

### 7.1 基线实验（Baseline）

直接使用当前 PPO 实现，验证基本收敛性：

```bash
python train_test.py
# 修改 algorithm_name = "ppo"
```

### 7.2 评估指标

1. **清扫率**: cleaned / total_dirt
2. **平均回合长度**: 每局游戏实际步数
3. **电量利用率**: 清扫率 / (1 - battery_ratio)
4. **收敛速度**: 达到目标清扫率所需的训练步数

### 7.3 消融实验

| 实验 | 修改内容 | 目的 |
|------|----------|------|
| Exp 1 | 去掉射线特征 | 验证射线特征有效性 |
| Exp 2 | 网络 128→64→32 | 测试模型容量影响 |
| Exp 3 | 增大熵系数到 0.01 | 测试探索强度影响 |
| Exp 4 | 增加接近奖励 | 验证奖励 shaping 效果 |

## 9. 风险与应对

| 风险 | 可能性 | 应对策略 |
|------|--------|----------|
| 训练不稳定 | 中 | 降低学习率，增大 batch size，使用梯度裁剪 |
| 局部最优 | 高 | 增大熵系数，添加更多探索奖励 |
| 过拟合 | 低 | 早停，降低模型容量，增加训练地图多样性 |
| 样本效率低 | 中 | 使用 priority replay，多环境并行采样 |

---

## 10. 总结

本方案采用 **PPO 算法** 解决清扫大作战问题，核心设计包括：

1. **双头 MLP 网络**: 共享特征提取 + 独立策略/价值输出
2. **82D 特征向量**: 局部视野 + 全局状态 + 充电桩/能量护栏 + 官方机器人避碰 + 合法动作掩码
3. **GAE 优势估计**: 平衡偏差与方差
4. **改进奖励 shaping**: 清扫 + 时间惩罚 + 直线条带 + 能量安全 + 避碰惩罚

后续将通过系统性的消融实验和迭代优化，逐步提升清扫效率和策略鲁棒性。
