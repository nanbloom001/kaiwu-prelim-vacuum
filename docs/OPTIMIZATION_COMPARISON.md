## 详细对比

### 对比 1: 行为优先级权重 (第 389-415 行)

#### 充电权重计算
```python
# ❌ 原版本
charger_weight = float(np.clip((0.55 - battery_ratio) / 0.35, 0.0, 1.0))

# ✅ 优化版本  
charger_weight = float(np.clip((0.60 - battery_ratio) / 0.35, 0.0, 1.0))
```

**变化分析**:
```
电量 50% 时的权重:
- 原: (0.55 - 0.50) / 0.35 = 0.143  (较低，不会主动充电)
- 新: (0.60 - 0.50) / 0.35 = 0.286  (明显提升，会启动充电)
  → 权重提升 100% ✓

电量 40% 时的权重:
- 原: (0.55 - 0.40) / 0.35 = 0.429  (才开始有成效)
- 新: (0.60 - 0.40) / 0.35 = 0.571  (更强的充电意识)
  → 权重提升 33% ✓
```

## 改动的设计思想

### Why 充电权重从 0.55 → 0.60?
- 原来 50% 电量时权重才 0.14, 太晚
- 新版本 50% 时权重 0.29, 足够提醒
- 形成"提前60%就考虑 → 65%才退出"的充电闭环

### Why 触发阈值从 45% → 55%?
- 原来的 45% 触发太晚，电量已经危险
- 新的 55% 给充电过程充足的时间
- 避免因充电排队导致耗尽

### Why NPC 距离从 12→10?
- 5 格距离内是"危险距离" (秒杀范围)
- 10 格距离时开始躲避，给予充足反应空间
- 符合现实中的"预见性躲避"

### Why 躲避惩罚提升 50%?
- 原来的惩罚 (1.0) 不足以对抗吸引诱惑 (清扫奖励)
- 新的惩罚 (1.5) 能显著压制靠近 NPC 的倾向
- 极近距离额外惩罚 (2.0) 能彻底阻止接触

### Why 覆盖奖励从 0.07 → 0.10?
- 清扫奖励是 1.05/脏污, 非常大
- 覆盖奖励需要 40% 以上的强度才能抗衡
- 0.10 可以鼓励探索，但不会偏离清扫

## 风险评估

### ✅ 低风险
1. **奖励调整历来最稳妥** - 不涉及网络训练
2. **参数变化可控** - 都在合理范围内
3. **易于回滚** - 一行命令恢复原版
4. **向后兼容** - 旧 model checkpoint 可继续训练

### ⚠️ 可能的负面效果

| 潜在问题 | 表现 | 应对 |
|---------|------|------|
| reward 虚高但胜率低 | reward ↑ but win % 平 | 看 charge_success_cnt |
| 过度充电导致清扫降低 | clean_ratio ↓ | 调整权重系数 |
| 躲避过度导致无法清扫 | stuck_cnt ↑ | 降低躲避权重 |

### 监控指标 (快速诊断)
```
✓ charge_success_cnt - 应该 > 0.15
✓ near_npc_steps - 应该下降  
✓ clean_ratio - 应该 >= 当前
✓ stuck_cnt - 应该下降
✓ steps 分布 - 应该 > 200 的增加
```

## 总结

**改动本质**: 通过重新权衡奖励函数的各项系数，让智能体优先学会"续航管理"和"安全躲避"，然后在这个基础上优化"清扫覆盖"。

**改动方式**: 仅改数值，不改结构，最小化风险。

**预期效果**: 胜率从 0.9% → >= 5%, 充电成功率从 2.3% → >= 15%, 续航时间翻倍。

**验证周期**: 1-2 周可见效果，4 周可验证上限。
