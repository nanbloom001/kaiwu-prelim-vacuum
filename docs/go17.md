# go17

目标：在当前训练已经具备基本生存能力与部分高分能力的基础上，继续压缩“混合策略分布”，减少以下三种状态同时高频共存的现象：

1. 高质量局
   - `900+` 分
   - 多充电桩探索到位
   - `max_steps=1000`
2. 低效存活局
   - 可以跑满 `1000`
   - 但只到达 `1` 个充电桩
   - 分数通常落在 `700~850`
3. charge 崩溃局
   - 中途 `FAIL`
   - 多数发生在 `mode=charge`

`go17` 的目标不是“继续大改框架”，而是：

- **让策略更稳定地从“单桩可活”过渡到“多桩高效覆盖”。**

---

## 1. 当前问题结论

基于最新训练日志，当前策略已经不是“不会学”，而是进入了一个典型的混合分布阶段：

### 1.1 生存层

已有明显进步：

- 许多局可以稳定跑满 `1000`
- learner 正常训练
- 训练链路没有再出现全局卡死

但仍然存在：

- `mode=charge` 下的小概率暴毙
- 某些地图会在 `150~800` 步之间突然失败

### 1.2 效率层

更普遍的问题是：

- 虽然不少局能 `WIN`
- 但很多局仍然只有 `charger_arrivals=1`
- 说明策略停留在“近桩可活”而不是“多桩高效覆盖”

这会直接带来：

- 分数波动区间很大
- 跑满 `1000` 也未必高分
- 地图 4 这类“近桩 + 窄区 + 封闭热点”的局部最优反复出现

---

## 2. go17 核心判断

当前阶段最需要解决的，不是“第一个桩能不能找到”，而是：

1. **第二个桩是否能稳定到达**
2. **是否能尽快脱离单桩附近的局部热点循环**

换句话说：

- 现在的策略已经会充电
- 但还不会稳定地把多桩资源转化成高效覆盖

因此 `go17` 的重点是：

- 强化“第二桩到达”这件事
- 更快识别并惩罚“单桩附近无效打转”

---

## 3. 方案原则

`go17` 继续遵守低风险原则：

1. 不改网络结构
2. 不改 planner 状态机主逻辑
3. 不引入黑名单、换桩、复杂历史控制器
4. 只做：
   - reward 微调
   - 少量 charge 安全边界收紧
   - 少量 residual/planner 约束微调
   - 日志观测增强

这么做的原因是：

- 当前主要问题是行为偏好还没压缩
- 不是系统性结构错误
- 也不适合为了修复局部最优再引入高复杂状态逻辑

---

## 4. go17 方案总览

`go17` 包含四个主方向：

### 4.1 强化“第二桩到达”的奖励信号

不是继续平均加大奖励，而是按到达序号重新分配权重。

### 4.2 强化“靠近未到达桩”的接近信号

不仅奖励最终到达，也奖励“已经进入可接近区”的过程。

### 4.3 针对“局部热点循环”增加专项惩罚

不全局大幅加重复惩罚，而是精确打击“无探索、无清扫、但持续走旧路”的状态。

### 4.4 小步收紧 charge 安全边界

继续降低 charge 阶段的极限回家失败概率。

---

## 5. 具体方案设计

### 5.1 重新定义充电桩首次到达奖励

当前问题不是第一个桩难到，而是第二、第三个桩不稳定。

因此建议从“平均奖励”改成“按序号区分”：

```python
first_arrival  = 0.16
second_arrival = 0.30
third_arrival  = 0.24
```

再乘一个较缓的进度衰减：

```python
arrival_scale = max(0.62, 1.0 - 0.30 * cleaning_progress)
```

设计逻辑：

1. 第一个桩本来就容易到
   - 不需要再过强激励
2. 第二个桩才是打破“单桩吸附”的关键
   - 因此奖励最高
3. 第三个桩继续鼓励
   - 但略低于第二个桩
   - 避免出现“为了第三个桩而偏离主任务”的副作用

预期效果：

- 第二个桩首次到达率上升
- `charger_arrivals=1` 的局占比下降

---

### 5.2 增强“靠近未到达桩”的过程奖励

当前只奖励“最终到达”仍然不够。

`go17` 建议保留已有的 progress reward，并增加一个中距离接近 bonus：

```python
if has_unarrived_charger:
    if nearest_unarrived_dist < 18:
        bonus += 0.010
    if nearest_unarrived_dist < 10:
        bonus += 0.012
```

触发条件：

1. 当前仍存在未到达充电桩
2. 当前不在 starvation 区间
3. 当前不在充电桩上
4. 当前电量高于安全返航线

这样做的意义：

- 不再只奖励“已经到了”
- 还奖励“已经进入第二/第三个桩的可接近区域”
- 防止策略在快接近时又被局部旧路吸回去

---

### 5.3 新增“局部热点循环惩罚”

当前全局 `revisit_penalty` 虽然存在，但对热点打转的识别仍不够直接。

`go17` 建议增加一个专项惩罚：

```python
if cur_revisit_count >= 3 and new_observed_cells == 0 and cleaned_this_step == 0:
    loop_penalty = -0.010
else:
    loop_penalty = 0.0
```

再加限制：

- `not starving`

含义：

- 已经在重复位置
- 本步没有新探索
- 本步没有新增清扫
- 那基本可以判断是在无效打转

为什么不直接继续大幅提高全局 `revisit_penalty`：

- 因为正常回充和必要折返也会重复走路
- 全局加太猛会伤到正常路径
- 专项惩罚更适合当前问题

---

### 5.4 继续小步收紧 charge 安全边界

当前 `go16` 虽然已经前移了安全窗，但 `mode=charge` 的失败仍未完全消失。

`go17` 建议进一步微调：

```python
if battery <= charger_distance + 16:
    alpha = 0.0
elif battery <= charger_distance + 22:
    alpha = min(alpha, 0.001)
```

同时：

```python
is_starving = battery <= nearest_charger_dist + 22
```

设计逻辑：

- 当前 `+14 / +20` 仍留出少量误动作空间
- 再前移 `2` 步，属于可控的小步收紧
- 目标是减少 charge 阶段的 late decision 崩溃

---

### 5.5 保持 go16 的低风险优化项

`go17` 建议继续保留：

```python
PLANNER_PRIOR_TEMPERATURE = 0.54
BC_COEF_MIN = 0.28
```

不继续向更激进方向调。

原因：

- 当前问题核心不在优化器本身
- 继续大改优化项会增加归因难度

## 7. 预期效果

如果 `go17` 有效，预计会看到：

1. `charger_arrivals=1` 的 WIN 局明显减少

## 8. 风险与控制

### 风险 1：第二桩奖励过强，导致策略为桩而桩

控制方式：

- 第一桩奖励反而降低到 `0.16`
- 第二桩最高，第三桩次高
- 仍保留进度衰减

### 风险 2：热点循环惩罚误伤正常折返

控制方式：

- 只在“重复 + 无新图 + 无清扫”时触发
- 不使用全局粗暴大惩罚

### 风险 3：charge 边界继续前移后变得过保守

控制方式：

- 每次只前移 `2` 步
- 仍保持无状态规则，不引入新状态残留风险

---

## 9. 结论

`go17` 的一句话概括：

- **把“第二桩到达”提升为核心目标，同时更快识别并惩罚单桩附近的无效热点循环。**

这不是继续泛化地强化探索，而是更有针对性地压缩当前混合策略分布：

1. `go16` 解决的是“先活下来”
2. `go17` 解决的是“活下来之后，别只围着一个桩转”
