## 一、观测处理
环境返回的`observation`为智能体**局部观测信息**，通过`observation_process`函数完成处理，推荐使用内置预处理器`preprocessor`做标准化预处理。

### 核心处理函数
```python
def observation_process(self, env_obs):
    # 特征、合法动作、奖励预处理
    feature, legal_action, reward = self.preprocessor.feature_process(env_obs, self.last_action)
    # 封装观测数据
    obs_data = ObsData(
        feature=list(feature),
        legal_action=legal_action,
    )
    remain_info = {"reward": reward}
    return obs_data, remain_info
```

| legal_action | 8 | 8方向移动合法掩码（0-7对应8个移动方向），标记动作是否可执行 |
| **合计** | **69** | — |

## 三、奖励处理
基线版本采用**最简清扫奖励设计**，仅包含清扫奖励与步数惩罚，最终奖励为两项加权和。

### 基础奖励项
| 奖励项 | 含义 | 数值规则 |
|--------|------|----------|
| cleaning_reward | 每步清扫格子奖励 | +0.1 × 实际清扫格数 |
| step_penalty | 每步时间惩罚（鼓励高效清扫） | -0.001 |

### 最终奖励公式
$$reward = cleaning\_reward + step\_penalty$$

### 时序处理
使用**GAE算法**（配置参数：`Config.GAMMA`、`Config.LAMDA`）计算优势函数`advantage`与累计奖励`reward_sum`，作为PPO算法的训练目标。

## 五、算法详细说明
### 1. 模型设计（Actor-Critic架构）
基线采用**单MLP骨干+双头结构**，输入69维特征，输出动作概率与状态价值：
```
输入(69D) → MLP骨干(69→128→64) 
    → Actor头(64→8) ：输出动作logits（8个方向）
    → Critic头(64→1)：输出状态价值
```

### 2. 动作输出规则
- 动作空间：8维离散动作（仅移动方向0-7）
- 合法动作掩码：通过`legal_action`屏蔽非法动作（对非法动作logits赋予大负数，再做Softmax）
- 采样策略：训练时随机采样（multinomial），评估时选最大概率动作（argmax）

### 3. 训练流程
1. **交互采样**：智能体与环境交互，生成包含观测、动作、概率、价值、奖励的`SampleData`
2. **数据后处理**：填充下一状态价值，用GAE计算`advantage`和`reward_sum`
3. **模型更新**：基于采样数据执行PPO更新（策略损失、价值损失、熵正则）
4. **保存与评估**：定期保存模型，在验证地图上评估性能

### 4. 损失函数
$$total\_loss = vf\_coef × value\_loss + policy\_loss - beta × entropy\_loss$$
- `value_loss`：裁剪版价值函数损失
- `policy_loss`：PPO裁剪代理目标
- `entropy_loss`：动作熵正则化（提升探索能力）

### 5. 算法监控指标
可在腾讯开悟平台/客户端查看核心监控指标，支持在`monitor_builder.py`自定义新增指标：

| 指标名称 | 说明 |
|----------|------|
| total_loss | 总损失 |
| policy_loss | 策略损失 |
| value_loss | 价值损失 |
| entropy_loss | 熵损失 |
| reward | 累计回报 |

| 地图类型 | 数量 | 说明 |

## 七、选手开发优化指引
基线仅实现基础能力，推荐从**特征工程、奖励设计、模型结构、行为策略**四大方向优化：

### 1. 特征工程
| 优化方向 | 说明 |
|----------|------|
| 充电桩特征 | 添加充电桩位置、距离、BFS路径距离 |
| NPC特征 | 添加官方机器人位置、速度、接近方向 |
| 轨迹特征 | 记录历史移动轨迹，避免重复清扫 |
| 全局污渍图 | 粗粒度网格表示全局污渍分布 |
| 地图记忆 | 记录已探索/未清扫区域 |

### 2. 奖励设计
| 优化方向 | 说明 |
|----------|------|
| 充电桩导航 | 低电量时奖励靠近充电桩 |
| NPC躲避 | 惩罚与NPC距离过近的行为 |
| 探索奖励 | 鼓励探索新区域，减少重复清扫 |
| 效率奖励 | 奖励连续清扫，惩罚空闲 |
| 多头奖励 | 分解清扫、电量、安全多目标 |

### 3. 模型结构
| 优化方向 | 说明 |
|----------|------|
| CNN分支 | 处理局部地图，保留空间结构信息 |
| 注意力机制 | 动态关注充电桩、NPC、污渍 |
| 多头价值 | 分别估计清扫/充电/安全价值 |
| RND网络 | 增加好奇心驱动，提升探索 |
| 独立Critic | 分离策略与价值网络，减少梯度干扰 |

### 4. 行为策略
| 优化方向 | 说明 |
|----------|------|
| 充电策略 | 根据电量、距离决策充电时机 |
| 躲避策略 | 基于NPC位置/速度规划安全路径 |
| 清扫规划 | 优化路径，减少重复覆盖 |
