## 一、我如何理解你的问题

你问的并不是一个简单的“换个网络试试”问题，而是一个更深层的系统设计问题：

1. 这个赛题到底是什么类型的问题。
2. 现有 PPO 系统为什么会在 88% 左右卡住。
3. 到底是 reward、Expert、特征、算法、还是网络结构在主导瓶颈。
4. 如果允许较大范围调整，什么样的网络和训练设计才真正匹配这个任务。

我对这个问题的第一判断是：

> 当前系统的问题，不是单点超参数失调，而是“任务目标、训练信号、控制接口、状态表示”四件事没有对齐。

也就是说，你不是单纯缺一个更大的模型，而是当前系统把一个“长期生存约束下的高效覆盖规划问题”训练成了一个“基于单步即时收益的局部反应问题”。

这个判断，是后续所有方案设计的起点。

## 二、我对赛题本质的建模

### 2.1 赛题不是普通清扫，而是约束型多目标决策

表面目标是清扫更多灰尘，但真正目标不是简单最大化 clean_score，而是：

1. 在不死亡的前提下尽量多扫。
2. 在回充、避险和清扫之间做阶段切换。
3. 在地图、NPC 和资源配置变化下保持鲁棒性。

如果形式化表达，我会把它理解为：

$$
\max_\pi J_{clean}(\pi)
$$

subject to

$$
P(\text{survive to horizon}) ≥ \tau
$$

其中 $\tau$ 应接近竞赛要求下的高完成率阈值，而不是一个可被轻易牺牲的小目标。

这意味着它更像“有硬约束的多目标 POMDP”，而不是单一 reward 的普通 MDP。

### 2.2 这是一个部分可观测问题，不是完整可观测问题

当前系统的输入是：

- local view: 21×21×3
- global memory: 8×8×3
- scalar: 74D
- legal action: 8D

这份输入包含了很多有用信息，但仍然是明显不完整的：

1. 它不知道 NPC 下一步怎么动，只知道当前位置。
2. 它不知道别的机器人会不会去抢同一个充电桩。
3. 它不知道自己过去 20 步的路径结构，只知道一个很粗糙的 visit heat。
4. 它不知道当前回充计划进行到什么阶段，因为网络本身没有时序状态。

所以从问题本质上说，这不是“单帧观测足以还原状态”的任务。当前网络却是单帧前馈模型，这就是第一层错位。

### 2.3 这个任务天然有阶段结构

我认为这个任务至少有以下阶段：

1. 开图探索。
2. 高效清扫。
3. 预备回充。
4. 执行回充。
5. 近距避险。

这些阶段之间不是连续平滑过渡，而是带有阈值、上下文和机会成本的切换。

例如：

- 清扫阶段追求的是“向脏格密集区推进”。
- 回充阶段追求的是“缩短到安全充电状态的剩余代价”。
- 避险阶段追求的是“短期 collision risk 最小化”。

把这三类目标硬塞进同一个 8 动作 `logits` 中，且只用一个 value 去概括，本身就很吃力。

## 三、我对当前系统的核心判断

### 3.1 当前系统不是“完全不会工作”，而是工作在一种结构性错位上

现有系统并不是一无是处。它有几个明显已经做得不错的部分：

1. 工程优化到位，训练吞吐、AMP、compile、batch tensor 等都已较成熟。
2. Expert 在碰撞问题上已经证明能快速产生收益，v5.4 明显降低了碰撞占比。
3. entropy floor 已经证明可以阻止最明显的策略塌缩。
4. reward shaping 已经不是裸环境奖励，系统具备进一步雕刻的空间。

所以我的判断不是“推倒重来”，而是：

> 当前系统已经有一套有效骨架，但骨架上的最关键承重关系是错的。

### 3.2 最大瓶颈不是碰撞，而是“回充没有被模型内部学会”

从最新诊断看，碰撞问题在 Expert 修复后已经不是第一大矛盾；电池死亡才是当前主矛盾。

更关键的是，电池死亡的模式非常说明问题：

1. Expert 经常已经找到可行路径。
2. expert_action 也经常不是空。
3. 但 non-emergency bias 太弱，压不过模型自己的清扫偏好。

这说明不是“系统完全不知道如何回充”，而是：

- 回充知识在 Expert 里。
- 清扫偏好在模型里。
- 两者没有被统一训练成一个一致策略。

这是我后续一直强调“接口错位”的原因。

### 3.3 当前 reward 本质上在鼓励“继续扫”，不是“及时回”

我对现有 reward 的理解是：它已经加入了大量 shaping，但主体仍然是清扫导向的即时收益系统。

问题不在于有没有 charger_reward、urgency_penalty、charge_reward，而在于它们在时间尺度和总量上仍然不是主导信号。

更直接地说：

1. 清扫奖励是频繁、密集、即时的。
2. 回充收益是稀疏、延迟、跨多步兑现的。
3. GAE 又进一步把长距离收益传播削弱掉。

所以即使 reward 表面上“考虑了回充”，模型在优化时看到的仍然是“多扫一会儿更划算”。

### 3.4 当前网络结构对“计划”没有表达能力

当前 `[logits, value]` 的前馈结构足够做反应式策略，不足以可靠地做计划式策略。

它的局限不是“参数不够多”，而是：

1. 没有内部记忆，不知道自己已经朝一个目标走了多久。
2. 没有显式阶段变量，不知道当前到底是在 clean 还是在 charge。
3. 没有价值分解，不知道“眼前扫一格”和“保住 200 步后的生存”如何在 value 里同时表达。

因此我不认为当前网络只是“可以再深一点”，而是“类型不对”。

## 四、我对根因的拆解

### 4.1 第一根因：训练目标错位

当前任务真正需要优化的是“高效清扫 subject to 生存约束”，但现有训练更像是在做“单个总 reward 的局部近视优化”。

这种错位的后果是：

1. policy 被频繁的清扫梯度拉向确定性高效清扫。
2. critic 主要学习清扫价值，而不是安全边际。
3. 回充被当作一种不太划算但偶尔必要的例外行为。

### 4.2 第二根因：长周期 credit 传播不够

即使不考虑 reward 总量失衡，GAE 本身也不擅长把 50 到 200 步后的收益稳定地传回当前决策点。

这不是你代码写错，而是 PPO + GAE 的固有偏好：

- 它更擅长中短期 credit；
- 更适合 dense reward；
- 更适合策略本身能从当前观测直接决定动作的场景。

而回充时机恰恰是一个：

- 长期收益主导；
- 信号延迟；
- 需要持续上下文的决策。

### 4.3 第三根因：Expert 与 RL 的职责切分不合理

我不认为 Expert 的存在本身是错的。

我认为错的是：

1. Expert 在做高层 mode selection。
2. RL 在做低层 8 方向输出。
3. 但训练目标没有把这两个层次统一起来。

于是结果就变成：

- Expert 越强，模型越不学回充。
- 模型越不学回充，Expert 越不能撤。
- Expert 一旦边缘失效，模型也接不上。

这就是一个典型的闭环依赖。

### 4.4 第四根因：观测表示太粗，历史几乎缺位

当前 coarse global memory 是 8×8×3，这在表达“整体大势”上有用，但对路径细节不够。

尤其是：

1. 16 倍压缩会损失很多真实可达结构。
2. visit heat 过粗，不足以抑制局部 orbiting。
3. 无时间窗输入，无法表达变化趋势。

所以我认为“更高分辨率 global + 明确的时序上下文”不是锦上添花，而是当前系统下一步最自然的升级方向。

## 五、哪些问题网络能解决，哪些不能

### 5.1 网络能显著改善的问题

1. revisit 和 orbiting。
2. 回充路径执行中的上下文连续性。
3. 低电量状态下的阶段识别。
4. 对 NPC 风险趋势的短期记忆。
5. clean / survive 价值混在一起时的表示冲突。

### 5.2 网络不能单独解决的问题

1. reward 本身如果仍然严重失衡，换大网络也没用。
2. Expert 如果仍以错误方式介入，网络只会在这个接口下过拟合。
3. 训练制度如果仍然让 peak 后继续退化，强模型也一样会退化。
4. 多机器人充电桩竞争信息如果根本不在观测中，网络无法凭空学会最优分配。

所以我的总判断是：

> 先修目标函数和控制接口，再升级网络；不能反过来。

## 六、我提出这些方案时的思路

我在方案设计时，不是简单按“哪个听起来更高级”来排，而是按下面四个维度做取舍：

1. 是否直击当前主瓶颈。
2. 是否和现有框架兼容。
3. 是否能在 3 小时训练预算内看出趋势。
4. 如果失败，是否容易诊断原因。

基于这四条，我把方案分成了三层：

1. 先做低风险高回报的目标修正。
2. 再做中风险的观测与 value 结构升级。
3. 最后才做真正的重训型时序模型。

这个排序不是保守，而是为了避免“在错误目标函数上训练更强的模型”。

## 七、我的方案回答

下面是我对你问题的正式回答，不是简略版，而是带判断依据的完整方案集。

### 方案 A：先修目标函数和 Expert 接口，不动主干网络

#### 我为什么提出它

因为我认为当前最大问题仍然不是 backbone 表达力，而是：

1. 模型没有被正确地教会“为什么该去充电”。
2. Expert 的控制权太模糊，既不是纯 teacher，也不是纯 fallback。

在这种情况下，直接上大网络风险很高。

#### 方案内容

1. 保持现有 CNN + MLP 主干不变。
2. 对 reward 做势函数 shaping，把回充相关信号从稀疏终局收益变成局部每步势能差。
3. 调整 Expert：训练态只在 critical 状态硬接管，非紧急状态不再长期依赖弱 bias 牵引。
4. 在 policy loss 上对被 Expert 接管的样本做梯度隔离或显著降权。
5. 在 scalar 中增补少量时序派生特征，但尽量不破坏当前 checkpoint 兼容路径。

#### 它能解决什么

1. 让回充信号真正进入训练目标。
2. 降低“模型继续清扫压过回充引导”的概率。
3. 明确 Expert 的边界，让它更像安全网。

#### 它不能解决什么

1. 它不能根治没有时序记忆的问题。
2. 它不能把当前网络变成真正有计划能力的策略。
3. 它的上限仍然可能受限于前馈结构。

#### 我对它的评价

这是当前最应该优先做的方案，不是因为它最强，而是因为它最应该先做。

### 方案 B：增强感知和价值分解，但不进入复杂时序重构

#### 我为什么提出它

如果方案 A 之后系统仍然卡在 91% 附近，那么我会认为：

1. 目标函数已基本纠正。
2. 接下来卡住的主要原因是“看不清”和“value 表达混在一起”。

这时最合理的第二步，不是马上上 GRU，而是先把输入带宽和 critic 结构补上。

#### 方案内容

1. global memory 从 8×8 提升到 16×16。
2. local view 增加 visit_count 或轨迹热度通道。
3. scalar 增加更强的阶段上下文特征。
4. critic 拆成 clean 和 survive 两头，或至少做双价值分解。
5. 可选加入 death risk 辅助头。

#### 它能解决什么

1. 更准确地区分已扫区域与未扫区域。
2. 更容易抑制 revisit。
3. 更容易表达“当前状态的生存风险”。
4. 在 broad、少充电桩、小电池场景下更稳。

#### 它的风险

1. 输入变大后吞吐下降。
2. dual critic 如果设计不好，可能引入新不稳定。
3. 会失去 checkpoint 直接兼容性。

#### 我对它的评价

这是我认为最合理的第二阶段方案。它比 attention 更稳，比 GRU 更容易接入当前框架。

### 方案 C：GRU 时序策略，作为真正的下一代主线

#### 我为什么提出它

如果要从任务本体出发，真正击中当前系统的结构缺口，那么答案几乎一定是：

> 给模型真正的内部状态。

当前系统很多失败，本质上都是因为“它不记得”。

#### 方案内容

1. 保留现有 encoder 框架。
2. 在 fused feature 后接 GRU。
3. 训练侧引入 stored hidden state 或 sequence-aware rollout。
4. 优势估计改用 n-step 或 GAE+n-step 混合。
5. 加入 battery prediction / death prediction 辅助任务。
6. 随训练进展逐步退火 Expert influence。

#### 它能解决什么

1. 让模型记住“回充已经执行到哪一步”。
2. 让模型在 blocked、绕路、NPC 趋势下做连续决策。
3. 让 return timing 不再完全依赖硬规则。

#### 它的风险

1. `KaiwuDRL` 当前数据流对 RNN 不天然友好。
2. hidden state 管理容易出错。
3. 调试成本高，失败代价大。

#### 我对它的评价

这是我认为理论上限最高、最值得开“下一代模型线”的方案，但不是最适合马上落地的第一步。

### 方案 D：空间注意力 + 模式门控，作为高风险探索线

#### 我为什么提出它

因为当前问题还有一个明显特点：

1. 需要关注全局关键区域。
2. 需要显式处理 clean / charge / evade 模式冲突。

attention + mode gate 在结构上很贴题。

#### 方案内容

1. 用更高分辨率全局图做 token 化或 attention。
2. 用 mode gate 先输出 clean、charge、evade 概率。
3. 每个模式单独有 actor head，再做 soft mixture。

#### 它的优点

1. 结构上更接近真实任务分层。
2. 更容易显式建模阶段切换。
3. 更有机会学到“何时回充”而不是只学“往哪走”。

#### 它的缺点

1. 训练复杂度高。
2. gate 容易塌缩。
3. 若目标函数仍没修好，只会让错误结构更复杂。

#### 我对它的评价

它是一个值得保留的高风险高回报方向，但不应该比方案 B 和方案 C 更靠前。

## 八、我的推荐顺序

如果让我给出清晰排序，我的建议是：

1. 先做方案 A。
2. 若 A 有效但卡住，再做方案 B。
3. 若要开重训主线，优先方案 C。
4. 方案 D 作为探索线，不作为当前主线。

排序背后的逻辑是：

1. 先纠正目标函数。
2. 再补观测和 value 结构。
3. 最后引入时序重构。

这不是为了保守，而是为了把试错成本压到最低，同时保持每一步都可归因。

## 九、我认为最值得马上验证的实验

如果现在只能做少量实验，我会优先这样安排：

### 实验 1

仅验证：

1. 势函数 shaping。
2. Expert bias 增强。
3. Expert 接管样本降权。

目的：确认 battery death 能否明显下降。

### 实验 2

在实验 1 通过后，验证：

1. global 8→16。
2. visit_count 作为 local 通道。
3. dual critic。

目的：确认 revisit、broad profile fail rate 是否下降。

### 实验 3

只有在前两轮都证明方向正确后，再开 GRU 重训。

目的：验证“真正的内部记忆”是否能把 return timing 拉到新的水平。

## 十、我对你原问题的直接回答

如果回到你最初的问题，也就是“请你重新评估和设计网络架构”，那么我的最终回答是：

1. **这个赛题的本质不是单纯清扫，而是有硬生存约束的阶段化资源调度与覆盖规划问题。**
2. **当前最大结构性限制不是卷积不够深，而是前馈单头 PPO 在错误目标函数下被迫学习长期回充决策。**
3. **Expert 与 RL 的主要冲突，不是因为 Expert 存在，而是因为它替模型做了高层模式切换，却没有与训练目标统一。**
4. **短期最优解不是立刻换大模型，而是先把回充变成模型可被正确训练的目标。**
5. **中期最有价值的网络升级是时序记忆和价值分解，而不是盲目加深前馈层。**

换句话说：

> 如果你现在直接把当前 `model.py` 换成更深的 CNN 或更大的 MLP，大概率只能更快地学会错误目标，而不会自然学会“及时回充”。

真正有效的改动，必须同时考虑：

1. 目标函数。
2. credit 传播。
3. Expert 协同方式。
4. 状态表示。

这四件事不能只改其中一件。

## 十一、我的最终建议

如果让我用一句最工程化的话给建议，我会这样总结：
