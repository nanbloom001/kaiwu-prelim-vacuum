你好，我正在做一个机器人吸尘器（清扫大作战）的强化学习竞赛项目，使用 PPO 算法训练智能体。现在训练遇到了瓶颈，我有一个优化方案想请你评估和讨论。

## 项目背景

智能体在一个 128×128 的网格地图上清扫脏格子，需要管理电量（返回充电站充电）、规避 NPC（其他吸尘器，碰撞即死）、在有限步数内尽可能多清扫。每局参数随机：NPC 数量 1-4、充电站数量 1-4、电量上限 120-720、最大步数 500-2000。

**技术栈**：PPO + 21×21 局部视野 + 8×8 全局记忆 + 74 维标量特征，8 方向移动。训练使用腾讯 KaiwuDRL 框架，Docker 本地训练（1 learner + 1 aisrv + 4 gamecore）。

## 当前状态

我已经迭代了 v4 → v5 → v5.1 → v5.2 四个版本。v5.2 从 v51-step4900 checkpoint resume，训练到 step 64000。

**关键指标**（最佳 checkpoint v52-step8500，位于训练峰值区）：
- 平均清扫分 AvgCS = 1320
- 最低清扫分 MinCS = 871（方差大，个别局灾难性低分）
- 每步清扫效率 CPS = 0.895
- 存活率 Survival = 0.818

**问题**：MinCS 远低于 AvgCS（871 vs 1320），分数方差大。训练在 step 8k-12k 达峰后持续下降 50k+ 步无回升。

## 我识别的根因

**核心问题：奖励信用归因失败**

我的奖励函数有 15+ 个分量，其中清扫奖励 +1.5/格是主导项（累积约 +1500/episode），而死亡惩罚（碰撞 -8.0、电池 -3.0）只在 episode 结束时一次性施加。

问题在于 GAE (γ=0.99, λ=0.95) 的衰减：50 步后信号衰减到 4.7%，100 步后 0.2%。导致死亡的关键决策（比如没及时充电、走向 NPC）通常发生在死亡前 100+ 步，此时 GAE 传播过来的死亡信号几乎为零（约 -0.02），完全无法与当步的清扫奖励 +1.5 竞争。

所以模型学会了"平均清扫好"但没学会"避免灾难"——在高难度配置（低电量、多 NPC）下暴露为灾难性低分。

**次要问题**：
1. 诊断指标缺失——只有聚合均值，无法定位哪些 episode 配置导致死亡、各奖励分量贡献如何
2. 训练采样均匀——高难度配置曝光不足

## 我的优化方案（v5.3）

分三个 Phase：

**Phase 1：诊断增强（零训练影响）**
- 让奖励函数返回各分量字典，上报监控面板
- 记录死亡 episode 的最后 20 步轨迹（电量、充电站距离、NPC 距离、动作）
- 按 (NPC数, 充电站数, 电量档, 步数档) 追踪每 config 死亡率

**Phase 2：信用归因修复**
- outcome_bonus 按剩余步数比例缩放：早死 = 更大惩罚（乘以 1 + 2×剩余比例）。比如 step 100/2000 死亡，bonus 从 -3.0 变成 -8.7，GAE 50 步后仍有 -0.41 的有效信号，可与 +1.5 竞争
- 强化每步电池危险信号：从 max -0.4/步 提升到 -1.3/步，接近清扫奖励量级
- NPC 距离 < 3 时额外持续惩罚 -0.6/步

**Phase 3：Config 感知训练**
- 追踪每 config 死亡率后，在 eval_hard 阶段 50% 超采样高死亡 config
