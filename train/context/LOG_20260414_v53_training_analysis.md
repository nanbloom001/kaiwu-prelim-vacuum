**典型轨迹（ep 204，broad map 10，4机器人）**：
```
s35:bat=686/720 slack=640 npc=59 mode=0 act=0    ← 电量极高，正常清扫

```
注意：ep 204 电量 667/720（93%），完全不需要充电！但 Expert 仍然进入了 return_mode。

**根因分析**：

1. **A* 寻路 NPC 避让不足**：A* cost map 中 NPC danger zone 用指数衰减（`_NPC_DANGER_MAX=15, _NPC_DANGER_DECAY=2.0`），在距离 2-3 处的代价仅约 3-7，不足以让路径绕行。当 NPC 离充电路径很近时，绕行代价高于直接穿过，A* 选择穿过 → 碰撞。

2. **3 级 fallback 加剧问题**：`_plan_to_charger_cached()` 在第 1 级（npc_weight=1.0）找不到路时会降级到 npc_weight=0.3，最终降到 0.0（完全忽略 NPC）。这意味着当充电路径受阻时，Expert 会选择无视 NPC 的路径。

3. **`filter_actions()` 防线被绕过**：`filter_actions()` 只阻止"直接朝 NPC 方向移动"（距离 ≤ 5 时），但不阻止"朝 NPC 附近移动"。当 npc_dist=2 且动作是对角线移动（如 act=2 → (0,-1)），如果 NPC 不在目标格正中心，filter 不会拦截。

4. **电量充足时也触发 return_mode**：ep 204 电量 93% 却进入 mode=2，说明 return_mode 的进入条件（`prep.battery <= charger_dist + margin`）在 broad 大地图配置下被误触发（charger_dist 可能很大，margin 也很高）。

```

Expert 从未触发 return_mode，机器人一直在清扫直到电量耗尽
```

**典型轨迹（ep 136，broad map 4，1充电桩 2机器人）**：
```
battery_max=200, 1个充电桩, 2个机器人
slack=-73（严重不足），但从没进入充电模式
```

**根因分析**：

1. **充电触发条件覆盖不足**：Expert 使用 3 个条件触发 return_mode：
   - `self.return_mode`（已经激活）→ 循环依赖，首次触发没用
   - `prep.battery <= charger_dist + margin` → 距离计算依赖 A*，可能因为未探索区域导致 dist=inf
   - `battery_ratio <= LOW_BATTERY_RATIO (0.32)` → 这是兜底条件

   但数据表明这些条件没触发。最可能的原因：**A* 路径到充电桩距离为 inf**（未探索区域太多），导致条件 `charger_dist < float('inf')` 为 False，而 battery_ratio 虽然很低但可能刚好没到 0.32。

2. **多机器人场景充电桩争抢**：broad 配置中 charger_count=1 或 2，robot_count=3 或 4。Expert 不感知其他机器人，多个机器人同时冲向同一充电桩，部分机器人因为被占而无法充电。

3. **模型未学会自主充电**：由于训练中 Expert 有 logit_bias 引导充电行为，模型自身没有独立学习充电决策。当 Expert 的触发条件没满足时，模型完全没有充电意识——它只会继续清扫。

## 七、Expert 代码问题定位

### 7.1 碰撞问题：A* fallback 链过度降级

**文件**: `expert.py` L341-367 (`_plan_to_charger_cached`)

```python
# 当前逻辑：3级 fallback
cost_map = self._build_cost_map(prep, npc_weight=1.0)   # 第1级
cost_map = self._build_cost_map(prep, npc_weight=0.3)   # 第2级：降低NPC避让
cost_map = self._build_cost_map(prep, npc_weight=0.0)   # 第3级：完全忽略NPC
```

问题：第 3 级完全放弃 NPC 避让，A* 会规划穿过 NPC 的路径。`filter_actions()` 只在距离 ≤ 5 时阻止"正对 NPC 方向"，对角线或侧向移动不会被拦截。

### 7.2 电池问题：return_mode 触发条件不够鲁棒

**文件**: `expert.py` L173-177 (`_evaluate_return`)

```python
should_return = (
    self.return_mode
    or (charger_dist < float('inf') and prep.battery <= charger_dist + margin)
    or battery_ratio <= self.LOW_BATTERY_RATIO
)
```

问题 1：当 A* 找不到路径时 `charger_dist = inf`，中间条件永远为 False，只靠 `LOW_BATTERY_RATIO=0.32` 兜底。但 `battery/battery_max` 可能因为浮点问题刚好没触发。

问题 2：`LOW_BATTERY_RATIO=0.32` 对于 broad 配置（battery_max=120-200）太晚。当电池只剩 32% × 120 = 38 步时，可能来不及到达充电桩。

### 7.3 filter_actions 逻辑漏洞

**文件**: `expert.py` L86-113 (`filter_actions`)

```python
# 只阻止"直接朝 NPC 方向"的动作
if dx == sx and dz == sz:
    legal[idx] = 0
```

问题：只拦截方向完全一致的动作。如果 NPC 在东北方 (1,1)，但机器人走北 (0,1) 或东 (1,0)，不会被拦截。这在距离 2-3 时尤其危险——对角线移动可能直接走到 NPC 旁边的格子。

### 7.4 充电模式被误触发

**文件**: `expert.py` L173

```python
or (charger_dist < float('inf') and prep.battery <= charger_dist + margin)
```

当 `charger_dist` 很大（broad 大地图）且 `margin` 也因路径复杂度高而膨胀（最高 40）时，即使电量 93%（如 ep 204 的 667/720），只要 `charger_dist + margin > 667` 就会触发 return_mode。

## 九、总结与下一步建议

### v5.3 改动效果

| 改动 | 效果 | 判定 |
|------|------|------|
| ENTROPY_FLOOR_COEF 0.2→1.0 | entropy 0.12-0.21 稳定，无塌缩 | **成功** |
| urgency 三段式 | 局部信号增强，但死亡主要由 Expert bug 导致 | **方向对但非主因** |
| outcome_bonus 缩放 | 死亡惩罚更合理 | **正向** |
| DEATH_TRAJ 日志 | 精准定位碰撞/电池模式 | **高价值诊断** |
| CONFIG_RISK 日志 | 发现高风险配置 | **有参考价值** |

### 核心问题：Expert 充电逻辑需要修复

训练本身是健康的（entropy 稳定、无退化），**失败主要来自 Expert 代码 bug**：

1. **碰撞（56%失败）**：充电路径 NPC 避让不足 + fallback 过度降级 + filter_actions 漏洞
2. **电池（44%失败）**：return_mode 触发条件不鲁棒 + 多机器人争抢 + 模型未学会自主充电

### 建议优先级

1. **修复 filter_actions**：在距离 2-3 内全面拦截所有朝 NPC 方向的动作（不仅是完全一致的），包括对角线方向
2. **修复 A* fallback**：移除 npc_weight=0.0 的 fallback，最低保留 npc_weight=0.3
3. **修复 return_mode 触发**：增加基于 battery_ratio 的多级触发（如 0.40 时 mild 提示，0.35 时强制 return），不依赖 A* 距离
4. **修复误触发**：添加条件 `battery_ratio > 0.70` 时不进入 return_mode（电量充足不充电）
